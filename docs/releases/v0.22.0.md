# ETL-SQL v0.22.0

**Released:** 2026-11-04

## Release summary

This release improves release recovery, installed-package checks and the security boundaries
around scripts, reports and connections. Successful work on an unchanged candidate can be retained
across failed-job recovery. Publication verifies the original accepted package bytes and required
evidence before making the release public.

## Breaking changes and required actions

Read [the complete breaking-change ledger](../../BREAKING_CHANGES.md) and
[migration guide](../guides/onboarding/migration-guide.md) before upgrading.

- Back up configuration, databases and keys before changing an installation. Earlier database,
  report, draft and unauthenticated encryption formats are no longer accepted. Follow the migration
  instructions for affected state; do not assume an unsupported store will be upgraded automatically.
- Update scripts using removed syntax and retired commands. The migration guide and focused
  references describe their replacements.
- Review connection security settings. Boolean encryption options, TLS requirements, credential
  paths and allowed environment-variable references are enforced consistently.
- Scripts cannot access the application's own configuration, secrets, databases, keys or binaries,
  including through an approved safe zone.

## Deprecations

Removed forms and migration actions are recorded in the breaking-change ledger. No additional
removal timeline is announced in this release.

## Highlights

- **Release recovery:** regular CI selects affected lanes, full certification selects all required
  lanes, and failed-job recovery preserves successful executions and artifacts on unchanged inputs.
  Native packages are promoted from retained certification instead of rebuilt after tagging.
- **Release evidence:** independent workstation state and operator reports are candidate-bound.
  Required reviews, applicability decisions, original artifact identities and actual draft hashes
  are checked before publication. A green PR alone cannot authorize a release.
- **Installed packages:** native acceptance covers extracted CLI launches, packaged browser assets,
  VSIX webviews and Intel DMG mount/launch/detach. MSI and DEB installation evidence remains separate
  from archive identity checks.
- **Browser reliability:** Windows test browsers preserve Playwright's defaults while applying its
  upstream TCP port-allocation mitigation. Failure diagnostics retain bounded, sanitized transport
  and process information without retrying assertions or extending their waits.
- **Security and correctness:** report SVG/URL sanitization, identity-sensitive snapshots, protected
  application paths, Gateway reply ownership, connector authentication and encryption handling have
  focused fixes. See [the changelog](../../CHANGELOG.md) for the full list of changes.

## Improvements

- **Release operations:** source checks collect independent findings before restore/build. Explicit
  deadlines and streamed logs bound long jobs; direct MSI checkpoints preserve progress separately
  from the runner's final log upload. A diagnostic dispatch reuses an earlier installer pair.
- **Packaging:** staging excludes runtime state and protects program permissions. Package validation
  checks source identity, retained inventories and hashes before promotion.
- **Browser tests:** failed navigation and missing-element waits retain bounded, sanitized transport
  and process diagnostics. Assertions keep their original failure behavior.

## Performance

The [release recovery record](recovery-acceptance.md) records a scoped PR at 19m21s and broad
proposal CI at 26m31s. That broad proposal's native packages finish last at 49m18s; its complete
PR validation does not meet the 30-minute target. These measure development validation, not a
frozen release or runtime throughput.
The last certification round before tagging went from push to all hosted checks green in 1h21m
on its first attempt; native packages were the slowest run at 80 minutes. The complete release
timeline, including tagging and publication, is recorded in the recovery record. This release
makes no new runtime-performance claim.

## Security

This release restricts access to application-owned files, validates credential and encryption
options, sanitizes report content and preserves protected installer configuration. See
[the breaking-change ledger](../../BREAKING_CHANGES.md),
[security policy](../../SECURITY.md) and [changelog](../../CHANGELOG.md) for the
affected boundaries and migration requirements.

## Bug fixes

- Declared MOCKDB schema reads avoid generating the full data fixture; failed seeding blocks reads
  instead of returning partial rows.
- Typed JSON spill rows preserve scalar values, including numeric-looking text. Recreate saved
  sessions containing the older untyped format before use.
- MSI and DEB configuration failures stop installation; successful upgrades preserve operator-added
  protected settings and service keys.
- Native packaging rejects protected runtime files and preserves accepted output after a failed
  replacement build.

## Known issues and certification limits

- **JSON `COMPRESS=ON` writes a ZIP named `<path>.zip`.** `AS JSON('data.json.gz', COMPRESS=ON)`
  produces `data.json.gz.zip`, a ZIP archive, not gzip. `DELETE FILE` on the named path misses it.
  Delete both names until this is fixed.
- **A JSON write through `ROOT_PATH` cannot be read back.** The rows are written as a top-level
  array instead of at the root path, so `SELECT` through the same connection returns no rows.
  Write without `ROOT_PATH` for data you need to read back.
- **Spill GC pauses are above the stored smoke baseline.** Three spill metrics exceed their band
  (temp-table and spill-cleanup GC pause, spill-cleanup elapsed time) with no engine change and
  matching allocations and checksums. The cause is not yet known; it is accepted for this release.
- **Certification limits.** Shared SaaS runtime containment, live HA and capacity, hosted
  production regions and a billion-row claim are not certified by this release. The
  [deployment-profile claims](release-checklist.md) state the scope of each certified profile.

## Upgrade guide

1. Review the breaking-change ledger and migration guide linked above against the installation's
   scripts, saved state and connection settings.
2. Back up configuration, databases and keys using the installed administration tools. Keep the
   backup outside package output and release evidence.
3. Validate the release in a disposable installation, including applicable state migrations and
   install/upgrade/rollback checks. The intended predecessor for this release is v0.21.0.
4. After those checks pass, follow the
   [installation guide](../administration/platform/installation.md) for the platform. Verify service
   health, authentication and a representative script/report before returning it to use.

## Install

Downloads, `sha256sums.txt` and `sbom.json` are attached to the GitHub release. Verify each file
against `sha256sums.txt` before installing.

| macOS Apple Silicon | osx-arm64 portable ZIP |
| macOS Intel | DMG or osx-x64 portable ZIP |
