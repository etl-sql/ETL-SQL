# ETL-SQL v0.19.0

**Released:** 2026-09-06

v0.19.0 completes ETL-SQL's own charting engine — every graphical visual now renders through the native Grammar-of-Graphics path with no external chart runtime — and introduces **ETL-SQL Studio** as an Alpha visual and script workbench alongside the existing authoring tools.

---

## Release Summary

This release finishes two long arcs and opens one.

**Charting is finished and owned.** The native Grammar-of-Graphics surface is complete, the last chart property gaps against Power BI, Tableau, and ggplot2 are closed, and no graphical visual requires ECharts, ClearScript, or any other external runtime. A directory-discovered golden lane pins the resolved plan, the rendered SVG, the semantic fallback, and the terminal render for every catalog visual, and a payload budget gates what a report page actually downloads.

**Reports carry their own presentation contract.** `SET REPORT TIME_ZONE`, `LOCALE`, and `NULL_LABEL` resolve server-side with deterministic precedence, so the browser, PDF, email, and terminal renderings of one report agree; design tokens and `CREATE STYLE PALETTE` give a report a stable, inheritable colour system; and constrained `HTML` visuals extend authoring without giving up the semantic fallback that non-graphical surfaces depend on.

**ETL-SQL Studio arrives as an Alpha.** Studio is a unified dual-projection workbench across the SaaS Portal and a new desktop host. It is available, usable, and worth trying — and it **does not replace** Report Builder or Workstation Editor. Nothing is deprecated and no entry point is retired. What holds Studio at Alpha is evidence rather than missing features; see [Known Issues](#known-issues).

## ⚠️ Breaking Changes & Required Actions

**Data-quality rules are first-class syntax, not comment tags**

A rule decides which rows leave a statement, so it must not be something a formatter or comment stripper can silently remove.

```sql
-- Before (v0.18.0 and earlier)
SELECT
    email  /* @expect: 'MATCHES ''^[^@]+@[^@]+$'''; @fail: 'WARN'; */
FROM #users;

-- After (v0.19.0)
SELECT
    email EXPECT MATCHES '^[^@]+@[^@]+$' ON FAILURE WARN
FROM #users;
```

- Repeat `EXPECT` as needed; combine rules with `AND`/`OR` (a comma separates columns in a select list).
- `ON FAILURE` takes `THROW`, `WARN`, or `QUARANTINE`.
- A `MATCHES` pattern is now an ordinary quoted string literal, so the outer quoting and doubled quotes the tag layer forced are gone.
- Comments keep carrying the tags that *describe* data: `@d`, `@owner`, `@pii`.
- Writing a rule as a tag is a lint error naming the clause to use instead.

**`ASSERT JOB` uses stacked `ON FAILURE` actions**

Severity is an action, not a clause name, and not an option hidden in a `WITH()` bag that could fail a run without the severity clause saying so.

```sql
-- Before
ASSERT JOB NULL_PERCENT(clean_users.Email) < 5 ON CRITICAL_FAILURE THROW;
ASSERT JOB ROW_COUNT(clean_users) > 0 WITH (FAIL_ON_WARN = TRUE);

-- After
ASSERT JOB NULL_PERCENT(clean_users.Email) < 5 ON FAILURE THROW;
ASSERT JOB WARN_PERCENT(clean_users) = 0 ON FAILURE THROW;
```

- `WARN` is the default on both surfaces; `NOTIFY <notification>` alone is non-fatal.
- "Any warned row fails the run" is now the explicit predicate `WARN_PERCENT = 0` with `ON FAILURE THROW`.

**Data-quality catalog column rename**

`eng.data_quality_rules.rule_tag` is now `rule_clause`, and its values are `EXPECT` / `EXPECT #2` rather than `@expect` / `@expect_1`. Update any query, dashboard, or export that reads this column or the `SHOW DATA QUALITY RULES` output. The Portal's data-quality views are updated in place.

**Browser manifest delivery is projected**

Every graphical visual was serializing five representations of one chart while the runtime read two. Normal browser delivery no longer includes `chartSpec`, `chartData`, `plotPlan`, `microCharts[].plotPlan`, or the legacy `interactions` map.

- **Migration:** read `visual.interaction` for interaction semantics and `visual.nativeSvg` for the rendered chart.
- A consumer that genuinely needs the full semantic contracts must go through the explicitly authorized diagnostic projection; the browser options cannot produce them.
- A tested compatibility shim keeps manifests built before v0.19.0 — offline snapshots, cached artifacts — rendering and cross-filtering.
- Across six representative fixtures the combined manifest fell from 170.1 KB to 65.9 KB raw (15.1 KB gzip).

**Unrecognised `SET REPORT` keys are rejected**

`SET REPORT TIMEZONE = 'UTC'` previously parsed through the arbitrary-identifier path and was silently discarded by the handler, producing a report that looked configured and was not. An unknown key is now a syntax error naming the supported keys. Check existing scripts for misspelled keys — the correct spelling is `TIME_ZONE`.

## ⏳ Deprecations

- None in this release. In particular, **Report Builder and Workstation Editor are not deprecated.** ETL-SQL Studio ships as an Alpha alongside them; legacy retirement is deliberately not scheduled until Studio has certified evidence behind it.

## Highlights

### Charting is complete and runtime-free

Every graphical catalog visual now renders through ETL-SQL's own native `PlotPlan` path or an approved focused native SVG module. No graphical visual requires ECharts, ClearScript, or another external chart runtime.

The native Grammar-of-Graphics surface is finished: typed field / `DATUM` / `VALUE` bindings, inherited encodings, explicit stack/offset/interval placement, deterministic jitter and nudge, continuous colour ranges, wrapped facets, fixed Cartesian aspect, and category-local `TICK` marks — carried consistently across parser, formatter, lint, LSP, lineage, Report Builder, serialization, native SVG, terminal, accessibility, and export.

Alongside it, the last property gaps against Power BI, Tableau, and ggplot2 are closed on the named charts:

```sql
CREATE VISUAL RevenueTrend AS LINE (
    SOURCE = #monthly,
    MAPPINGS (X = Month, Y = Revenue),
    OPTIONS (
        INTERPOLATION   = STEP_AFTER,
        LINE_WIDTH      = 2.5,
        LINE_DASH       = DASHED,
        SYMBOL_SHAPE    = DIAMOND,
        SYMBOL_SIZE     = 8,
        PLOT_BACKGROUND = '#fafafa',
        AXIS_FONT_SIZE  = 11,
        SERIES_LABELS   = ON WITH (POSITION = END),
        Y_AXIS (MIN = 0, MAX = 500000, INCLUDE_ZERO = ON, MINOR_TICKS = ON)
    ),
    OVERLAYS (
        REFERENCE_BAND (LOW = 250000, HIGH = 400000, LABEL = 'Target range'),
        RUNNING_TOTAL(CumulativeRevenue) AS DASHED WITH (COLOR = '#64748b')
    )
);
```

Axis titles, bounds, tick control and label rotation; gridline, spine and plot-area styling; 100% stacking; error bars; forecast and anomaly encodings; reference lines and bands; running-total and percent-of-total overlays; data labels with backgrounds, borders and leader lines; marker shape, stroke and size; and full legend control are all available on the named surface rather than only in `CUSTOM CHART`.

### ETL-SQL Studio (Alpha)

Studio is a full-viewport workbench that keeps one document in two projections — a visual canvas and the script — with neither one owning the truth. It reads and writes ordinary `.rptsql` and `.etlsql`; there is no project file and no proprietary UI schema, and surgical AST patching leaves SQL, CTEs, comments, and whitespace it did not target byte-for-byte alone.

```bash
# Desktop host: opens a per-project workbench on local loopback
etlsql studio ./analytics

etlsql studio list          # running instances
etlsql studio open ./sales --new-window
etlsql studio stop ./analytics
```

The SaaS Portal serves the same workbench at `/studio`, bound to the zero-trust connection catalog, Gateway routing, and OIDC identity, with renewable collaborative edit leases.

Studio splits report authoring into **Dashboard** and **Paginated Report** workflows that share the parser, patcher, data, expression, formatting, preview, and code surfaces. Around them it carries a document outline, a data-model view, an engine panel with positional scope and `EXPLAIN`, a formatting inspector, a type-aware filter pane, cross-visual filter and cascade authoring, a Git diff viewer, a workspace Explorer, and PDF export with a pagination preview read from the engine's own compilation.

**Start with sample data** opens a working dashboard on the built-in MOCKDB connector, needing no database at all — the zero-dependency on-ramp for a first session.

### The pipeline canvas is a real execution map

`.etlsql` canvases are projected from the shared engine DAG rather than generated by regex, so they show real sequential and branching edges — `IF`, `PARALLEL`, loops, `TRY`/`CATCH`, and validation stages.

Control-flow containers are palette kinds that hold other tasks: drop a task into a `PARALLEL`, `FOREACH`, or transaction scope and its statement is *relocated* rather than regenerated. Precedence edges hand over on success, failure, completion, or an author-written expression, lowered into the script as a `BEGIN TRY`/`BEGIN CATCH` guard and an `IF` — so the pipeline runs what the canvas draws.

**Run to Selected Node** executes the pipeline through a chosen task, covering that selection's dependency closure rather than everything above it. Before anything runs, a confirmation names every write that would outlive it — the connection-qualified table, the address, the path — grouped by the task performing it. `#temp` staging is not listed, so the confirmation appears only when something real is at stake.

### Reports carry their own time zone, locale, and null label

```sql
SET REPORT TIME_ZONE  = 'America/Chicago';
SET REPORT LOCALE     = 'en-US';
SET REPORT NULL_LABEL = 'n/a';
```

Precedence is deterministic and resolved server-side: `SET REPORT TIME_ZONE` then `Scheduler:DefaultTimeZone` then UTC; `SET REPORT LOCALE` then `Reporting:DefaultLocale` then the invariant culture; a visual's `OPTIONS (NULL_LABEL = '…')` then `SET REPORT NULL_LABEL` then `Reporting:DefaultNullLabel` then `-`.

Nothing is inferred from the viewer's browser, so the browser, PDF, email, and terminal renderings of one report agree. A temporal string carrying no offset is anchored to UTC rather than picking up the server's local offset, so the same report no longer renders different instants on two hosts.

### Offline report packages

```bash
etl-sql-report offline sales_dashboard.rptsql
```

Turns an existing `.etlsnap` package into a single self-contained HTML file that opens with no server and no network. The exporter inlines the runtime, its stylesheet, and the manifest, and declares a `default-src 'none'` Content-Security-Policy so the file cannot quietly depend on being online. It reads the package rather than re-evaluating the script, so the page shows the figures the package captured.

## Improvements

### Language & Engine

- `||` string concatenation works across the full expression grammar: explicit aliases, parentheses, larger expressions, SQL-style `NULL` propagation, and compilation to the target dialect's operator.
- Connectors that expose a catalog (SQL Server, PostgreSQL, MySQL) surface primary and foreign keys through `IMetadataManager`, so both Studio hosts answer schema questions the same way.
- `EXPLAIN` is allowed in a Portal interactive run because it plans without executing; `EXPLAIN ANALYZE` is refused by name because it does execute.
- Parser and lint diagnostics carry plain-language guidance where ETL-SQL can act on them: a sentence with no parser vocabulary, a next step, the card or page the line sits in, a reference link, and — only where exactly one repair is correct — a button that makes the edit. The guidance rides on the diagnostic, so it reaches VS Code through the language server and the CLI's lint output, not only Studio.
- `docs/grammar.ebnf` recognizes all 1,092 working documentation examples the parser accepts, including this release's new syntax.

### Reporting & Visualization

- Constrained `HTML` visuals with escaped typed bindings, scoped CSS, declarative actions, bounded `VISUAL(...)` embeds, and `SPARKLINE(...)` / `PROGRESS_BAR(...)` helpers, under explicit row, node, byte, query, and render budgets — with a deterministic semantic fallback for PDF, Markdown, terminal, email, plain text, snapshots, and screen readers.
- Report design tokens and `CREATE STYLE PALETTE = (...)` sequences resolving into scoped `--etl-*` variables with deterministic inheritance, stable series-colour assignment, explicit-colour precedence, and contrast validation.
- Chart toolbox and linked zoom: `SHOW_EXPORT = ON` (what saves is what is on screen, zoom included), `SHOW_DATA_VIEW = ON`, and `ZOOM_GROUP = 'name'` to link the range sliders of several charts.
- Dense-series rendering: `SAMPLING = NONE|LTTB|AVERAGE|MAX|MIN` and `PROGRESSIVE = ON` with `PROGRESSIVE_CHUNK = n`. Sampling never invents a point — each bucket contributes a real row that keeps its own row index, tooltip, and selection identity — and the resolved plan still carries every row, so the plan hash continues to describe the data.
- `TOOLTIP (FIELDS = (Col FORMAT 'C0', …))` renders a formatted field list from the hovered row with no server round-trip and no `CREATE CONTAINER`.
- `EMIT_FILTER (TARGETS = (Visual, …))` says which visuals a selection made *here* may reach, complementing the receive-side `INTERACTIONS` clause.
- Focused layout modules (`TREEMAP`, `SUNBURST`, `SANKEY`, `NETWORK`, `MAP`, `MATRIX`) consume shared theme tokens, series colours, accessible names, and resolved interaction metadata, so a `TREEMAP` and a `BAR` of the same categories on one page can no longer disagree on colour.
- Nine `TRANSFORM` recipe snippets and matching Report Builder data-preparation helpers for rolling aggregates, period comparisons, share of total, top-N grouping, date filling, pivots, interpolation, normalization, and deduplication.

### Portal, Gateway & Security Operations

- Approved Gateway resource discovery and binding in the Connection Wizard, `Admin → Connections`, and `Admin → Data Gateways`, replacing manual Gateway and Resource ID entry. Server-side validation re-verifies tenant ownership, active session, resource approval, allowed operations, and persisted use grants on save and execution.
- Durable ambiguous Gateway write triage in Portal Operations: one high-priority case per tenant and operation with acknowledgement, assignment, evidence, notes, four externally verified resolutions, and append-only history. Script and scheduler execution carry a non-retryable outcome so configured retries cannot duplicate the write.
- Short-lived, audience-bound workload identity exchange for GitHub, GitLab, Azure DevOps, and `private_key_jwt` schedulers, with durable replay rejection, non-self one-use approvals, and owner-capped service tokens.
- Tenant-portability v2 bundles bind a cross-system consistency point with reconciled stable-ID/hash/owner/ACL inventory, certified delta sequencing, and resumable content-addressed chunks; offline self-contained validators for Windows, Linux, and macOS can verify customer-encrypted content after source access is gone.

### Build, Test & Release Engineering

- A directory-discovered reporting golden lane covering both visual catalogs. Adding a chart means adding a `.rptsql` fixture and blessing it rather than editing C#, and each fixture reports as its own test result. Every fixture pins the serialized `PlotPlan`, the native SVG, the semantic fallback, and the terminal render — plan and SVG compared independently, so a moved plan hash is a semantic regression and a moved SVG hash with the plan holding is a rendering change.
- A browser payload regression budget gating raw and gzip bytes for `report-runtime.js`, `report-runtime.css`, the shared runtime total, and end-to-end page weight, re-blessed only through `Test-ReportPayloadBudget.ps1 -UpdateBudget` so new numbers land in the diff for review.
- A browser type gate: root `tsconfig.json` with `checkJs`, `.d.ts` contracts generated by reflection over the C# DTOs and enums, and a ratchet standing at zero findings, wired into pre-push and CI. The pass that established it found twelve live defects.
- A reproducible Studio performance-budget gate for workbench startup, post-GC browser heap, CodeMirror keystroke latency, 250-row visual aggregation, and canvas redraw, with checked-in Windows, Linux, and macOS ceilings running in a dedicated CI matrix.
- Pre-release gate hang protection: a per-phase watchdog kills a stalled phase on a stall or hard cap and reports why, phase logs stream live rather than buffering until completion, and a preflight clears leftover browsers and test hosts and proves the Docker daemon answers before the Docker lane runs.

## Performance

- **Browser manifest payload: 170.1 KB → 65.9 KB raw (15.1 KB gzip)** across six representative fixtures, by projecting browser delivery instead of shipping five representations of every chart.
- **Native catalog bundle: 2,977,679 B → 1,188,724 B** once the payload measurement was corrected to exclude the Studio authoring subtree a report viewer never loads.
- Dense-series `SAMPLING` and `PROGRESSIVE` reveal reduce what a chart draws at render time without changing the resolved plan.
- Measured page-weight composition is now published rather than asserted: of the 979,829 B raw / 226,725 B gzip a report page downloads, Tabulator and Arrow plus their CSS account for 637,889 B / 151,362 B — 65% of raw and 67% of gzip. The chart runtime is 34% and 32%. A footprint claim that does not name the vendor bundles is wrong by roughly a factor of two.

**Engine performance is unchanged from v0.18.0.** Scale certification passes 13/13 scenarios on both
tiers. Two standard-tier scenarios fail the checked-in baseline and fail it identically on v0.18.0 —
a controlled A/B comparison (one worktree, interleaved arms, warmed) puts the two builds 4.7% apart
inside a 13% within-arm spread, which is not a result. The full evidence, the hypotheses tested, and
why the baselines were deliberately not re-blessed are in
[v0.19.0 Performance Results](v0.19.0-performance-results.md).

## Security

- Studio secret handling uses the same PBKDF2 + AES-GCM `ENC:` envelope as the Connection Wizard and engine. Plaintext values never reach modal markup or DOM content, and Base64 is never presented as encryption. Production browser journeys prove hidden plaintext and engine-compatible decryption.
- `OPEN_URL(TEMPLATE = …, PARAMS = (…))` interpolates only the columns the author declared and URL-encodes every value, so a row value cannot introduce a path segment, query parameter, or scheme of its own. An undeclared or missing placeholder resolves to empty rather than being left in the URL; `PARAMS` without `TEMPLATE` is rejected.
- Offline report packages declare a `default-src 'none'` Content-Security-Policy.
- Verified Viewer Context is certified for SQL Server Gateway resources: the configured service login is preserved, signed viewer values are installed through parameterized `SESSION_CONTEXT`, claim-driven role selection is prohibited, and pooled sessions are cleared or evicted after success, provider failure, cancellation, timeout, and broken connections.
- Constrained `HTML` visuals are covered by focused and real-browser tests for hostile markup, URLs, SVG, CSS, disclosure, cycles, JavaScript, refresh consistency, and aggregate limits.

## Bug Fixes

- **`CUSTOM` charts cross-filter on the column they are keyed on.** A layered chart has no `MAPPINGS` clause, so the browser's lookup always missed and fell through to the source query's first column. The selection key is now resolved server-side from the chart's encodings, and a key naming no column raises no filter rather than a confidently wrong one.
- **Non-stacked `CUSTOM` `RECT` layers honour `Y_START`/`Y_END` and `X_START`/`X_END`.** Both rect paths read interval endpoints only under `STACK` and otherwise forced the start to zero, so a ranged bar, a qualitative band, or an explicit-bin histogram rendered from the baseline with the author's start silently discarded.
- **`CUSTOM` charts receive resolved theme and style tokens.** A `CREATE STYLE` theme reached `BAR` and stopped at `CUSTOM` — the sharp edge for exactly the authors following the themed-dashboard recipe.
- **`CUSTOM` chart errors point at the mistake.** The lint rule stamped every diagnostic on the `CREATE VISUAL` header, so on a multi-layer chart all ~20 possible errors squiggled the first line. Every chart node now carries a source span, every duplicate is reported in one pass, and semantic checks live in one validator both the lint rule and the report lowerer run.
- **Named visuals reject unsupported `MAPPINGS` roles** with a valid-role diagnostic instead of silently lowering a wrong chart.
- **`PAGE` options and `MOBILE_LAYOUT` reach the rendered page.** `BACKGROUND_IMAGE`, `BACKGROUND_SIZE`, `MAX_WIDTH`, `ALIGN_CONTENT`, `OVERFLOW`, and the whole mobile layout block parsed into the manifest and were then dropped — the page renderer read only `structure` and `slotMap`.
- **A displaced data label is connected to its mark again.** A leader-line gate landed on the shared smart-label path and silently dropped the connector whenever the renderer moved a label to resolve a collision.
- **A chart with no server-rendered SVG no longer aborts the report page.** The runtime called an undefined function, so an older snapshot or an unrendered visual type raised a `ReferenceError` that took every other visual with it. That card degrades to an announced "chart payload missing" state.
- **An `ASSERT JOB` predicate naming a column no sink writes is a lint error at author time.** The runtime skipped the unobserved metric and the assertion passed, so a typo such as `NULL_PERCENT(clean_users.Emial)` was a guard that could never fire.
- **Portal test factories no longer leak their temp directory.** `WebApplicationFactory.DisposeAsync` does not route through `Dispose(bool)`, so every fixture disposed with `await using` left its directory behind — one machine held 74,007 of them across 11 GB.
- **Studio:** a saved file keeps the line endings it was written with; the script pane no longer erases what was typed ~800 ms later; canvas edits apply as ranged transactions so Ctrl+Z genuinely reverses an "Add visual"; the first click after editing a guided-dialog field is not swallowed by a repaint; task-card drag works on the pipeline map; dragging a visual onto the canvas binds a source rather than writing a script that cannot parse; and the Connection Wizard rejects an empty alias instead of writing a literal `<alias>` placeholder.
- **Offline snapshots served over `http` are no longer treated as web mode**, which started auto-refresh polling against an API that is not there and made every detail popover render "could not be loaded".
- **Documentation grammar validation honours CommonMark-indented fences.** The extractor required the closing fence at column zero, so an indented block ran past its own end and swallowed the prose after it. Validated statements rose from 3,457 to 3,495 and the gate now ratchets on that count.

## Known Issues

**ETL-SQL Studio is an Alpha.** It is available and usable, and it does not replace Report Builder or Workstation Editor. What holds it at Alpha is evidence rather than missing features:

- Three of the five hosts Studio runs on are not yet certified.
- Every certified journey is an author's; none is a reader's.
- Row-level security has not been proven under a second identity opening the same report.
- The schedule handoff stops at the statements it writes.

Three authoring limits are known and specific:

- An `IF` created on the pipeline canvas cannot be given an `ELSE` there.
- The task editor can rename most task kinds but not edit their other fields.
- `PARALLEL` branches are drawn without swimlanes.

Four usability gaps found by hand are open: the properties inspector offers no aggregate selector, the dashboard workflow cannot be advanced past cross-filter setup, paginated headers and footers accept text only, and a selection inside the current line is painted over by the active-line highlight.

Hand-written scripts are unaffected either way — Studio reads and writes ordinary `.rptsql` and `.etlsql`, and surgical patching leaves SQL, CTEs, comments, and whitespace it did not target alone. Closing these gaps is scheduled as *Code Stability* in [`ROADMAP.md`](../../ROADMAP.md).

**The orchestrator's four metric chips are disabled** rather than filtering. The counts they display are the service's runtime metrics — how many jobs are running or queued right now — while the table lists job *definitions*, which carry no run state. They are disabled with a title explaining why, rather than throwing.

## Upgrade Guide

### Before you upgrade

1. **Migrate data-quality rules.** Search your scripts for `@expect` and `@fail` comment tags and rewrite them as `EXPECT … ON FAILURE …` clauses. The linter names the clause to use for any tag it finds.
2. **Migrate `ASSERT JOB` severity.** Replace `ON CRITICAL_FAILURE THROW` with `ON FAILURE THROW`, and `WITH (FAIL_ON_WARN = TRUE)` with an explicit `WARN_PERCENT = 0 … ON FAILURE THROW` predicate.
3. **Check `SET REPORT` keys.** An unrecognised key is now a syntax error; the correct spelling is `TIME_ZONE`, not `TIMEZONE`.
4. **Update `rule_tag` consumers.** Any query, dashboard, or export reading `eng.data_quality_rules.rule_tag` must read `rule_clause`, and expect `EXPECT` / `EXPECT #2` values.

### Solo / Workstation

1. Download the `v0.19.0` binary or Windows MSI installer.
2. Run the installer or replace the existing binaries in your execution path.
3. Optionally try the new workbench with `etlsql studio <project>`. Report Builder and Workstation Editor are unchanged.

### Team / Enterprise Portal & Orchestrator

1. Upgrade the Orchestrator service first. Database schema migrations apply automatically.
2. Upgrade Portal instances. In multi-node HA clusters, perform rolling node upgrades behind your load balancer (`/healthz` drain endpoints are supported).
3. If you have a custom consumer of the report manifest, move it to `visual.interaction` and `visual.nativeSvg` before upgrading — the compatibility shim covers stored pre-v0.19.0 snapshots, not new manifests.
4. Optionally set `Scheduler:DefaultTimeZone`, `Reporting:DefaultLocale`, and `Reporting:DefaultNullLabel`. An invalid configured zone or locale now fails at startup rather than silently degrading the deployment to a fallback.

### Secure Outbound Data Gateway

1. Update gateway daemons to `v0.19.0`. Daemons re-authenticate to Portal brokers automatically.
2. Review the new ambiguous-write triage queue in Portal Operations; a restart now promotes abandoned in-flight writes to ambiguous rather than losing them.
