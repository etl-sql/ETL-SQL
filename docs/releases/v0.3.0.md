# ETL-SQL v0.3.0 *(Unofficial)*

**Released:** 2026-04-06

Introducing the **VS Code Extension (Alpha)**, **SSH security keys**, and **hash join performance optimizations**.

---

## Release Summary

v0.3.0 is an unofficial pre-release that focuses on developer tooling and runtime security. The release introduces the first alpha version of the **VS Code Extension** featuring an integrated Language Server (LSP) for syntax checking and formatting. Security is enhanced with SSH key pair generation (`GENERATE SSH_KEY_PAIR`) and file encryption utilities. Database execution is optimized through the implementation of `CompoundKey` hash joins and cross-source SQL pushdown capabilities.

---

## ⚠️ Breaking Changes & Required Actions

- **`ON FLATFILE` syntax standardization:** The file connection keyword `ON FILE` has been deprecated and standardized to `ON FLATFILE`. Scripts targeting CSV, JSON, or XML files must be updated to use the new keyword.

---

## ⏳ Deprecations

- **`ON FILE` syntax**: Use `ON FLATFILE` instead.

---

## Highlights

### VS Code Extension (v0.1 Alpha)

**Audience:** Script Authors

**Problem:** Writing ETL-SQL scripts in standard text editors without syntax highlighting, inline linter checks, or autocomplete required executing scripts repeatedly via the CLI to check for basic spelling errors.

**Solution:** The first alpha release of the official editor extension:
- An integrated Language Server (LSP) providing real-time query parsing.
- Auto-formatting and syntax highlighting.
- Metadata hovers displaying column lineages.
- Direct script execution from the IDE workspace.

---

### Security & Encryption Primitives

**Audience:** Administrators · Script Authors

**Problem:** Pipelines often need to encrypt files before sending them over the network or require SSH key pairs for secure connection authentication.

**Solution:** Built-in cryptographic operations:
- **`GENERATE SSH_KEY_PAIR`:** Generate SSH keys directly in scripts.
- **`ALTER CONNECTION`:** Modify connection parameters dynamically during runs.
- **`ENCRYPT FILE` / `DECRYPT FILE`:** Encrypt and decrypt pipeline data.

---

### Performance: Hash Joins & SQL Pushdown

**Audience:** Script Authors · Evaluators

**Problem:** Joins across diverse data sources (e.g. Postgres and JSON files) failed or ran slowly when dealing with mixed-type keys (strings vs. numerics).

**Solution:** Evaluator optimizations:
- Implemented `CompoundKey` to handle complex and mixed-type hash joins.
- Enabled remote SQL pushdown to delegate operations directly to the source database.
- Added `EXECUTE ... INTO #temp` pushdown blocks.

---

## Improvements

### Language & Engine

- Supported grouping sets (`ROLLUP` and `CUBE`).
- Added column-level lineage tracking during bulk insert.

### VS Code Extension & IDE
- Alpha version of the LSP editor environment.

### Connectors
- Renamed connection parameter target to `ON FLATFILE`.

## Performance

- **CompoundKey hash joins** — Avoids string formatting overhead when evaluating compound keys, reducing CPU execution times by up to 2× for multi-column joins.

---

## Security

- **Encryption Standard:** The PGP-based encrypt/decrypt file commands default to cryptographically strong algorithms with validation checks.
