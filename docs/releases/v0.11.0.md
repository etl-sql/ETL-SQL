# ETL-SQL v0.11.0

**Released:** 2026-06-14

Encrypted datasets, infrastructure-as-code portal reconstruction, and operator CLI tooling
make ETL-SQL ready for governed, multi-user production deployments.

---

## Release Summary

v0.11.0 addresses the three biggest barriers to running ETL-SQL as a shared team service.
**Secure Datasets** add globally unique names, folder-linked ACLs, and portal-managed
at-rest Parquet encryption so cached data is never silently exposed or unprotected.
**Script-First Portal Reconstruction** exports every portal object — users, groups, folders,
ACLs, reports, datasets, SMTP configuration, subscriptions, and alerts — as an idempotent
`.etlsql` bootstrap script, enabling version-controlled disaster recovery and environment
cloning. New **Operator CLI tools** (`etl-sql admin backup`, `admin restore`,
`admin support-bundle`, `admin doctor`) give administrators production-grade operational
capabilities without touching the database directly.

## Highlights

### Secure Dataset Subsystem

**Audience:** Script Authors · Administrators · Report Consumers

Multi-user ETL-SQL environments need to share and cache datasets safely. Previously, dataset
paths were folder-scoped and relative, access control was implicit, and cached Parquet files
sat on disk unencrypted — a data-governance gap in any regulated environment.

v0.11.0 introduces a complete dataset security model:

- **Globally unique dataset names with stable-Id paths.** Each dataset receives a
  content-addressable identifier that is independent of folder layout, eliminating breakage
  when folders are reorganized.
- **Dataset → folder ACL linkage.** Access control lists are evaluated against the dataset's
  parent folder. Assigning `PUBLIC` permission grants folder-level read access, closing
  potential privilege-escalation paths.
- **Portal-managed at-rest Parquet encryption.** The local dataset cache is written in
  encrypted Parquet format. The engine **fails closed** if a weak encryption key is detected,
  and supports automatic key rotation with verification.
- **`EXPORT DATASET` and `PUBLISH DATASET`.** Two new statements package transport-encrypted
  datasets for secure cross-server distribution.
- **Serve-stale-with-warning.** When a dataset refresh fails, viewers receive a staleness
  warning banner instead of a hard error, keeping dashboards available while alerting
  operators.
- **Refresh gates.** Administrators can define conditions that must be met before a dataset
  refresh is accepted, preventing partial or corrupt data from entering the cache.

### Script-First Portal Reconstruction

**Audience:** Administrators · Evaluators

Disaster recovery and environment cloning require the ability to reproduce a portal
configuration from scratch. Manual reconfiguration is slow, error-prone, and impossible to
audit. There was no supported way to version-control a portal's full state.

`EXPORT PORTAL CONFIGURATION` now compiles the entire portal — users, groups, memberships,
folder trees, ACL mappings, report registrations, dataset bindings, SMTP aliases,
subscriptions, and alert rules — into a single idempotent `.etlsql` bootstrap script.

- **Logical names only.** Exported scripts reference objects by name, never by internal
  database ID, making them safe to run against fresh or existing databases.
- **Secrets separation.** Credentials are excluded from the export and replaced with
  `${...}` placeholders. A machine-readable requirements header enumerates every secret the
  script needs, so operators know exactly what to provision before running.
- **`WHAT_IF` dry-run validation.** Running the bootstrap script with `SET WHAT_IF ON`
  validates that all secrets, connections, and dependencies are present without making changes.
- **Content manifest and recovery runbook.** Every export includes an inventory manifest and
  a step-by-step runbook, reducing mean-time-to-recovery from hours to minutes.
- **Automated clean-server round-trip proof.** CI/CD pipelines can export a running portal,
  import the script onto a clean server, and assert parity — providing continuous confidence
  that backups are restorable.

### Multi-User Correctness & Recovery

**Audience:** Administrators

Running ETL-SQL with multiple concurrent users exposed several correctness gaps: orphaned
assets when users were removed, non-atomic audit writes, and race conditions in subscription
and refresh-token lifecycles.

This release hardens the multi-user runtime:

- **Folder/asset ownership lifecycle.** Deleting or disabling a user transfers owned folders
  and assets to a designated administrator, preventing orphans.
- **Atomic audit recording.** Audit events are written transactionally so partial failures
  never produce incomplete records.
- **Durable per-job execution lease.** Each running job acquires a lease that survives
  transient portal restarts, preventing duplicate execution.
- **Recoverable subscription lifecycle.** Subscription state machines handle crash recovery
  gracefully, resuming from the last committed checkpoint.
- **Per-user execution fairness.** A scheduling fairness policy prevents any single user's
  jobs from monopolizing execution capacity.
- **Refresh-token reuse detection.** Reuse of a previously consumed refresh token
  immediately invalidates the entire token family, mitigating token theft.

### Operator Tooling CLI

**Audience:** Administrators

Production ETL-SQL instances lacked first-party operational tooling, forcing administrators
to write ad hoc scripts for initialization, diagnostics, backup, and restore.

The new `etl-sql admin` command group provides:

- **`etl-sql init`** — Scaffolds a starter project directory, generates a cryptographically
  strong JWT secret, and creates a runnable template script. Gets a new environment to
  first-run in under a minute.
- **`etl-sql admin doctor`** — Runs a suite of environment health checks (database
  connectivity, schema version, disk space, certificate validity) and reports pass/fail
  with remediation hints.
- **`etl-sql admin support-bundle`** — Compiles host health statistics, connection tests,
  and recent logs into a credential-redacted ZIP archive suitable for sharing with support.
- **`etl-sql admin backup`** — Produces a split-custody backup: configuration and data are
  separated from encryption keys so that no single archive contains everything needed to
  decrypt sensitive material.
- **`etl-sql admin restore`** — Restores from a backup with fail-closed validation
  (`--validate`). Key version, file integrity, and platform compatibility are verified before
  any data is written.

### Language & Engine Enhancements

**Audience:** Script Authors

- **Inline tags in `CREATE TABLE`.** Tags can now be declared directly in table DDL rather
  than requiring a separate `CREATE TAG` statement, reducing boilerplate for metadata-rich
  schemas.
- **`INT(N)` fixed-width integers.** `INT(1)` through `INT(8)` declare storage-efficient
  fixed-width integer columns, useful for connectors and file formats that distinguish
  integer widths.
- **Memory-grant arbiter.** A process-wide arbiter tracks and budgets memory grants across
  concurrent operations, preventing any single query from exhausting available memory.
- **Tag value validation.** Tag values are now validated against their declared type at parse
  time, catching misconfigurations before execution.
- **Lineage cycle warnings.** The lineage engine detects and warns about circular
  dependencies in data flows, helping script authors identify unintentional feedback loops.

## Improvements

### Language & Engine
- Added `INT(N)` fixed-width integer type family for storage-efficient schema declarations.
- Memory-grant arbiter now tracks and budgets concurrent operation memory usage process-wide.
- Tag value validation enforced at parse time.

### Portal
- Automatic SQLite schema migrations execute on portal startup with fail-fast behavior — if
  the schema cannot migrate successfully the portal refuses to start, preventing silent
  data-model drift.
- Optimistic-concurrency control added for concurrent administrative operations, preventing
  lost-update anomalies when multiple administrators edit settings simultaneously.

### Connectors
- FLATFILE connector dialect resolution corrected — the engine now selects the proper CSV/TSV
  dialect based on file extension and explicit configuration rather than falling back to a
  hardcoded default.

### Documentation
- Documentation validation pipeline extended with connector-aware checks, ensuring that
  connector examples in the manual compile against the current parser.

## Performance

- Memory-grant arbiter prevents over-commitment under concurrent workloads, reducing
  out-of-memory failures during parallel pipeline execution.

## Security

- **Backup artifact permissions.** Backup files are written with owner-only access
  privileges (`0600` for files, `0700` for directories) to prevent other local accounts
  from reading sensitive backup data.
- **Session and anonymous hardening.** Strengthened session management and anonymous-access
  controls, including rate limiting on authentication endpoints and Content Security Policy
  (CSP) headers.
- **Runtime secret rotation.** Secrets (JWT signing keys, encryption keys) can now be
  rotated at runtime without restarting services.
- **Auth/SSRF/injection/key-handling blockers closed.** Addressed multiple security review
  findings including SSRF prevention, SQL injection hardening, `.p8` private key file
  handling, and audit-trail completeness.
- **Dependabot enabled.** Automated dependency vulnerability scanning added for both NuGet
  and npm package feeds.

---

## Bug Fixes

- **FLATFILE dialect resolution now works correctly.** The FLATFILE connector properly
  resolves the CSV/TSV dialect from file metadata and explicit configuration instead of
  ignoring the setting.
- **SessionCache race conditions eliminated.** Concurrent session access no longer leaks
  cache entries or serves stale admin context.
- **Refresh-token debounce race resolved.** Rapid token-refresh requests no longer
  occasionally produce duplicate tokens.
- **Disabled LDAP accounts are now rejected at login.** Previously, accounts disabled in the
  LDAP directory could still authenticate under certain timing conditions.
- **Hardcoded first-run admin password removed.** The initial administrator account now
  requires an explicit password set via `etl-sql init` or an environment variable —
  eliminating a default-credential risk.
- **Dataset encryption metadata corrected.** Encrypted dataset metadata headers are now
  written consistently, fixing decryption failures that occurred after key rotation.
- **"Manage" access level changes take effect immediately.** Changing a user's access level
  to or from "Manage" no longer requires a portal restart.

## Upgrade Guide

1. Stop all ETL-SQL services.
2. Replace binaries with the v0.11.0 release assets.
3. Restart services — the portal will automatically migrate its SQLite schema on first
   startup. If migration fails, the portal will refuse to start and log the specific error.
4. Run `etl-sql admin doctor` to verify environment health.
5. Review the license change from PolyForm Noncommercial 1.0.0 to Apache License 2.0 with
   your legal or compliance team if required.
