# v0.21.0 Performance Results — Smoke Baseline Deviation

**Status:** Explained deviation, accepted by the owner on 2026-10-18. The checked-in baselines are
unchanged and no band was widened. No engine speedup or slowdown is claimed.

## Result

On the candidate (`b825b8667`) the Smoke tier fails its baseline comparison on two scenarios. Every
other Smoke measurement, the Standard tier and the 10M spill allocation budget pass.

| Scenario | Baseline | Candidate in the Smoke tier |
| :--- | ---: | ---: |
| `ParquetRoundTrip_50000` | 31 ms | 86–125 ms |
| `ReportDatasetSnapshotReload_50000` | 319 ms | 503–564 ms |

The same numbers came from the working checkout and from a clean worktree, in four runs.

## Cause: the baseline measured a warm start

Both scenarios read a Parquet file that holds decimals. In the full Smoke tier, scenarios that run
earlier used to spill decimals through the Arrow `Decimal128` Parquet path, so that code was already
compiled when these two were timed. Commit `be3175f3e` (2026-10-13) stores spilled decimals as
strings so each value keeps its own precision and scale. The earlier scenarios no longer exercise
`Decimal128`, and these two scenarios now include its first-use cost.

Evidence, all on the same host, with the candidate's runner for every arm:

1. **Full Smoke tier, candidate/control/control/candidate, 5 samples:** v0.20.1 measured 33 and 30 ms
   and 335 and 344 ms. The candidate measured 100 and 116 ms and 530 and 564 ms. The two controls
   agreed with each other.
2. **`git bisect` over the 169 commits, full Smoke tier per step:** the first slow commit is
   `be3175f3e`.
3. **Each scenario alone, candidate/control/control/candidate, 5 samples:**

   | Scenario, run alone | v0.20.1 | v0.21.0 |
   | :--- | ---: | ---: |
   | `ParquetRoundTrip` | 98, 99 ms | 98, 100 ms |
   | `ReportDatasetSnapshotReload` | 602, 578 ms | 581, 584 ms |

Run alone, the released version is as slow as the candidate. The Parquet reader and the dataset cache
did not get slower; the baseline's values depended on which scenarios ran first.

## Decision

Keep the checked-in baseline and record these two failures as explained. Recalibrating them now
would bake in a different run-order dependence. The harness fix, warming each scenario's own path
before timing it and then recalibrating from clean candidate/control runs, is in
[`ROADMAP.md`](../../ROADMAP.md).

The released v0.20.1 control no longer restores by default: a later advisory on
`System.Security.Cryptography.Pkcs` is a warning treated as an error. The control arms ran with
`NuGetAudit=false`, which does not change what is built. v0.21.0 pins the patched package.

Evidence: `artifacts/release-evidence/0.21.0/ci-gaps/` (`smoke-compare-*`, `bisect.log`,
`isolated-*`, and the driver scripts).
