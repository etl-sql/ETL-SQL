# ETL-SQL v0.14.0

**Released:** 2026-07-05

Billion-row columnar execution, row-level security, and enterprise-grade policy enforcement arrive in a single release.

---

## Release Summary

v0.14.0 makes ETL-SQL production-ready at billion-row scale by shipping a native columnar execution engine with a process-wide RAM governor and extent-based spilling. Row-Level Security ensures shared reports automatically filter data by the viewer's identity, eliminating the need for per-audience script copies. Enterprise Policy Enforcement (Phase 3) adds signed, machine-authenticated policy distribution so administrators can govern connector egress, resource ceilings, and filesystem access across every runner in the organization.

---

## ⚠️ Breaking Changes & Required Actions

- **Default temp storage switched from row-based to columnar.** The `#temp` storage engine now defaults to the new append-only columnar format. This change is transparent to scripts — all existing SQL continues to work — but memory consumption profiles may shift because columnar batches allocate contiguous `ColumnBatch` buffers rather than individual `DataRow` objects. **Action:** Monitor peak working-set memory on your first few runs after upgrading. If you encounter memory pressure on constrained hosts, set `Engine:TempStorage:Mode` to `RowBased` in `appsettings.json` to revert while you tune the RAM governor's grant ceiling.

## ⏳ Deprecations

- None in this release.

## Highlights

### Billion-Row Columnar Execution Foundations

**Audience:** Script Authors · Administrators · Evaluators

Large-scale ETL jobs previously hit a performance wall because the engine processed data row-at-a-time through `DataRow`/`DataTable` objects, causing excessive GC pressure, poor CPU cache utilization, and unpredictable memory growth. Spilling to disk relied on many small files, thrashing OS file handles on high-throughput workloads.

v0.14.0 introduces a ground-up columnar execution path. A native **append-only segmented `#temp` storage engine** writes data into `ColumnBatch` buffers that keep columns contiguous in memory, dramatically improving cache locality for projection, selection, and aggregation operators ("columnar islands"). A **process-wide Memory Grant Arbiter** (RAM governor) coordinates memory budgets across all concurrent operators — external sort, hash join, distinct, aggregation, and window functions — preventing any single query from starving the system. When an operator exceeds its grant, data spills to disk in **large sequential extents** targeting 128 MB blocks, minimizing file-handle churn and maximizing NVMe throughput. **Bounded double-buffered pipelining** overlaps background extent writes with foreground evaluation so CPU cores stay busy during heavy spills. Adaptive hash partition sizing tunes partition counts at runtime based on actual data distribution.

Formal **Scale Certification Tiers** define the tested boundaries for this release:

| Tier | Dataset Size | Row Count |
| :--- | :--- | :--- |
| Smoke | 1 GB | — |
| Standard | 4 GB | 10 M rows |
| Stress | 8 GB | 5 M rows |
| Huge | 16 GB | 50 M rows |

> **Design context:** See [BillionRowOperatorCertification.md](../architecture/decisions/BillionRowOperatorCertification.md) for the operator-specific certification matrix, admission criteria, and scenario contracts.

### Row-Level Security (RLS) & Impersonation (Phases 1 & 2)

**Audience:** Script Authors · Report Consumers · Administrators

Shared reports that contain sensitive data previously required either separate script copies per audience or fragile `LIKE`-based filtering that was easy to bypass. There was no engine-enforced guarantee that user A's data would never leak to user B through cached snapshots or bulk subscriptions.

RLS introduces **unforgeable, trust-injected system variables** that the engine sets from the authenticated caller's identity — outside user-controlled parameter namespaces — so scripts can filter rows without risk of impersonation or injection:

| Variable / Function | Purpose |
| :--- | :--- |
| `@@CURRENT_USER` | Effective principal running the query |
| `@@CURRENT_USER_ID` | Numeric ID of the effective principal |
| `@@REAL_USER` | Actual authenticated actor (unchanged during impersonation) |
| `@@IS_ADMIN` | Boolean administrative-status flag |
| `HAS_GROUP('name')` | Set-membership predicate for group checks |
| `HAS_ROLE('name')` | Set-membership predicate for role checks |
| `USER_GROUPS()` | TVF returning all groups for the current user |
| `USER_ROLES()` | TVF returning all roles for the current user |

The compiler rejects any attempt to `DECLARE` or write to system variables. When the engine detects RLS variables or functions in a script's AST, it automatically **disables shared snapshot caching** (preventing cross-user data leaks) and executes **subscriptions per-recipient** so each subscriber's predicates evaluate against their own identity.

Administrators can use **secure preview-as / impersonation** to test how a report renders for a specific group (e.g., `Region:East`) without leaving the Portal.

```sql
-- Filter sales data to the current user's region
SELECT *
FROM   Sales.Orders o
WHERE  HAS_GROUP('Region:' + o.Region)
ORDER  BY o.OrderDate DESC;
```

> **Design context:** See [RowLevelSecurity.md](../architecture/decisions/RowLevelSecurity.md) for the trust-injection boundary, read-only system variables, admin bypass, and impersonation model.

### Enterprise Policy Enforcement & Monitoring (Phase 3)

**Audience:** Administrators

In multi-tenant or regulated environments, administrators had no centralized way to enforce connector egress restrictions, resource ceilings, or filesystem boundaries across distributed runner machines. Policies had to be manually configured per host, creating drift and compliance gaps.

Phase 3 delivers a complete **policy-authority API** (`api/admin/policy-authority`) with admin-only endpoints to publish, sign, roll back, and audit organization-wide policies. Enrolled machines fetch policies via **signed distribution envelopes** authenticated through OIDC headers, verifying key signatures before loading. Policies use **monotonic issuance** numbering to guarantee ordering and support **staged rollout** with **emergency rollback**.

Once loaded, the policy snapshot is **immutable for the lifetime of a script execution** (`ExecutionPolicySnapshot`), preventing in-script overrides of resource ceilings such as `MAX_PARALLEL_DEGREE` and `MAX_FILE_OPERATIONS`. The snapshot propagates consistently through the CLI, TUI, Portal, Orchestrator, parallel branches, recursion, and scheduled jobs.

### File Connectors & Excel Write

**Audience:** Script Authors

Writing ETL results to Excel previously required external tooling or manual steps. v0.14.0 adds native **write and append support for `.xlsx`** files via MiniExcel, enabling scripts to produce formatted Excel output directly. The file connector layer also gained **stream-on-the-fly decryption and decompression**, so encrypted or compressed source files are processed in a single streaming pass without staging temporary copies. New `.etlds` and `.etlsnap` file extensions are now recognized by the engine.

### Host Metrics & Operational Alerting

**Audience:** Administrators

Administrators lacked visibility into the health of runner hosts between script executions. v0.14.0 adds **persistent host metrics collection** — disk, memory, and CPU — with a `SHOW HOST METRICS` statement for ad-hoc inspection and **daily rollups** for trend analysis. A **stale RUNNING→INTERRUPTED reconciliation** process detects executions that were orphaned (e.g., by a host crash) and marks them as interrupted. The Portal now sends a periodic **operational metrics digest email** summarizing queue depth, failure rates, and resource utilization.

## Performance

- **Columnar island operators** — Projection, selection, and arithmetic aggregation now operate directly on contiguous `ColumnBatch` memory slices, reducing CPU cache misses compared to the row-at-a-time path.
- **Adaptive hash partition sizing** — Hash-based operators resize their partition count at runtime based on actual cardinality estimates, reducing both over-partitioning overhead and under-partitioning spill volume.
- **Default columnar temp storage** — All pipeline steps use the columnar storage path by default, eliminating per-row boxing and `DataRow` allocation overhead.

---

## Security

- **Execution Policy Enforcement Boundary** — Every script execution captures an immutable `ExecutionPolicySnapshot` at startup. The snapshot is shared consistently across the CLI, TUI, Portal, Orchestrator, parallel branches, recursion, and scheduled jobs, preventing policy bypass through indirect invocation paths.
- **Governed Connector Egress** — Connector destinations are validated against host, scheme, and port allowlists at connect time. DNS-rebinding and proxy-bypass attacks are mitigated by pinning resolved socket addresses, normalizing obfuscated IPs, and rejecting URLs with embedded credentials.
- **Filesystem Policy Boundary** — Local file operations are restricted to administrator-approved paths. File handles are re-validated before OS calls, and link-substitution race conditions (TOCTOU) are mitigated by checking the resolved target immediately before the operation.
- **Governed Resource Ceilings** — Enterprise-defined ceilings for `MAX_PARALLEL_DEGREE`, `MAX_FILE_OPERATIONS`, and related limits are enforced from the immutable policy snapshot, preventing in-script escalation.
- **Removed `.tmp` from allowed file extensions** — Scripts can no longer read or write `.tmp` files, reducing the attack surface for temporary-file hijacking.

## Bug Fixes

- **`QuoteIdentifier` now correctly sanitizes all injection vectors** — The SQL identifier quoting function handles edge-case bracket and quote sequences that previously allowed SQL injection in generated statements.
- **VS Code Extension and TUI vulnerabilities resolved** — Addressed multiple security findings in the extension and terminal UI, including terminal command builder escape-sequence bugs that could allow argument injection.
- **TUI window resize no longer blocks input on Unix** — Resizing the terminal window during an active session no longer causes input lag or complete blocking; the resize handler now processes the signal asynchronously.

## Upgrade Guide

1. Stop all ETL-SQL services and the Portal.
2. Install the new binaries (MSI, `.deb`, or ZIP replacement).
3. Restart services.
4. Monitor memory utilization on the first few executions — the new columnar temp engine has a different allocation profile than the row-based engine. If necessary, set `Engine:TempStorage:Mode` to `RowBased` in `appsettings.json` and restart.
5. If using Enterprise Policy Enforcement, verify that enrolled machines can reach the policy-authority API endpoint and that OIDC authentication is configured.
