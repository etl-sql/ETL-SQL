# v0.23.0 Script and Test Review Plan

**Status:** Accepted by the owner 2026-11-22. Slices `RV01`–`RV05` are complete. Their findings are recorded below.

## Purpose and Finish Line

Scope a full review of `scripts/` and `tests/` for v0.23.0 so every script and test project has an owner, a CI/release lane mapping, a concrete review method, clear finding criteria, and bounded delivery slices.

**Finish line:** This plan is accepted by the owner, and slices `RV01`–`RV05` are scheduled and closed with every finding fixed or explicitly waived.

## What the v0.22.0 Tooling Review Already Swept

The [v0.22.0 tooling review](v0.22.0-tooling-review.md) (2026-11-09 to 2026-11-10) inspected release-critical scripts and ran repository-wide automated checks:

- **Read line by line:** Every script called by CI or release workflows — CI/release selection, evidence collectors, MSI/DEB/native installers and packagers, test-lane runners, certification drivers, and source gates/hooks (34 defects fixed; held v0.23.0 items later closed).
- **Scanned for swallowed errors and empty-input passes:** HA plan generators, `Export-HaSoakDiagnostics`, `generate-browser-contracts`, and `lib/browser-asset-inputs` (verified by their own self-test suites).

What that review did **not** read line by line: the ~1,355 C# test files across the 9 test projects, the SQL/scenario/fixture corpora, and the full inventory of `scripts/checks/` self-tests against their production callers.

## What Counts as a Finding

Every review pass flags defects in these five categories:

1. **Vacuous pass:** A test or check script passes when the feature under test fails, returns early on OS/tool checks instead of using `[WindowsFact]`/`[UnixFact]`/`[SymlinkFact]`, checks only non-null / byte length instead of semantic values, or catches/ignores a real failure.
2. **Orphaned test or script:** A test class/method excluded by every CI and Release Evidence filter (missing or misspelled `Category` trait, unrun PR/push gap), or a script under `scripts/` with no live caller, self-test, or documented operator use.
3. **Producer/fixture mismatch:** A mock, API recording, or synthetic test fixture shaped to satisfy the consumer rather than matching real producer output.
4. **Swallowed failure or silent fallback:** Ignored `$LASTEXITCODE`, unchecked `spawnSync` exit status, missing `TreatNoTestsAsError` / empty-list pass, or silent fallback that masks regressions.
5. **Flake or resource hazard:** Fixed `Thread.Sleep` / `Task.Delay` synchronization without condition polling, shared static or temp-directory state across parallel tests, or undisposed servers, containers, or spill directories.
