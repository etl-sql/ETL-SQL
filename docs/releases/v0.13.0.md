# ETL-SQL v0.13.0

**Released:** 2026-06-28

Native Apache Arrow snapshots replace JSON row serialization, giving the Portal columnar streaming and host-bound encryption by default.

---

## Release Summary

v0.13.0 transitions the snapshot pipeline from JSON to Apache Arrow IPC, delivering faster report rendering and smaller payloads for large result grids. Operators gain first-class execution observability through per-run resource metrics (CPU, memory, duration) and two new `SHOW` statements for querying portal health. The release also ships a broad security hardening pass — including PII column encryption, authenticated machine-bound encryption (encrypt-then-MAC with HKDF-SHA256), and ReDoS backtracking protection — alongside engine-wide stabilization and performance caching improvements.

## Highlights

### Apache Arrow Snapshot Integration

**Audience:** Report Consumers · Administrators

Large report snapshots serialized as JSON rows created slow page loads, high memory pressure on clients, and bloated storage. Portal operators had no columnar streaming path, and at-rest encryption required explicit key configuration.

v0.13.0 replaces the JSON snapshot pipeline with end-to-end **Apache Arrow IPC** serialization. The `SnapshotStore` compiles query outputs into compressed `.etlsnap` ZIP packages containing Arrow column batches. The Portal front-end decodes these streams on demand via a bundled `arrow.min.js` library, lazy-loading rows instead of materializing the full JSON grid. When `Portal:Dataset:AtRestKey` is left unconfigured, snapshots are encrypted at rest using a **host-bound fallback** — Windows DPAPI `LocalMachine` or a `machine-id`-derived AES-256-GCM key with authenticated encrypt-then-MAC (HKDF-SHA256) — so data is locked to the host OS without any operator setup.

```sql
-- Snapshots are created automatically during report execution.
-- No script changes needed — the engine writes .etlsnap Arrow packages transparently.
```

### Portal Execution Metrics & Observability

**Audience:** Administrators · Script Authors

Operators previously had no visibility into per-execution resource consumption, making it difficult to identify expensive reports, diagnose queue backlogs, or plan capacity.

Executions now persist **CPU usage, peak memory working set, and wall-clock duration** to the Portal database (via EF migrations supporting both SQLite and PostgreSQL). A new historical execution-load metrics endpoint exposes these data points for dashboards and alerting. Two new statements — `SHOW PORTAL USAGE METRICS` and `SHOW PORTAL OPERATIONAL METRICS` — let script authors query queue depth, execution concurrency caps, refresh failure counts, storage size, and load/resource buckets directly from within `EXECUTE portal` contexts.

```sql
EXECUTE portal BEGIN
    -- Check current queue depth and failure rates
    SHOW PORTAL USAGE METRICS;

    -- Inspect concurrency caps and resource buckets
    SHOW PORTAL OPERATIONAL METRICS;
END;
```

### Engine Lock Inspection

**Audience:** Script Authors · Administrators

Diagnosing script blocks and resource contention required external tooling or guesswork, with no engine-native way to see which locks were held and by whom.

The new `SHOW LOCKS` statement queries active **engine-level and orchestrator-level resource locks** in a single result set. Developers can identify contention sources, blocked sessions, and long-held orchestrator locks directly from the SQL prompt.

```sql
-- Inspect all active locks across the engine and orchestrator
SHOW LOCKS;
```

### LSP Cross-File Declaration Resolution

**Audience:** Script Authors

In multi-file workspaces, `GO TO DEFINITION` and hover information only resolved symbols within the current file, forcing developers to manually search for table or procedure declarations across scripts.

The Language Server now analyzes **all files in the current workspace** for declaration resolution. `HoverProvider` and `DefinitionProvider` resolve tables, procedures, and variables defined in adjacent scripts. Combined with new definition caching, this eliminates repeated metadata scans and keeps keystroke latency low even in large folders.

## Improvements

### Language & Engine

- Improved `LineageTracker` indexing to replace linear sweeps with indexed lookups during evaluation.
- Added `ParameterScanner` caching and `RunScript` parse caching to reduce redundant work in repeated executions.
- Implemented `AssetFingerprinter` improvements for faster change detection.
- Tuned spill-store, external sort, and external join paths for better I/O throughput.
- Applied a broad stabilization and hardening pass across engine handlers and analysis layers.

### Portal & Visualization

- Added lazy-loading Arrow IPC snapshot row rendering to reduce client memory usage on large grids.
- Introduced TUI frame metadata caching for allocation-free redraws on unchanged frames.
- Fixed TUI frame caching invalidation after connection or tab changes.

### VS Code Extension & IDE

- Added LSP definition caching to eliminate repeated workspace scans on each keystroke.
- Enabled cross-file `GO TO DEFINITION` and hover resolution across all workspace files.

### Connectors

- Fixed SFTP connector option serialization to correctly round-trip all configured options.

## Performance

- **LineageTracker indexing** — Replaced slow linear sweeps with O(1) indexed lookups during lineage evaluation, reducing overhead on scripts with deep dependency chains.
- **ParameterScanner & RunScript parse caching** — Eliminated redundant parsing on repeated script executions by caching parameter scans and parse trees.
- **LSP definition caching** — Cached token definitions and metadata scans to keep keystroke latency low in workspaces with many files.
- **TUI frame metadata caching** — Allocation-free redraws for unchanged Terminal IDE frames, cutting CPU overhead during editing sessions.
- **Machine-aware orchestrator defaults** — Concurrency ceilings now auto-tune to the host machine's core count and available memory, with `ChildProcessTracker` ensuring child processes are cleaned up and a startup temp-table sweep reclaims stale resources.

---

## Security

- **PII column encryption at rest** — Portal database columns storing user emails and display names are now encrypted using a key derived from the cluster Data Protection keyring.
- **Support bundle hardening** — Connection strings, API keys, and JWT secrets are redacted from support bundles before export.
- **Crypto hardening** — Consolidated `MachineBoundCrypto` and `CryptoUtils` paths for consistent key derivation and encryption across the engine.
- **Authenticated machine-bound encryption** — Snapshot at-rest encryption fallback upgraded to encrypt-then-MAC with HKDF-SHA256, preventing ciphertext tampering.
- **`machine.key` file permissions** — Owner-only permissions (`0600`) are enforced on the generated machine key file to prevent local privilege escalation.
- **Service Account token exchange timing mitigation** — Constant-time comparison on token exchange to prevent timing side-channel attacks.
- **Client certificate store handle leak cleanup** — Certificate store handles are now properly disposed to prevent resource exhaustion under high connection churn.
- **ReDoS backtracking hardening** — Core parsing regexes use `GeneratedRegex` with a `1000 ms` timeout to protect against catastrophic backtracking.
- **Egress sanitization** — Output encoding and URL sanitization hardened across Portal responses.

---

## Bug Fixes

- **Support bundle export** now correctly redacts connection strings, API keys, and JWT secrets before packaging.
- **Portal database migrations** now execute in a deterministic order, and timezone values are normalized consistently across SQLite and PostgreSQL backends.
- **SFTP connector options** are now serialized and deserialized correctly, preserving all user-configured values across restarts.
- **TUI frame cache** properly invalidates after connection or tab changes, preventing stale frames from persisting on screen.
- **Migration lint corpus** updated to cover current schema, eliminating false-positive lint warnings on valid migrations.
- **Scheduler test mocks** corrected to supply the expected argument count, fixing intermittent test failures.
- **`GROUP BY ALL`** now correctly expands columns when star-modifiers (e.g., `* EXCEPT`, `* REPLACE`) are present in the `SELECT` list.
- **Positional reference star projections** now pass validation checks, allowing `SELECT 1, t.*` patterns in positional-reference contexts.

## Upgrade Guide

Standard upgrade — replace binaries and restart services. No configuration changes required.

The Portal database will automatically apply EF migrations on first startup to add execution-metrics columns. Snapshot files created by earlier versions will continue to be served as JSON; new snapshots will use the Arrow IPC format automatically.
