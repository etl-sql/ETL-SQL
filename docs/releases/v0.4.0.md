# ETL-SQL v0.4.0 *(Unofficial)*

**Released:** 2026-04-20

Introducing **Report-SQL Scripting (`.rptsql`)**, **visual layouts**, and **VS Code live dashboard previews**.

---

## Release Summary

v0.4.0 is an unofficial pre-release that introduces native **Report-SQL (`.rptsql`)** visualization support. This enables developers to declare pages, datasets, and visuals (Bar, Line, Pie, tables, cards, and slicers) using a declarative query dialect. The release also ships the **ReportBuilder library** (Chart.js and Markdown outputs), a local Kestrel dashboard server (**ReportPlayer**), job retry mechanisms in the Orchestrator, and window query disk spilling.

## Highlights

### Report-SQL (`.rptsql`) & Visual Declarations

**Audience:** Script Authors · Report Consumers · Evaluators

**Problem:** Building dashboards previously required third-party BI software or custom front-end apps, decoupling the data engineering step from the presentation view.

**Solution:** Script-first visualization declarations:
- Write visual components directly in `.rptsql` files using `CREATE VISUAL`, `CREATE PAGE`, and `CREATE DATASET`.
- Full support for `BAR`, `LINE`, `PIE`, `SCATTER`, `TABLE`, `CARD`, and filter `SLICER` types.
- Layout definition mappings with responsive container slots.

```sql
-- Define a simple visual card
CREATE VISUAL TotalSales AS CARD (
  SOURCE = sales_dataset,
  VALUE = SUM(revenue),
  LABEL = 'YTD Revenue'
);

-- Organize visuals on a page grid layout
CREATE PAGE SalesDashboard AS (
  STRUCTURE = 'A B / C C',
  MAP ('A' = TotalSales, 'C' = SalesGrid)
);
```

---

### VS Code Live Report Previews

**Audience:** Script Authors

**Problem:** Authors had to compile scripts and run CLI refresh tools to inspect chart outputs, making visual iterations slow.

**Solution:** VS Code webview panel integration:
- Open a live, interactive visualization sidebar directly inside the editor.
- Renders Chart.js charts, data tables, and filters.
- Real-time parameter injection updates visual structures.

---

### Orchestrator Retry & Window Spilling

**Audience:** Administrators

**Problem:** Intermittent database dropouts aborted whole jobs, while huge window queries (e.g. `ROW_NUMBER` partitioning) exhausted server memory.

**Solution:** Scale and stability improvements:
- Orchestrator jobs implement configurable retries with exponential backoffs.
- In-memory `#temp` tables support spilling to disk and result capping thresholds.
- Bounded partition spilling for window queries handles larger-than-memory partition counts.

## Improvements

### Language & Engine
- Added the `ASSERT` statement to validate data qualities natively.
- Implemented standard ANSI string functions (`SUBSTRING`, `POSITION`, `OVERLAY`, `TRIM`, `EXTRACT`).
- Added statistical aggregate calculations.
- Added DATEPART and PIVOT/UNPIVOT validations in the compiler.

### Portal & Visualization
- Introduced the `ReportBuilder` helper CLI.

### VS Code Extension & IDE
- Added preview layouts to the extension sidebar.

### Connectors
- Enhanced JSON and XML file schema validations.

---

## Performance

- **Window deep-spilling** — Window partitions are streamed to disk when they exceed memory grant thresholds, keeping memory usage flat.

---

## Security

- **XML/JSON Hardening:** Enforced XML entity parsing constraints to block external entity expansion attacks (XXE).
