# ETL-SQL v0.23.0

**Released:** 2026-11-26

GitHub published this release at 03:33 UTC (November 25 at 9:33 p.m. Central), ahead of the planned November 29 date.

## Release summary

v0.23.0 moves Windows service configuration from the MSI into the services and lets administrators
provision Studio pipelines directly in the Orchestrator. In hosted 100M-row benchmarks, external
sort, window, and join allocated 68–82% less memory. This release also expands `TRANSFORM` with eight new
analyst operations, adds remote directory management, archive formats, and detached OpenPGP
signatures, and closes key connection, snapshot, and tenant-isolation gaps.

## Breaking changes and required actions

Read [the complete breaking-change ledger](../../BREAKING_CHANGES.md) and
[migration guide](../guides/onboarding/migration-guide.md) before upgrading.

- **Windows MSI configuration split (`appsettings.defaults.json`):** The MSI no longer runs script
  custom actions (`configure-portal-jwt.ps1` and `installer-actions.js` are removed) and no longer
  overwrites `appsettings.json`. Release defaults now live in `appsettings.defaults.json` (do not
  edit it); `appsettings.json` holds only your overrides (`{}` on a fresh install). On first start,
  the Orchestrator or Portal generates service secrets into `appsettings.secrets.json` and writes
  `first-run-password.txt` on fresh installs. Upgrading from v0.22.0 keeps your `appsettings.json`
  and strips values equal to the v0.22.0 defaults once. Uninstalling no longer deletes runtime data;
  use `etl-sql admin purge-data --confirm` to remove data intentionally. See [Upgrade guide](#upgrade-guide)
  for in-place restore options.
- **Publishing reports by script path requires `ScriptIngress`:** `POST /api/reports` (the CLI
  `PUBLISH REPORT` statement and script-path publication in `SourceControlled` Studio mode) now
  requires the `ScriptIngress` Studio capability in addition to `ReportPublish` and folder Manage.
  Grant `ScriptIngress` to roles or groups that publish by script path (for example
  `Portal__Studio__RoleCapabilities__Admin__2=ScriptIngress`), or calls return HTTP 403.
- **Pipeline provisioning checks Studio read access:** The Orchestrator pipeline catalog and
  provisioning endpoints now require read access to the Studio document. Grant read access to the
  Studio folder or document before provisioning its job (unauthorized provisioning returns HTTP 403).
- **Remote orchestration tenant and Gateway boundaries:** Run-detail reads authorize the recorded
  tenant and job identity (foreign run IDs return HTTP 404). Completion feeds filter by tenant
  before pagination and exclude unscoped legacy runs. Connection sync retains Gateway bindings;
  re-synchronize Gateway connections that were previously exported without their binding.
- **Cached report snapshots enforce `SHARED:` connection `Use` ACLs:** Snapshots record the
  `SHARED:` connection aliases expanded at execution time and re-check caller `Use` permissions on
  every read, export, and designer snapshot request (HTTP 403 on denial). Legacy snapshots without
  recorded dependencies verify their source hash and statically scan the script, failing closed on
  missing/changed source or unresolved dynamic connections. Refresh older snapshots and grant
  connection `Use` permission to readers.
- **Machine vault creation requires elevation:** Local vault directories receive restrictive ACLs
  before any value is written. Run `LocalMachine` vault administration elevated, or use
  `CurrentUser` protection for personal workstation stores.
- **Remote non-empty `DELETE DIRECTORY` requires `RECURSIVE = ON`:** `DELETE DIRECTORY ... AT conn`
  on a non-empty remote folder now fails across all connectors unless `WITH (RECURSIVE = ON)` is
  specified. Update scripts that relied on connectors deleting non-empty folders implicitly.
- **Remote file listings have four more columns.** `REMOTE_FILE_LIST` and remote file connection
  queries now expose `CreationTime`, `Permissions`, `Owner`, and `IsSymlink`, with `NULL` where the
  connector cannot provide a value. Select columns explicitly where a consumer expects the old shape.
- **Local-only file encryption and compression:** `ENCRYPT FILE`, `DECRYPT FILE`, `COMPRESS FILE`,
  and `DECOMPRESS FILE` now refuse a remote connection as source or destination. Encrypt or compress
  locally, then transfer the result with `SEND FILE` or `RECEIVE FILE`.
- **Strict `ENCRYPT` option validation:** File connectors, `EXPORT DATASET`, and `PUBLISH DATASET`
  now reject unrecognized `ENCRYPT` values instead of treating typos as `OFF` and writing plaintext.
- **`MSSQL` `TRUSTED_CONNECTION=TRUE` with credentials:** Combining `TRUSTED_CONNECTION=TRUE` with
  `USER` or `PASSWORD` now fails at `CREATE CONNECTION` instead of silently ignoring the credentials.
- **Unscheduled `CREATE JOB` defaults to `MANUAL`:** Jobs created without a linked schedule now run
  only when triggered instead of firing every hour. Link a schedule (`CREATE SCHEDULE`,
  `ALTER JOB ... ADD SCHEDULE`) for recurring runs.
- **Ambiguous `PIVOT` outputs rejected:** `TRANSFORM ... USING PIVOT` rejects output column names
  that collide with grouping columns or the `NULL` label before modifying the target.
- **Lower default `SystemMemoryFloorMB`:** Under the unified memory coordinator, the default
  `SystemMemoryFloorMB` changed from `4096` to `512` (override in `appsettings.json` if needed).
- **Query correctness fixes:** Pre-join filter pushdown on `RIGHT`/`FULL` joins, merge `SEMI`/`ANTI`
  joins, mixed-type compound sort keys, first-batch grouped aggregation fallback, Top-N spill sort
  keys, and ordered running `RANGE` window spills now produce correct results. Recheck any scripts
  that depended on the previous behavior.

## Deprecations

Removed and changed behaviors are recorded above and in [BREAKING_CHANGES.md](../../BREAKING_CHANGES.md).
No additional removal timeline is announced in this release.

## Highlights

### Windows MSI: services own their configuration

**Audience:** Administrators

In earlier releases, MSI upgrades relied on PowerShell and JScript custom actions to merge settings,
generate secrets, and force-close processes, which complicated upgrades and could disrupt unrelated
programs. In v0.23.0, the MSI only copies files and registers, starts, and stops the Windows
services through `ServiceControl`.

The release defaults ship in `appsettings.defaults.json`. The services keep operator overrides in
`appsettings.json`, migrate secrets into `appsettings.secrets.json`, and create
`first-run-password.txt` on a fresh install.

> **Design context:** [Services Own Their Configuration](v0.23.0-mi01-services-own-configuration-design.md)
> and [Windows installation](../administration/platform/installation.md#windows).

### Unified memory coordinator and 100M-row spill performance

**Audience:** Administrators · Script Authors

Large multi-operator pipelines previously tracked memory in separate pools, boxed decimal values as
strings in Arrow spills, and suffered hash-chain collisions in partitioned external joins. v0.23.0
consolidates production memory grants into one byte-budgeted coordinator with live host/container
headroom, byte-bounded Top-N, window peers, and inter-stage queues, and adds single-pass framed
`ETLSPL03` AES-256-GCM spill encryption with adaptive compression.

Projection pruning, alias-preserving Arrow metadata, bounded dictionary encoding, 16-byte binary
decimal spills, zero-copy `ColumnBatch` handoff, and Fibonacci-mixed hash-join buckets reduced
allocations and wall time in the hosted 100M-row fixtures. [Performance](#performance)

> **Design context:** [Framed Spill Encryption (ETLSPL03)](../architecture/decisions/framed-spill-encryption-etlspl03.md)
> and [Resource Governance](../administration/orchestration/resource-governance.md).

### Data preparation (`TRANSFORM`) reliability and analyst operations

**Audience:** Script Authors

`TRANSFORM` now preserves `NULL` semantics, output column data types, table/column lineage, LSP
scope discovery, and `SET WHAT_IF ON` safety across all algorithms, and supports in-place
`TRANSFORM #target USING ...` without repeating `FROM`.

Eight new analyst operations ship alongside shared scalar functions `CLEAN_TEXT` and `STANDARDIZE`:
`CLEAN`, `UNPIVOT` (`MELT`), `BIN` (`BUCKETIZE`), `OUTLIERS`, `IMPUTE`, `SPLIT` (`EXPLODE`),
`MASK_PII`, and `SCD2`, plus multi-column `INTERPOLATE`/`NORMALIZE`, `FILL_DATES` intervals, and
`DEDUPLICATE` `REJECT_INTO` quarantine routing.

```sql
TRANSFORM #customers USING CLEAN (COLS = 'Email,Phone', RULES = 'TRIM,LOWER');
TRANSFORM #customers USING MASK_PII (COLS = 'Email', METHOD = 'REDACT_EMAIL');
```

> **Reference:** [TRANSFORM statement](../reference/statements/dml/transform.md).

### Portal, Studio, and Orchestrator unification

**Audience:** Administrators · Report Consumers · Script Authors

Studio catalog pipelines (`PIPELINE:{id}`) now provision directly into Orchestrator job slots with
one-click **Provision & Grant EXECUTE**, **Open in Studio ↗** navigation, and read-only script
protection against accidental out-of-band edits. `CatalogOnly` mode and `ScriptIngress` enforce
governed script ingress across both Orchestrator jobs and report publishing.

The Portal retires direct SQLite access to Orchestrator databases in favor of bridge APIs and
federated `SHARED:` connections/`SECRET:` sync, scopes Orchestrator bundles by tenant, and adds
Edit Job metadata, schedule/notification ACLs, per-run execution waterfalls, parameterized runs,
`Cancel`/`Kill` actions, a Nodes & Sandboxes fleet health tab, and `ORCHESTRATOR` connector parity.

### Database, Excel, archive, and remote file-tree operations

**Audience:** Script Authors

- **Database connectors:** `MSSQL` adds Microsoft Entra ID `AUTH_MODE` (`ENTRA_DEFAULT`,
  `ENTRA_MANAGED_IDENTITY`, `ENTRA_SERVICE_PRINCIPAL`); `POSTGRES` adds `SEARCH_PATH`; `SNOWFLAKE`
  adds `ROLE` and `PRIVATE_KEY_PASSPHRASE`; `MONGODB` adds read-only JSON `EXECUTE` filter/pipeline
  pass-through and `KEY_COLUMNS` BulkWrite upserts; `SQLITE` adds `JOURNAL_MODE` and
  `BUSY_TIMEOUT_MS`.
- **Multi-sheet Excel:** `xl_conn.<SheetName>` routes reads and writes to named worksheets while
  preserving other sheets in existing `.xlsx` workbooks (`OVERWRITE_WORKBOOK` opt-out), plus
  `START_ROW`, `SHEET_INDEX`, `EXCEL_SHEET_LIST`, and `xl_conn._sheets`.
- **Archives & detached signatures:** `COMPRESS`/`DECOMPRESS` add `.gz`, `.tar`, and `.tar.gz`
  (`.tgz`), selective `PATTERN` extraction, optional `TO` defaults, and `ARCHIVE_LIST`. New
  `SIGN FILE` and `VERIFY FILE SIGNATURE` statements provide detached OpenPGP signing via PgpCore.
- **Remote file trees:** Remote connections add file and directory copy, recursive listing and
  download, and local-to-remote and remote-to-local directory sync. SFTP and FTP support remote
  directory rename and move. `VERIFY = ON` checks transfer size and compares a checksum when the
  provider exposes one that ETL-SQL supports. [Remote file operations](../reference/file-operations/README.md)

```sql
RECEIVE FILE FROM '/exports/*.csv.gz' TO './inbox/' AT sftp_conn
WITH (RECURSIVE = ON, VERIFY = ON);
```

## Improvements

### Language & Engine
- Added local file and path functions `PATH_ROOT`, `PATH_IS_ABSOLUTE`, `FILE_READONLY`,
  `FILE_ACCESSED`, `DIRECTORY_SIZE`, and `DIRECTORY_FILE_COUNT`.
- Added `eng.datasets` to list datasets visible to the caller and pointed the retired
  `SHOW DATASETS` message at it.
- Added a native binary column buffer and Arrow binary spill support for `VARBINARY`/`HASHBYTES`,
  formatting binary values as `0x…` hex in CLI tables, JSON results, and text casts.
- Enabled `TO DIRECTORY` for `ENCRYPT FILE`, `DECRYPT FILE`, `COMPRESS FILE`, and
  `DECOMPRESS FILE`.
- Separated native `EXECUTABLE` tool `WORKING_DIR`, approved `SCRIPT_PATH`, and disposable per-run
  scratch directories, with quoted `ARGS` tokenization preserving paths with spaces.
- Added host-wide capacity admission (CPU, spill-volume free space, and aggregate worker memory
  reservations) and priority-FIFO short-job slots under heavy spilling.

### Reporting & Visualization
- Expanded `CUSTOM ... CHART` Grammar-of-Graphics parity: continuous `TEMPORAL` axes, analytical
  `OVERLAYS`, `CONDITIONS` on categorical/temporal/uninterpolated `LINE`/`AREA` with
  `LINE_DASH`/`SEGMENT_STYLE`, `COLOR = DATUM(...)` legends, data-driven `OPACITY`, discrete color
  `RANGE` mappings, `LOG`/`IDENTITY` scales, 2D grid facets, exact least-squares
  `EXPONENTIAL`/`LOGARITHMIC`/`POWER` overlays, explicit `SERIES` overlay ownership, and Studio
  inspector, cross-filter, hover-popover, and `DRILL_IN` parity.
- Fitted `US_STATES` maps now fit geometry automatically when `ZOOM`/`CENTER` are omitted and
  render Alaska, Hawaii, and Puerto Rico as insets.
- Added `ETL-SQL-Report build --strict` (exits 3 on any failed visual while still writing the
  report) and report polish (icon maximize button, clean headers when owner is absent, clear
  offline slicer notice).

### VS Code Extension & Documentation
- Added the VS Code Get Started walkthrough (`etlsql.getStarted`) and fixed Connection Wizard
  narrow-panel layout and spacing.
- Updated the Quickstart to start in VS Code, made 13 ETL recipes and all report recipes runnable
  as-is on `MOCKDB` (verified in CI), and added a rendered report gallery to the README.
- Reconciled all ten database connector pages against live option allowlists, added the database
  capability matrix, write-path/transaction reference, native-to-engine type-mapping reference,
  write-time encryption/compression docs across all six file connectors, and source-specific
  incremental watermark recipes for SQL Server, PostgreSQL, and Oracle.

### Release & CI Engineering
- Added the always-running `Merge Gate` CI aggregator, PR regression lane routing for ordinary
  engine/language-server/portal tests, Dependabot coverage for all script npm projects, and
  commit-SHA pinning for third-party GitHub Actions.
- Redesigned performance certification to gate correctness, exact work counters, and allocations
  (+5%) against hosted baselines, with paired A/B elapsed-time gating at release.

## Performance

Hosted 100M-row Scale Measurement ran on `ubuntu-latest` with 4096/2048 MB grants. Result checksums
matched the v0.22.0 baseline.

| Operation (100M rows) | Elapsed time | Allocated | GC pause |
| :--- | :--- | :--- | :--- |
| External Sort | 1,249 s → 483 s (−61%) | 593 GB → 154 GB (−74%) | 177 s → 112 s |
| External Window | 1,227 s → 266 s (−78%) | 621 GB → 113 GB (−82%) | 170 s → 33 s |
| External Join | 896 s → 266 s (−70%) | 335 GB → 106 GB (−68%) | 337 s → 32 s |

Additional measured engine improvements:

- **Encrypted spill compression (`Adaptive` default):** `CompressionLevel.Fastest` writes 100k
  compressible rows in 0.72× wall time and 0.73× CPU time compared to `Optimal`, selected
  automatically under CPU pressure or concurrent spill writers.
- **Bounded Arrow dictionary encoding:** 0.24× encrypted-compressed spill bytes and ~1.7× faster
  write/read on 100k low-cardinality rows.

## Security

- **Process-spawned caller identity:** Process-spawned Orchestrator runs sign single-use
  HMAC-SHA256 caller identity envelopes with a per-run key (cleared before script execution) and
  strip `Orchestrator:IdentitySigningSecret` from child environments so scripts cannot forge
  identity assertions.
- **Snapshot & Orchestrator `SHARED:` ACLs:** Orchestrator runs bind an explicit owning
  `ExecutionIdentity`, and Portal report snapshots record and re-check `SHARED:` connection `Use`
  permissions on every read, export, and designer request.
- **Tenant-scoped bundles & fleet view:** Orchestrator bundle storage, resolution, and retention
  are scoped by `tenant_id`, legacy unassigned-bundle endpoints require administrator rights, and
  `GET /api/fleet/nodes-sandboxes` redacts node hostnames/PIDs/capacity and scopes sandbox counts
  for tenant-bound readers.
- **Vault & spill hardening:** Local vault directories receive restrictive ACLs before writing;
  `ETLSPL03` frames spill encryption with `AES-256-GCM` and per-frame AAD; plaintext buffers in
  `RowPacker`, join/distinct tables, and spill writers are zeroed on disposal.
- **Path & mount guardrails:** Local directory functions skip symlinks and junctions; recursive
  remote `RECEIVE FILE` refuses traversal paths resolving outside the target folder; sandbox
  writable mounts use group-restricted permissions (`2770`) on Unix hosts.
- **Strict encryption & remote guards:** Unrecognized `ENCRYPT` values are rejected; file
  encryption/compression statements refuse remote connections; `SNOWFLAKE` quotes connection-string
  secrets containing `;` or `=`.

See [BREAKING_CHANGES.md](../../BREAKING_CHANGES.md) and [SECURITY.md](../../SECURITY.md) for
affected boundaries and migration steps.

## Bug fixes

- **PostgreSQL `COPY` writes:** Escaped backslashes, tabs, newlines, and literal `\N` in text
  `COPY`, encoded `bytea` as hex, cancelled `COPY` on mid-load failure so no partial rows commit,
  and surfaced `COPY` line and column on server-side errors.
- **SharePoint & Excel connectors:** Fixed `SHAREPOINT` paths containing apostrophes and
  culture-invariant UTC `TimeCreated`; `EXCEL` now fails closed on unreadable workbooks and
  preserves existing first-sheet names when `SHEET` is omitted.
- **Engine & SQL execution:** Fixed `EXECUTE proc @var OUTPUT` parameter writeback,
  `DECLARE @x LIST = (SELECT ...)` keeping only the first row, `ERROR_MESSAGE()` including the
  console prefix after `RAISERROR`, `SELECT *` on empty `#temp` tables/CTEs losing column headers,
  `Connectors:Retry` config being ignored, detached job schedules continuing to fire hourly,
  `PARALLEL` message-list modification races, concurrent in-process job session ID collisions, and
  six spill edge cases (`HAVING COUNT(*)`, `ORDER BY` after spill, spilled `PIVOT` `AGG_*` columns,
  text-key space trimming, `MERGE` duplicates, and `INSERT OR REPLACE` false unique violations).
- **CLI & Orchestrator:** Disabled response-file parsing so `--var @Name=Value` works on CLI and
  scheduled Orchestrator runs; fixed Studio practice runs on sandboxed Orchestrators running as the
  pipeline owner instead of the submitting learner.
- **Reporting & TUI:** Fixed `US_STATES` maps failing on an Aleutian ring at -187° longitude,
  Sankey last-column labels clipping, terminal charts reporting "not currently supported" on empty
  data, and `PlotPlanTerminalRenderer` pie `Other` slice totals.

## Known issues and certification limits

- **Allocation noise in scale harness:** Smoke join/aggregate allocations vary by ~2–3 MB between
  runs (can trigger the 2% warning, not the 5% failure gate), and Standard cube allocation is
  bimodal per sample (~1,150 or ~2,010 MB).
- **Certification scope:** Release Evidence covers the declared deployment fixtures, including a
  Compose HA soak, service capacity fixtures, and a billion-row memory-flatness test. Shared SaaS
  containment and hosted production remain outside the release claims. [Release checklist](release-checklist.md#certification-schedule-and-evidence-ledger)

## Upgrade guide

Upgrades are supported from **v0.22.0**.

1. Review [BREAKING_CHANGES.md](../../BREAKING_CHANGES.md) and the
   [migration guide](../guides/onboarding/migration-guide.md) against your scripts, Portal roles,
   and service configuration.
2. Back up configuration, databases, and keys before changing an installation:
   ```powershell
   etl-sql admin backup --output-dir '<backup-dir>'
   ```
3. **Windows MSI upgrades:**
   - Install `ETL-SQL-v0.23.0-x64-Setup.msi` over v0.22.0. The installer preserves your
     `appsettings.json` and `appsettings.secrets.json` and writes new release defaults to
     `appsettings.defaults.json`.
   - On first start after upgrade, the services strip values in `appsettings.json` that matched
     v0.22.0 defaults once, leaving only your overrides. Do not edit `appsettings.defaults.json`.
   - Remove any operator scripts that called the removed `configure-portal-jwt.ps1`.
   - For an in-place restore, supply the matched data and keys archives and the existing installation
     directory. [Backup and monitoring](../administration/platform/backup-and-monitoring.md)
     ```powershell
     etl-sql admin restore --from '<data-archive>' --keys '<keys-archive>' --to '<install-dir>' --in-place
     ```
4. **Portal & Orchestrator upgrades:**
   - Grant `ScriptIngress` to any roles or groups that publish reports by script path or
     `PUBLISH REPORT` in `SourceControlled` Studio mode.
   - Verify Studio read permissions for users who provision Orchestrator jobs from Studio pipelines.
   - Refresh existing cached report snapshots that use `SHARED:` connections so runtime connection
     dependencies are recorded, and verify readers hold `Use` permission on those connections.
   - Re-synchronize any remote Orchestrator Gateway connections previously exported without their
     Gateway binding.
5. **Script checks:**
   - Add `WITH (RECURSIVE = ON)` to any `DELETE DIRECTORY ... AT conn` targeting non-empty folders.
   - Split any `ENCRYPT`/`DECRYPT`/`COMPRESS`/`DECOMPRESS` targeting a remote connection into a
     local operation followed by `SEND FILE` / `RECEIVE FILE`.
   - Verify `CREATE JOB` scripts attach a schedule where recurring execution is intended, and remove
     `USER`/`PASSWORD` from `MSSQL` connections that set `TRUSTED_CONNECTION=TRUE`.
6. Validate in a disposable installation first, then follow the
   [installation guide](../administration/platform/installation.md) and verify service health,
   authentication, and a representative script and report.
