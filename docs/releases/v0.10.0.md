# ETL-SQL v0.10.0

**Released:** 2026-06-08

Introducing **Specification-Driven Development (Beta)**, a complete modernization of the **Terminal IDE (TUI)**, a native **Neo4j** connector, and **Orchestrator API key protection**.

---

## Release Summary

v0.10.0 accelerates pipeline authoring and enhances console usability. With **Specification-Driven Development**, developers can use the new `gen-script` and `extract-spec` CLI utilities to convert standardized JSON schemas and vendor PDF data dictionaries directly into validated ETL-SQL templates. The **Terminal IDE (TUI)** receives a comprehensive overhaul, adding tabbed multi-file editing, a collapsible sidebar file explorer, async background query execution, variables/schema explorers, and built-in braille/fractional charting. Security is hardened by enforcing OIDC-aligned `X-Orchestrator-Key` header validation on non-loopback Orchestrator ad-hoc API endpoints.

---

## ⚠️ Breaking Changes & Required Actions

- **`X-Orchestrator-Key` required on Orchestrator ad-hoc APIs:** Ad-hoc job endpoints (`POST /jobs`, `DELETE /jobs/{id}`, `GET /jobs/{id}`) now require the `X-Orchestrator-Key` header when bound to a non-loopback address. Standalone runner scripts must update their API requests to include this key.
- **REST Egress redirect behavior:** The REST connector no longer follows automatic HTTP redirects. Redirects are now followed explicitly up to a bounded count, and every hop's host is re-validated against the egress allowlist.

---

## ⏳ Deprecations

- **`WITH PARAMETERS` report options:** The legacy report option syntax is deprecated. Use visual mappings and parameter sets within report definitions instead.

## Highlights

### Specification-Driven Development (Beta)

**Audience:** Script Authors · Evaluators

**Problem:** Integrating external vendor feeds requires manual translation of data dictionaries, column mapping, safe casting, and validation routines — an error-prone and tedious bootstrapping phase.

**Solution:** A pipeline template generation utility that compiles standard JSON specification contracts directly into ETL-SQL starter scripts:
- **`gen-script` CLI:** Generates structured template files including source schema validation (`EXPECT SCHEMA`), confidence ratings, casting logic, and quarantine table generation.
- **`extract-spec` CLI:** Utilizes PDFsharp and a heuristic keyword scoring algorithm to parse data dictionaries from vendor PDF documents, outputting structured JSON contracts.
- **Runnable Recipes:** Added a complete customer-feed generation recipe (Cookbook recipe 25) with validation schemas.

```powershell
# Extract data dictionary from a vendor PDF
etl-sql extract-spec --pdf "vendor_docs.pdf" --output "spec.json"

# Compile spec contract into an ETL-SQL starter template
etl-sql gen-script --spec "spec.json" --output "ingest_vendor.etlsql"
```

---

### Terminal IDE (TUI) Modernization

**Audience:** Script Authors

**Problem:** The initial console editor was limited to single-file buffers, blocked during query execution, and lacked schema/variables discovery context, forcing developers to switch between CLI shells and editors.

**Solution:** A fully-featured terminal development workspace running in Kestrel/console modes:
- **Navigation & Tabs:** Collapsible sidebar explorer tree, tabbed multi-file editing, and customizable JSON themes.
- **Advanced Editing:** Multi-cursor editing, drag-to-select, F1 shortcuts, and F3/Shift+F3 find/search navigation.
- **Live Gutter Diagnostics:** Inline syntax warnings and compiler errors display directly in the editor margin.
- **Explorers:** Asynchronous lazy-loaded Database Schema Explorer and a Variables Explorer matching VS Code's view.
- **Asynchronous Runs:** Background non-blocking execution with a Command Palette (`Alt+P`) and cell-popup result inspection.
- **Terminal Visualization:** Renders braille-based line charts and fractional-block bar charts.
- **Local Server (`serve`):** Press `Ctrl+Shift+R` to serve live browser report previews instantly.

---

### Native Neo4j Graph Database Connector

**Audience:** Script Authors

**Problem:** Moving data from relational systems or flat files into graph databases required external pipelines or complex Python helper libraries.

**Solution:** A native `Neo4j` connector supporting node/edge creation, Cypher executions, key merging, and metadata checks.

```sql
CREATE CONNECTION graph AS NEO4J(
  URI = 'bolt://localhost:7687',
  USER = 'neo4j',
  PASSWORD = 'SECRET:neo4j_password'
);
```

-- Write nodes directly using native Cypher
```cypher
EXECUTE graph BEGIN
  UNWIND $batch AS row
  MERGE (c:Customer {Id: row.CustomerId})
  SET c.Name = row.CustomerName
END;
```

## Improvements

### Language & Engine
- Added `CREATE TAG` and `CREATE LINEAGE FROM ...` syntax for importing curated lineage tags.
- Added `DIFFERENCE(s1, s2)` Soundex similarity scoring string function.
- Expanded SQL Logic Test (SLT) coverage for `LEFT SEMI`/`LEFT ANTI` joins, index creation, table truncations, and `QUALIFY` statements.
- Tolerated trailing semicolons (`;`) inside statements inside `BEGIN`/`TRY` blocks.

### Portal & Visualization
- Added subscription delivery diagnostics UI and preserved subscription failure codes in the orchestrator history store.
- Added page navigation arrows to Report Player.

### VS Code Extension & IDE
- Restored temp table querying inside the TUI autocompletion manager.
- Scaffolding templates and schema JSON files added to improve editor code intelligence.

### Connectors
- Enhanced S3, Azure Blob, SFTP, and local Directory connectors to support fallback decryption and structured path parsing.

## Performance

- **Low-overhead TUI rendering** — `EditorRenderer` caches frame metadata, making status bar and key-binding redraws allocation-free on unchanged frames.
- **`etl-sql purge` CLI** — Added a cross-platform command to purge stale sessions, log histories, and temp files.

---

## Security

- **Orchestrator Key Lock:** Enforced `X-Orchestrator-Key` validation on non-loopback interfaces. The service refuses to bind to non-loopback addresses if an API key is missing.
- **Spec Traversal Prevention:** Restricted spec-generated dataset names to a strict safe-identifier format, preventing path traversal in output scripts.
- **SSRF Hardening:** Disabled automatic redirects in the REST connector, stripped authorization headers on cross-host hops, and normalized IP address ranges to block loopback/link-local SSRF attempts.

## Upgrade Guide

Standard upgrade — replace binaries and restart services.

If your Orchestrator binds to a non-loopback interface (e.g. `0.0.0.0`), ensure you configure `Orchestrator:ApiKey` and supply the matching header `X-Orchestrator-Key` on all remote HTTP client calls.
