# ETL-SQL v0.16.0

**Released:** 2026-07-19

v0.16.0 turns enterprise security into something you can *watch*: a vendor-neutral security-event
stream that flows to Splunk, Elastic, or Sentinel, backed by a durable local outbox that keeps
delivering across restarts and never blocks enforcement.

---

## Release Summary

This release makes ETL-SQL observable to a SOC. Every host now emits a versioned, correlated
**security-event** stream — policy denials, override attempts, enrollment changes, lifecycle
failures, and resource-limit violations — delivered over an acknowledgement-based channel with a
bounded, crash-safe outbox and ready-made Splunk CIM / Elastic ECS / Microsoft Sentinel ASIM field
mappings. Alongside the security work, the connector layer was split into independently deployable
projects so a host no longer drags in every database and cloud dependency, flat-file ingestion gained
**schema-resilient** modes that ride out upstream column drift, and the Portal report editor gained an
in-designer preview pane. The documentation set was reorganized end-to-end around single-responsibility
sections.

---

## ⚠️ Breaking Changes & Required Actions

- None in this release. Existing scripts, connections, and deployments run unchanged. The new
  security-event transport is **opt-in** — an unenrolled standalone install starts with no enterprise
  HTTP clients or remote collector and unrestricted local workflows.

## Highlights

### Central Security Events

**Audience:** Administrators · Evaluators

Enterprises could enforce policy but couldn't *see* it: there was no first-class, machine-readable
record of what security decisions each host was making, and no reliable way to get those records into
a SIEM. v0.16.0 adds a versioned, vendor-neutral **security-event contract** covering policy denials,
lifecycle failures, override attempts, enrollment changes, and resource-limit violations — correlated
across every host (Portal, Orchestrator, CLI, TUI, Report Player, Report Builder, Language Server,
scheduled jobs, and spawned runners).

Events are written to a **bounded, durable local outbox** and delivered over acknowledgement-based
HTTPS using the host's enrolled machine identity, with signed-policy severity filtering, bootstrap
OS/file sinks, delivery diagnostics, and optional fail-closed health thresholds. Enforcement is
independent of monitoring: if the collector is unreachable, the outbox retains events and delivers
them later — it never blocks a policy decision. Log-forging characters are stripped and connector
aliases are canonicalized before enforcement so events can't be spoofed.

The collector protocol ships with example field mappings for **Splunk CIM**, **Elastic ECS**, and
**Microsoft Sentinel ASIM**.

> **Design context:** [Security Events](../administration/platform/security-events.md) ·
> [Enterprise Security Review Packet](../architecture/decisions/enterprise-security-review-packet.md)

### Schema-resilient flat files

**Audience:** Script Authors · Administrators

A single new or missing column in a partner CSV used to fail the whole load. Flat-file (CSV/Excel)
ingestion now has explicit **schema-resilient** modes so upstream drift is a diagnostic, not an outage:
align by header name, ignore surplus source columns, and null-fill columns the source dropped.

```sql
-- Ride out an upstream partner feed that adds or drops columns
CREATE CONNECTION partner_feed AS FLATFILE(
    PATH        = 'C:\Data\partner_feed.csv',
    HEADER      = ON,
    MAP_BY_HEADER_NAME   = ON,   -- align by case-insensitive header, not position
    IGNORE_EXTRA_COLUMNS = ON,   -- drop columns not in the destination schema
    NULL_MISSING_COLUMNS = ON);  -- NULL-fill destination columns the source omits
```

When resilience changes the accepted shape, the connector emits a diagnostic with the ignored
extra-column count, null-filled missing-column count, and affected row count, so silent data loss is
visible.

> **Design context:** [Flat File connector reference](../reference/connectors/files/flatfile.md)

### Portal report editor: in-designer preview

**Audience:** Report Consumers · Script Authors

Previewing a report meant leaving the editor to run a separate serve command. The standalone script
editor now renders an **in-designer preview pane** — no serve step — and **Save** is now separate from
**Git commit**, each with its own action, so saving a draft no longer forces a commit.

> **Design context:** [Portal Editor Strategy](../architecture/decisions/portal-editor-strategy.md)

## Improvements

### Language & Engine
- Data-source reads now observe cancellation through dedicated hooks, so cancelled or timed-out jobs
  unwind promptly instead of finishing source and schema work.

### Portal & Visualization
- Thinned the Portal report controllers by extracting `ReportScriptInspectionService`,
  `ReportDependencyService`, and `ReportStructureService` from `ReportsController`; report-parameter
  parsing, dependency resolution, and structure/AST work now live in application services.
- Portal user lists are read through the paged API, returning complete results for large directories.

### Connectors
- Split the connector implementations into independently deployable projects —
  `ETL-SQL.Connectors.Common` (shared helpers) and `ETL-SQL.Connectors.Files` — and decoupled
  `ConnectionStringBuilder` from the database drivers, so a host loads only the connectors it uses
  instead of every database, cloud, messaging, and native dependency.

### Documentation & Project Structure
- Reorganized the documentation tree around single-responsibility sections (`guides/`, `reference/`,
  `architecture/`, `administration/`, `releases/`) with thin guide hubs and a task index; embedded
  runtime-help filenames were preserved so in-app help keeps resolving.
- Added architecture boundary tests that enforce the documented source-tier layering: a new upward
  project reference or a banned cross-layer package now fails CI.

---

## Performance

- **Portal storage sampling is now bounded** — usage reporting no longer scans large stores unboundedly.
- **Portal user-role lookups are batched** — listing users no longer issues a round trip per user.

---

## Security

- Canonicalized connector aliases before policy enforcement and stripped log-forging characters from
  emitted security events, closing spoofing and log-injection vectors.
- Corrected the Docker security-event outbox startup path so containerized hosts initialize delivery
  reliably.
- Serialized enterprise policy initialization and ignore stale policy notifications so runtime
  configuration and security-event transport cannot regress during concurrent refreshes; disposed
  configuration roots release their policy subscriptions.
- Resolved the security and release findings raised in the v0.16.0 sprint code review.

---

## Bug Fixes

- Cancellation now propagates through warehouse and data-source schema resolution — cancelled jobs stop
  promptly instead of completing schema work.
- Docker container builds restore every connector assembly now that the split connector projects are
  included in the restore set.
- Restored true Release builds for `ETL-SQL.Analysis`, redacted fatal CLI/TUI startup exceptions, and
  passed report-launch arguments without string concatenation.
- Restored the repository format gate by correcting import ordering in enterprise security and
  fleet-policy files.

## Upgrade Guide

Standard upgrade — replace binaries and restart services. No configuration changes required.

The security-event transport is opt-in and off until enrollment configures a collector, so existing
standalone and local deployments are unaffected. To adopt it, follow
[Security Events](../administration/platform/security-events.md) to point hosts at your collector and
choose a severity threshold.
