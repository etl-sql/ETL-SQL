# ETL-SQL v0.21.0

**Released:** 2026-10-18

Portal Studio runs and schedules pipelines, keeps private drafts, and serves row-level-secured
reports to each reader; installed Portal and Orchestrator services now start, upgrade and keep
their secrets private.

---

## Release Summary

v0.21.0 makes Portal Studio a place to finish work, not only start it. A pipeline saved in the
Portal runs and is scheduled through the Orchestrator under the author's own identity, including on
a sandboxed Orchestrator. Unpublished work is kept as a private draft, and a report that filters
rows by the viewer opens live for each reader. The release also fixes the installed packages: an
MSI or DEB Portal now starts without hand-edited configuration, upgrades keep the installed
settings, and service secrets are readable only by the service account and administrators.

---

## ⚠️ Breaking Changes & Required Actions

The complete behavior changes and migration actions are in
[BREAKING_CHANGES.md](../../BREAKING_CHANGES.md). Review these before upgrading:

| Affected work | Required action |
| :--- | :--- |
| Portal and Orchestrator databases | **Back up both databases before upgrading.** The first v0.21.0 start renames tables and columns to snake_case, and v0.20.x cannot open the renamed database: rolling back means restoring that backup with the previous release. Update direct SQL, reports and tools to the [snake_case names](../architecture/standards/database-schema-standards.md). |
| `ENC:` values and session checkpoints | The default machine key is now random per installation. Mount a key with `ETLSQL_MACHINE_KEY_FILE` or keep local application data on persistent storage, then re-enter and re-encrypt values written under the old key. |
| `GENERATE JWT_SECRET` | Read the `Secret` column of the returned row; the secret is no longer written to the log. |
| Reports with `RUN SCRIPT` | Expect live, per-viewer execution instead of a shared snapshot. Keep a report self-contained when a shared snapshot is required. |
| BigQuery streaming writes | Reconcile destination rows after an ambiguous failure before resubmitting; inserts are no longer replayed. |
| ODBC and Snowflake table views | Commit or roll back through the transactional source; disposing a view no longer rolls back its owner. |
| Unique constraints on nullable columns | Add `NOT NULL` where NULLs must be rejected; repeated NULL keys no longer collide in the fallback scan. |
| Spilled decimals | Remove workarounds for nine-place rounding; spilled decimals keep their value and scale. |
| Dataset viewer API | Use the `is_null` filter to select null cells; numeric comparisons exclude them. Read text cells and distinct values as strings, not character arrays. |
| Studio documents above the host limit | Shorten the document below the displayed limit to resume automatic analysis, completion and hover. Text is never truncated. |
| Studio after an editor load failure | Type in basic mode or retry the editor load; visual and helper writes are refused until then. |
| Studio helper previews | Use the SQLite read-only fixture for native previews and the authorized pipeline path for writes. |
| Multi-tenant schedulers | Restore lease-store availability before retrying a refused occurrence; keep scheduler versions aligned when sharing a job store. |

## Highlights

### Run and schedule a Portal pipeline

**Audience:** Script Authors · Administrators

A pipeline authored in Portal Studio could be saved but not run from the Portal. **Run** now submits
the saved revision to the pipeline's Orchestrator job, `PIPELINE:{id}`, under the author's own
identity. Studio shows that run's status and bounded statement log by run ID, and **Stop** cancels
it. Nothing executes inside the Portal, unsaved edits are refused, and a missing Orchestrator, job
or `EXECUTE` grant each says so. The governance rail pins a saved revision and attaches a cron
schedule, which keeps running the pinned revision until it is set again.

On a sandboxed Orchestrator the run carries the submitter's identity into the worker, which fails
closed when it is missing or does not match. The Portal practice exercise passed on a real
Standard (runc) sandbox; hardened (gVisor) isolation is not part of that evidence.

> **Design context:** [Portal ETL documents](../architecture/decisions/portal-etl-documents.md) ·
> [Sandbox submitter identity](../architecture/decisions/studio-sandbox-submitter-identity.md)

### Private drafts in Portal Studio

**Audience:** Script Authors · Report Authors

Saving a new document without publish rights used to answer "Not Saved", leaving the work only in
the browser tab. **Save** now keeps it as a private draft that only its owner can open, listed
under **My Private Drafts** on Studio Home. Each save is versioned, a save from a stale copy is
refused, and unsaved edits are offered back after a browser crash or renewed sign-in. **Publish**
moves the draft into the catalog through the normal create checks.

```json
"Portal": { "Studio": { "PrivateDrafts": true, "PrivateDraftRetentionDays": 90, "PrivateDraftRevisionsKept": 10, "PrivateDraftsPerUser": 25 } }
```

> **Design context:** [Private draft policy](../architecture/decisions/studio-private-drafts.md)

### Row-level-secured reports open live for each reader

**Audience:** Report Consumers · Report Authors

A report that filters rows by the viewer keeps no shared snapshot, so a reader who opened one was
returned to "Ready for first run". These reports now open live, labelled **Live · your rows**:
each reader's rows are produced under their own identity and nothing is stored. Filters, saved
views, export and **Subscribe** work from that result, and a delivery runs once per recipient under
each identity.

### Installed Portal and Orchestrator services that start and upgrade

**Audience:** Administrators

No installed Portal had started without hand-edited configuration since v0.11.0. The MSI and DEB now
generate the dataset at-rest key, identity signing secret and a one-time administrator password,
and Linux services start under systemd-managed state and cache directories. Upgrades carry the
installed configuration forward and add only keys new in the release. Generated secrets live in
`appsettings.secrets.json`, readable only by the service account and root (`640 root:etlsql`) or by
Administrators and SYSTEM. Certified on DEB: a fresh install, an upgrade from v0.20.0 with cache
revalidation, and rollback from backup. The MSI Portal-profile certification runs in CI on the
release candidate.

## Improvements

### Studio

- Move and resize a report visual with the keyboard; each change is announced, and a step off the
  grid is refused and said so.
- Studio Home searches and pages the Portal catalog; deleted or moved selections explain why they
  cannot open.
- Studio pauses automatic editor services above the host's document limit while keeping every
  character editable.
- Run IDs are kept, a lost execution response reports an unknown outcome, and results stay with the
  document that ran.
- Export, import and promote catalog pipelines with the Portal configuration
  (`PUBLISH REPORT … WITH (KIND = 'PIPELINE')`).

### Portal & Orchestrator

- The Orchestrator page's metric chips filter, search and page server-side, counting only readable
  jobs; a tenant-scoped activity API backs them.
- New Orchestrator routes run submitted text once through a job and address runs by ID
  (`POST /api/scheduled-jobs/{name}/runs`, `GET /api/job-runs/{id}`, `POST /api/job-runs/{id}/cancel`).
- Every Portal page and shared module is compiled from strict TypeScript against contracts generated
  from C#, and pages report unavailable sources instead of empty results.

### Build & packaging

- Generated browser JavaScript left source control. A fresh clone runs
  `npm ci --prefix scripts/typecheck` and `node scripts/sync-assets.js` before its first build;
  published products still need no Node.js.
- Builds that skip compilation refuse binaries prepared from older browser assets.

### Connectors

- FTP calls are asynchronous and cancellable; Avro uses one background task per batch; JSON, XML and
  Excel output stream to disk.

## Performance

- A spilled `ORDER BY` stays a stream through `OFFSET`/`LIMIT`, projection and `TOP … PERCENT`
  instead of collecting sorted rows into memory again.
- Orchestrator job, schedule and notification lists make one grant lookup per page instead of one
  per row.
- No new benchmarked throughput claim is made. Scale baselines are re-measured on the final
  candidate by the release gate.

---

## Security

- Installed service secrets moved out of the world-readable `appsettings.json` into the protected
  `appsettings.secrets.json`; anyone who could read the old file could forge Portal sign-ins.
- DEB maintainer scripts no longer follow links in folders the service account owns.
- `/management/stop` requires an administrator where federated identity is required, and the Portal
  limits stopping the Orchestrator to administrators.
- The report runtime strips script-capable content from chart SVG before adding it to the page.
- `System.Security.Cryptography.Pkcs` updated to 10.0.13 for CVE-2026-84008 and CVE-2026-70162.
- The default machine key is random per installation instead of a digest of the host and account.

---

## Bug Fixes

- A scalar subquery is read again after the data it reads changes; it had answered from its first
  evaluation for the rest of the script.
- Spilled decimals keep their precision and scale instead of rounding to nine places.
- A job run's statement log names the statement that failed, not the one before it.
- A job keeps the interval it was created with; the Orchestrator had stored every Portal-created
  job as hourly.
- An overloaded Orchestrator node refuses a manual trigger with `503` and `Retry-After` instead of
  answering "queued" and dropping the run.
- The Portal starts on PostgreSQL after the snake_case schema migration.
- The workstation MSI installs the Desktop Player's report runtime.
- Dozens of Portal and Orchestrator page controls that existed but never worked end to end now do,
  including the job Access panel, "Save script", "Unowned objects" and bundle-job creation. The
  [changelog](../../CHANGELOG.md#0210--2026-10-18) lists each one.

## Known Issues

- Pipeline cancellation signals only the executing node, and kill-by-job-name still records
  `FAILURE`. Pipeline schedules must be recreated at a promotion target.
- Sandbox submission is evidenced on Standard (runc) isolation only.
- The Snowflake table-view transaction fix is verified with a recording transaction; a live row
  rollback against Snowflake has not been run.
- Private drafts expire when read or listed, without a background sweep; recovery does not persist
  offline edits.
- Row-level-secured reports do not appear under Popular or Recently viewed, and detection through an
  included script is unchecked.
- Screen-reader passes for Studio have not been run; keyboard and zoom journeys are certified.
- Learner understanding of Studio has not been observed, so no learner-validated claim is made.
- The Smoke scale certification fails its baseline on two Parquet scenarios. The baseline held warm
  timings that depended on run order; run alone, v0.20.1 and v0.21.0 measure the same. See the
  [performance results](v0.21.0-performance-results.md).
- The macOS packages and DMG are checked by content only: their browser files match the prepared
  build, but they have not been launched on a Mac. The VS Code extension's webviews are verified
  in a real VS Code on Windows; the Linux and macOS extension packages are verified by file hashes
  only. See the [delivery matrix](v0.21.0-browser-asset-delivery-matrix.md).
- Production canaries and HA fault evidence are not certified for this release.

## Upgrade Guide

1. **Stop both services and back up the Portal and Orchestrator databases**: the SQLite files with
   their `-wal`/`-shm` sidecars, or the PostgreSQL databases. An installed Orchestrator keeps its
   SQLite database under the service account's local application data, not the install folder:
   `C:\Windows\System32\config\systemprofile\AppData\Local\etlsql-data\etlsql.db` on Windows and
   `/var/lib/etl-sql/.local/share/etlsql-data/etlsql.db` on Linux. v0.20.x `admin backup` does not
   include that file, so copy it by hand. The schema rename cannot be undone by reinstalling v0.20.x;
   rollback is restoring this backup with that release.
2. If `ENC:` values are in use without `ETLSQL_MACHINE_KEY_FILE`, plan to re-encrypt them after the
   upgrade.
3. Install the v0.21.0 MSI or DEB over the existing installation. The installer keeps the installed
   configuration and moves existing secrets into `appsettings.secrets.json`.
4. Confirm both services are running and the Portal answers `/health`.
5. Update any SQL or tools that query the Portal or Orchestrator databases directly to the
   snake_case names.

A building checkout also needs Node.js 22 to prepare browser assets:
`npm ci --prefix scripts/typecheck`, then `node scripts/sync-assets.js`.
