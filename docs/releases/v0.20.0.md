# ETL-SQL v0.20.0

**Status:** Release candidate preparation. Not published. Final certification and packaged-asset
availability must be recorded before these notes become the release record.

## Release Summary

v0.20.0 focuses on code stability. The shared browser runtime and Studio now use focused TypeScript
modules with type, lint, generated-contract and asset checks. The release also improves Studio's
script authoring and recovery, extends supported native chart semantics, and fixes data correctness,
credential handling, cancellation and operational evidence defects.

## Breaking Changes & Required Actions

The complete behavior changes and migration actions are in
[BREAKING_CHANGES.md](../../BREAKING_CHANGES.md). Review these before upgrading:

| Affected work | Required action |
| :--- | :--- |
| Independent numeric facets | Remove authored MIN/MAX where each panel should fit its data automatically; supplied bounds are now retained. |
| Connected charts | Regenerate saved exports to restore unsampled endpoints, missing transposed ribbons and correctly anchored decorations. Reduce the query dataset explicitly when fewer connections are desired. |
| Connected/POINT compositions | Set the POINT layer's Z_INDEX above the connected layer when points should paint in front. |
| AREA ribbon scales | Bind both bounds to the same Y scale or leave both inferred. |
| Serialized chart contracts | Regenerate malformed schema/version envelopes and use a renderer supporting the authored controls. Ordered accessible fallback content is checked by value. |
| Excel extraction | Only the selected sheet is streamed; validate other sheets separately if required. |
| REST connections | Use separate credential origins, explicit Cookie headers when needed, and a TIMEOUT_SECONDS deadline sufficient for the entire response body. |
| SharePoint and Active Directory | Remove downstream workarounds for dropped pages or duplicate results. SharePoint continuations must stay on the configured origin. |
| Case-insensitive joins | Use CASE_SENSITIVE ON where differently cased keys must remain distinct. |
| Nested transactions | The outermost COMMIT persists writes. Recheck any workflow that depended on writes escaping an outer ROLLBACK. |
| Remote UPDATE | Literals and variables are now bound correctly; rerun affected statements and validate their intended result. |
| LIST text and page selections | Use VARCHAR to retain whole text; use a JSON array for an item containing a comma. Decode multi-page selections as JSON arrays. |
| Tool JSON numbers | Remove rounding workarounds; reserve FLOAT/DOUBLE for approximate values. |
| Provider diagnostics and logs | Raw sensitive values are unavailable in sanitized errors, log properties and UI callbacks. |
| Scheduler evidence-store failures | Inspect persistence errors and repair the evidence store; completed mutations are not retried to recover logging. |
| HA environments | Supply a distinct `ORCH_IDENTITY_SIGNING_SECRET` of at least 32 UTF-8 bytes on all Portal and Orchestrator instances, or regenerate disposable soak roots with `admin ha-soak prepare`. |
| HA certification | Use CiSmoke plans for the bounded native runners. Replace historical reports labelled as manual evidence with measured physical topology runs; validators reject relabelled native reports. |
| Studio saves and formatting | Edits made during save remain dirty. Regenerate reports previously affected by lost interaction clauses or undeclared shared connections. |

Terminal charts now retain rows from every unfaceted layer, and transposed reference rules ignore
unrelated color groups. These corrections can change previously incomplete output without script edits.

## Deprecations

No new scheduled syntax removals. Existing ReportBuilder and WorkstationEditor entry points remain
supported; Studio Alpha does not establish a retirement decision.

## Highlights

### More authoring controls in Studio Alpha

**Audience:** Script Authors · Report Authors

Report and pipeline edits now preserve more of the surrounding authored script. Studio provides
inspector controls for analytics overlays, tooltips, cross-filtering, drill actions
and table row detail. Unsupported author text stays visible without a lossy rewrite. The pipeline
palette adds extract, validate, transform, load and cleanup steps, with the generated statement shown
before insertion. Task fields, labelled steps, ELSE branches and PARALLEL lanes remain tied to the script.

```powershell
etl-sql studio open .\reports
etl-sql studio list
```

Studio-authored pipelines can be catalog documents. Their remaining governed Portal submission,
status/log/cancellation and schedule journeys remain Alpha backlog work. See the
[Studio design](../architecture/decisions/etl-sql-studio.md) and
[Portal ETL documents](../architecture/decisions/portal-etl-documents.md).

### Native chart semantics and paginated furniture

**Audience:** Report Authors · Report Consumers

Chart connections, decorations and exports now preserve more of the same source data. Supported
Cartesian and transposed LINE/AREA charts share source-owned COLOR/OPACITY connections,
endpoint decorations and interpolation across native SVG, static PDF, terminal and accessible output.
Supported transposed fixed-aspect forms add nudges, stable-key jitter and paired confidence bounds.
Polar ARC charts add ZERO/NORMALIZE radial stacking. Refer to the
[CHART reference](../reference/visuals-reporting/visuals/chart.md) for the accepted combinations.

TEXT and IMAGE header/footer bands repeat on physical pages. Page, title, date, parameter and data-field
tokens resolve in printed output, and Studio exposes the corresponding furniture controls.
The remaining chart semantic extensions stay in the backlog. Build and serve an authored report
with the matching runtime to use its supported native semantics:

```powershell
etl-sql-report build .\charts.rptsql
etl-sql-report serve .\charts.rptsql
```

## Improvements

### Safer changes to the browser runtime

**Audience:** Report Authors · Administrators · Contributors

Browser regressions can break report rendering and authoring across hosts. The shared browser
sources now have type, lint, generated-contract and asset checks before distribution. Canvas edits,
document navigation, inspector controls, execution, governance and authoring dialogs have focused
controllers. Hosts retain their existing entry points; offline reports retain the generated bundle.
Route and DTO contracts are generated from the owning host and checked against the shipped sources.

See [reporting architecture](../architecture/reporting.md) and the
[browser verification record](v0.20.0-browser-split-baseline.md).

### Recovery and job outcomes

**Audience:** Authors · Administrators

A crash, expired sign-in or background failure now leaves clearer recovery and outcome evidence.
Host-side recovery keeps supported unsaved Studio work after a crash or expired sign-in. Desktop
recovery uses the user's application data; Portal recovery is private to the author. Save completion
preserves subsequent edits. This does not provide the unpublished learner-draft workflow still in
the Alpha backlog.

Cancellation now reaches tool execution and peer streams. Container teardown must prove removal.
Scheduler history failures preserve the workload outcome, and Gateway receipts retain mutation replay
protection across restart without rewriting the entire historical ledger.

- Studio route tables come from named Portal and desktop endpoints; complete palette keys and
  generated DTO/enum shapes are checked by the browser toolchain.
- Runtime assets are selected from host import closures. ReportPlayer receives the runtime;
  VS Code receives its designer/wizard closure; Studio modules ship in its two hosts.
- Browser tests use separate Portal collections and observable waits. Test fixtures isolate their
  databases, signing configuration and cleanup from the developer's environment.
- CLI Studio hosts stop after two idle minutes with no running or unsaved work. Use
  `--idle-timeout-minutes 0` for a persistent host.
- Portal and Orchestrator use the configured application logging sink, rolling/retention limits,
  levels and text/JSON format. Audit backlog and execution aggregates run in the database.
- Audit delivery records retries and terminal failures, releases claims after transport failure,
  and maintains its local outbox with no collector configured.
- Gateway receipt lookup and retention use an indexed incremental SQLite store; legacy migration
  is atomic and mutating receipts do not expire.
- Release resume verifies commands, retained evidence and file-content fingerprints. Test lanes
  require executed passing results, and certification archives select fresh clean-candidate claims.
- Maintenance release workflows select the newest stable previous MSI below the candidate and
  preserve Latest when a newer stable release exists.

## Performance

The browser split's measured runtime closure added 10,787 gzip bytes (11.3%) while raw JavaScript
shrunk by 27,271 bytes. This historical measurement includes the complete runtime closure and is
not a Studio cold-load latency claim. See the [browser verification record](v0.20.0-browser-split-baseline.md).

The [scale investigation](v0.20.0-performance-results.md) isolates output-capture latency and retained
theory data from engine measurements. After correcting fixture ownership, development Smoke and
Standard runs each passed 39 measurements, including scenario teardown.
Clean Smoke/Standard calibration passed 520 correctness/memory measurements and every candidate/
control and repeat-run comparison. Replacement references pool both released-control runs while
preserving the historical files and existing bands. Final candidate release-gate results remain
pending; no engine speedup is claimed.

## Security

- Connector exceptions, quoted secrets and nested log properties are sanitized at the final sinks.
- Container tool credentials are forwarded by environment name without plaintext values in argv.
- Tool output/stderr and line lengths are bounded, and cancellation/teardown failures stay visible.
- Child cleanup checks process creation, executable and owner identity before termination.
- Sandbox workspace reconciliation preserves ownership and admission until runtime detachment and
  cleanup are proven; failures retain actionable residue evidence.
- REST credentials stay on their configured origin. Response deadlines include reading the body,
  and implicit cookie persistence is disabled.
- FlatFile and SMTP paths require an execution context; missing context is refused.

See the [v0.20.0 review working record](v0.20.0-code-review.md),
[connector standards](../architecture/standards/connectors-standards.md) and
[deployment-profile boundaries](../architecture/deployment-profiles.md).
Contract or deterministic-adapter passes do not certify a physical hardened runtime or hosted region.

## Bug Fixes

- Windows child tracking reads executable identity from the retained process handle before the
  loader populates its module list. Creation-time, executable and service-owner checks still guard
  orphan cleanup.
- HA topology generation configures the distinct caller signing secret required by the Orchestrator.
  Sustained workloads exchange Portal sessions for signed caller identity alongside the API key,
  and diagnostics redact the signing secret. Existing HA environments must supply
  `ORCH_IDENTITY_SIGNING_SECRET` on upgrade. Portal connects to the shared Orchestrator database;
  HAProxy checks Portal readiness and learns the Portal node cookie for affinity.
- Joins honor the active case comparison across hash and spill paths; tool JSON output preserves
  exact integers/decimals; nested and first-statement mutations participate in transaction rollback.
- Shared-connection Studio reports declare the connection in their script, so reader, schedule and
  subscription execution use the same source contract as preview.
- Formatting retains INTERACTIONS, EMIT_FILTER and ROW_DETAIL. Canvas edits retain multiple trigger
  actions, annotations and hand-authored task options.
- Studio handles late responses after closing a document, tab rename focus, inspector state,
  newly declared connection schemas and per-tab undo state correctly.
- Pipeline connectors, readable zoom, labels, CASE-aware block boundaries and ELSE insertion work
  without corrupting the surrounding script.
- Browser conditional/action expressions recognize `<>`; print exports resolve text and page tokens.
- Ad-hoc jobs and CLI runs release cancellation sources on setup failures. Governance and storage
  sampling failures report sanitized errors instead of empty results or unhandled background faults.
- PDF exports remove partial images after cancelled/failed writes and surface cleanup failures.
- Chart facets, connected sampling, layer priority, transposed ribbons, decoration anchors and
  semantic fallback round trips preserve the represented data.

## Known Issues

- Studio remains Alpha. Unpublished learner drafts, full ordinary-author/reader certification,
  accessibility passes, large-document and catalog work, and governed Portal pipeline execution
  journeys remain scheduled backlog work.
- The broader chart extension roadmap is unfinished. Do not infer support from a neighboring form;
  use the current CHART reference and diagnostics.
- Shared transitions, sandbox metering closure and physical hosted launch evidence remain backlog.
  Release claims must name only actually certified profiles, transitions, topologies and regions.
- Intel macOS output remains best effort. Final asset availability and all required candidate
  certification results have not yet been recorded in this draft.

## Upgrade Guide

1. Back up Portal/Orchestrator state, artifacts and required keys using
   [backup and recovery guidance](../administration/platform/backup-and-monitoring.md).
2. Review the actions above and [BREAKING_CHANGES.md](../../BREAKING_CHANGES.md). Lint and validate
   affected reports, joins, REST integrations and transaction workflows on a controlled fixture.
3. Stop the ETL-SQL services, install the matching platform package and preserve deployment
   configuration, secret storage and host-owned bindings.
4. Start services and inspect the forward migration logs. Portal applies schema migrations on
   startup; rollback uses the pre-upgrade backup, not down-migrations.
5. Verify the binary version, a permitted report, a controlled job and any affected export. Regenerate
   saved reports and snapshots using the matching runtime.

```powershell
etl-sql --version
```

See [installation](../administration/platform/installation.md) for profile-specific service steps.
Final N-to-N+1 MSI, transition and restore evidence must be linked before release.
