# ETL-SQL v0.2.0 *(Unofficial)*

**Released:** 2026-03-23

Introducing **relational database connectors**, **standard query dialect operations**, and **transaction control flows**.

---

## Release Summary

v0.2.0 is an unofficial pre-release that builds out the core querying vocabulary of the ETL-SQL engine. It introduces database connectors for **MSSQL, Postgres, and Oracle**, file connectors for **JSON and XML**, and transactional capabilities (`COMMIT`/`ROLLBACK`/`THROW`). It also adds support for parallel processing pipelines (`PARALLEL`), cross-script orchestration (`RUN SCRIPT`), directory synchronization, and SMTP email notifications.

## Highlights

### Relational Database & File Connectors

**Audience:** Script Authors · Evaluators

**Problem:** The initial proof of concept was limited to CSV file inputs and could not query or write to corporate databases, cloud storage, or structured web feeds.

**Solution:** Native data connectors:
- **Relational Databases:** Connect and query `MSSQL`, `POSTGRES`, and `ORACLE` engines.
- **File Systems:** Built-in read/write support for `JSON` and `XML` formats.
- **Cloud & Transfer:** Integrated file transfers via `SFTP/SSH`, `FTP`, and `AZURE_BLOB`.

```sql
-- Connect to Postgres database
CREATE CONNECTION local_pg AS POSTGRES(
  HOST = 'localhost',
  DATABASE = 'app_db',
  USER = 'pg_user',
  PASSWORD = 'SECRET:pg_pass'
);

-- Read postgres and copy directly into engine memory
SELECT id, name INTO #users FROM local_pg.users;
```

---

### Core Query Dialect & Transactions

**Audience:** Script Authors

**Problem:** Transforming data in-memory requires standard SQL expressions, pagination clauses, and transaction controls to ensure partial failures roll back cleanly.

**Solution:** Standard SQL dialect expansions:
- **Pagination & Filters:** `DISTINCT`, `TOP`, `LIMIT`, `OFFSET`, `NTILE`, and `STRING_AGG`.
- **DML operations:** `MERGE` statement support.
- **Transactions:** `COMMIT TRANSACTION`, `ROLLBACK TRANSACTION`, and `THROW` exception handlers.

---

### Control Flow & Orchestration

**Audience:** Script Authors · Administrators

**Problem:** Standard ETL pipelines execute steps strictly in sequence, wasting CPU cores when loading independent source feeds.

**Solution:** Control structures:
- **Parallelism:** The `PARALLEL BEGIN ... END` block executes child pipelines concurrently.
- **Modular Scripts:** `RUN SCRIPT` executes adjacent script files.
- **Sync Operations:** Native directory synchronization and SMTP email (`SEND EMAIL`) alerts.
