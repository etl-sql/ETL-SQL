# ETL-SQL v0.9.0

**Released:** 2026-06-01

Introducing **resumable script checkpoints**, **ECharts SSR PDF chart rendering**, a native **MySQL** connector, and **EXPLAIN ANALYZE** query profiling.

---

## Release Summary

v0.9.0 introduces robust checkpointing and execution profiling to ETL-SQL pipelines. The new **Checkpoint and Resume** subsystem allows long-running jobs to auto-serialize `#temp` tables and variable scopes at named section boundaries (`LabelName:`), allowing failed or stopped scripts to `--resume` and skip completed work. Report exports receive a major upgrade via the **ECharts SSR engine**, which renders dashboard charts as vector SVGs within generated PDFs. A native **MySQL / MariaDB connector** replaces the slower ODBC bridge, while **EXPLAIN ANALYZE** adds real-time profiling (execution times, row counts, and disk spill footprints) to debugging.

---

## ⚠️ Breaking Changes & Required Actions

- **`--resume` CLI flag validation:** Running with the `--resume` CLI flag now requires a `--session` identifier and a valid saved checkpoint. Fresh invocations without these throw a fail-fast error rather than silently running from the start.
- **GOTO target validation:** Jump targets are strictly restricted to identifier tokens. Target names matching keywords (e.g. `SELECT`) now produce parser diagnostics.

## Highlights

### Resumable Pipeline Checkpoints & Scoped GOTO Jumps

**Audience:** Script Authors · Administrators

**Problem:** If a multi-hour pipeline fails during the final load stage (e.g. database connection dropout), developers have to manual-comment sections or rerun the entire script from scratch, costing time and database resources.

**Solution:** Stateful execution checkpoints combined with scoped GOTO jumps:
- **`LabelName:` Section Checkpoints:** Top-level labels act as auto-serialization boundaries. When hit, the engine serializes all variables (JSON) and active `#temp` tables (Arrow IPC) to a local session cache.
- **`--resume` and `--session`:** If a script fails, rerun it using `etl-sql --run script.etlsql --session job_run_42 --resume`. The engine restores the state and jumps directly to the last incomplete label.
- **`GOTO LabelName;` control flow:** Supports jumps out of nested loops, conditional branches, and `TRY...CATCH` blocks. Jumping *into* nested blocks or across script files is rejected at compile time.

```sql
ExtractData:
  SELECT * INTO #staged_orders FROM sales.orders;

ValidateData:
  -- If data is empty, jump directly to notification
  IF (SELECT COUNT(*) FROM #staged_orders) = 0
    GOTO SendNotification;

TransformData:
  -- Heavy calculations...
  SELECT id, HASHBYTES('SHA2_256', email) INTO #clean FROM #staged_orders;

SendNotification:
  PRINT 'Pipeline stage reached.';
```

### Native MySQL & MariaDB Connector

**Audience:** Script Authors

**Problem:** Relying on the system ODBC driver bridge for MySQL led to slower performance, dialect translation issues, and platform-specific connection errors.

**Solution:** A native `MySqlConnector` provider built directly on the `MySqlConnector` package:
- Removes ODBC driver requirements on runner machines.
- Delivers native MySQL/MariaDB dialect parsing.
- Automatically catches and wraps driver exceptions into structured, sanitized `ExecutionException` diagnostics.
- Adds metadata catalog discovery for tables, schemas, and stored procedures.

---

### ECharts SSR PDF Chart Export

**Audience:** Report Consumers · Administrators

**Problem:** Exported PDF reports lacked real chart visual rendering, displaying empty placeholders or low-resolution snapshots.

**Solution:** Server-side integration of the ECharts SSR pipeline:
- Chart visuals are rendered as high-fidelity vector SVGs inside generated PDF reports.
- Aligned Markdown tables preserve column formatting, number alignments, and custom fonts.
- Verified via automated PDF magic-header and structure regression tests.

---

### EXPLAIN & EXPLAIN ANALYZE Profiling

**Audience:** Script Authors · Evaluators

**Problem:** Identifying why a query is running slowly or where disk spilling is occurring required analyzing database engines directly.

**Solution:** Statements to trace query planning and runtime performance:
- `EXPLAIN <statement>`: Produces a query plan matrix listing costs, operations, and estimated rows.
- `EXPLAIN ANALYZE <statement>`: Executes the query under full telemetry instrumentation, returning actual execution time, row counts, and physical disk spill sizes in bytes.
- Supports whole-script analysis using the `--explain` CLI flag.

## Performance

- **Indexed Lineage Walks** — Lineage tracking scans are indexed via `LineageTracker` to replace slow linear sweeps with O(1) lookups.
- **Cached Parameter Scans** — Parameter listings are cached to optimize pipeline generation loops.

## Upgrade Guide

Standard upgrade — replace binaries and restart services.

If you utilize `--resume` scripts, ensure your automation passes a unique `--session` string. Resume requests without a session ID will fail fast with a configuration error.
