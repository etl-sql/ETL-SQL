# ETL-SQL v0.17.0

**Released:** 2026-07-23

v0.17.0 makes ETL-SQL easier to author, easier to govern, and easier for business users to find and
use trusted reports without learning the technical folder structure first.

---

## Release Summary

This release closes the v0.17.0 sprint by shipping design-time pipeline visualization, a much richer
visual report designer, business-consumer Portal discovery, report-scoped access approvals, and
script-first protected-data stewardship. It also tightens the release posture with SFTP host-key
verification closed by default, permission-aware schema lookup, report-level ACL enforcement, and
performance fixes in catalog search, equality checks, interpolation, and Portal permission lookup.

---

## Breaking Changes & Required Actions

**SFTP host-key verification is now closed by default**
- SFTP connections without `HOST_KEY_FINGERPRINT` are rejected unless
  `ALLOW_UNPINNED_HOST_KEY = 'TRUE'` is set intentionally.
- Preferred action: pin the expected host key fingerprint.

```sql
CREATE CONNECTION vendor_drop AS SFTP(
  HOST = 'sftp.vendor.example',
  USER = 'etl_sender',
  KEYFILE = 'C:\ETL\keys\vendor.key',
  HOST_KEY_FINGERPRINT = 'SHA256:...'
);
```

For temporary lab or migration scenarios only:

```sql
CREATE CONNECTION lab_sftp AS SFTP(
  HOST = 'lab.example',
  USER = 'etl_sender',
  PASSWORD = SECRET:lab_sftp_password,
  ALLOW_UNPINNED_HOST_KEY = 'TRUE'
);
```

## Highlights

### Design-Time Script Flow Preview

**Audience:** Script Authors · Report Builders

Authors can now inspect the expected shape of a pipeline before running it. The new Flow/DAG preview
is derived from the script itself, so `.etlsql` and `.rptsql` remain the source of truth while the UI
shows connections, staging tables, file reads/writes, report datasets, visuals, outbound transfers,
loops, branches, and unresolved dynamic parts.

The implementation reuses the existing lineage/DAG builder and shared browser renderer instead of
introducing a separate visual model. Node selection can route authors back to source context, and
parse uncertainty is shown explicitly instead of presenting an incomplete graph as definitive.

### Visual Report Builder Ergonomics

**Audience:** Report Builders

The visual designer is now closer to a daily-use dashboard authoring surface. It adds keyboard
delete, `Ctrl+S`/`Cmd+S`, escape-to-clear, arrow-key nudging, undo/redo, visual duplication,
multi-select movement, explicit container detachment, container collapse, tab/accordion child
assignment, mapping validation hints, dataset-column autocomplete, and drag-and-drop mapping from
the dataset tree.

These changes reduce the amount of manual `.rptsql` editing needed for layout work while keeping the
generated script reviewable in Git.

### Business Consumer Portal Discovery

**Audience:** Report Consumers · Portal Administrators

The Portal now gives non-admin users a consumer-oriented starting point: favorites, recently viewed
reports, featured/popular reports, and search results that explain why they matched. Catalog search
is fuzzy and metadata-aware, covering technical report titles, descriptions, tags, folders, owners,
domains, stewards, and certifications while preserving permission filtering.

Published report headers now expose owner/contact, freshness state, last-refresh information, and
interactive tags. A stale report can show a request-refresh action; users with execute permission
start a refresh, while read-only consumers create an audited owner request instead of bypassing
permissions.

### Report-Scoped Access Requests

**Audience:** Report Owners · Administrators

Restricted reports now have a self-service request path and an owner/admin approval queue. Approval
creates a report-level ACL using the existing `FolderPermission` levels, so granting one report does
not accidentally grant an entire folder. Effective report permission combines admin status, folder
ownership, folder ACLs, report creator ownership, and report-level ACLs.

Approval and denial decisions are audited atomically with the mutation, duplicate pending requests
are coalesced, and non-pending requests cannot be decided again.

### Protected-Data Stewardship Workflow

**Audience:** Data Stewards · Administrators

Stewards can inventory sensitive lineage without memorizing individual tag queries:

```sql
SHOW PROTECTED DATA LIMIT 100 INTO #protected_assets;
SHOW PROTECTED DATA SUGGESTIONS LIMIT 100 INTO #classification_review;
SHOW PORTAL AUDIT ACTION 'STEWARD_LINEAGE_IMPACT' LIMIT 100 INTO #steward_events;
```

The release includes a packaged `samples/08_Reporting/protected_data_audit.rptsql` dashboard and a
Portal Lineage Audit mode that brings protected inventory, missing metadata, stale protected assets,
impact, classifier suggestions, and audit/outbox health into one workflow.

## Improvements

### Language & Engine
- Added protected-data and Portal-audit inspection commands for script-first governance reviews.
- Added `DATE_SUFFIX` and `SUFFIX_SEPARATOR` file-operation options for common dated archive names
  after exports, sends, and handoffs.
- Extended `SHOW SCHEMA`/`DESCRIBE` lookup for file-based connections so agents and authors can
  inspect CSV/flat-file shape before writing transformations.
- Added tag-driven governance gates for sensitive exports, restricted public datasets, required
  stewardship metadata, and `@quality=gold` promotion metadata.
- Kept soft DateTime equality at second-level semantics while improving byte-array equality with
  span-based comparison.

### Data Quality
- Added column-level `@expect` / `@fail` rules, `ASSERT JOB` run-metric predicates, transition-based
  alerting, quarantine replay manifests, `REPLAY QUARANTINE`, disposition enforcement, and the first
  Portal steward queue/editor for quarantine rows.
- Hardened `UNIQUE` rules for larger inputs: UNIQUE key records now spill into hash partitions,
  all UNIQUE rule occurrences are collected in one pre-pass, and duplicate lookup is keyed by rule
  occurrence so identical rule text on different columns cannot collide.
- Added connector-side retention pruning as an explicit data-source capability. SQLite-backed
  quarantine/warn targets now honor `WITH (RETENTION = '...')` with a bounded delete on `__dq_ts`.

### Portal & Visualization
- Added report-level ACL persistence and enforcement across report opening, catalog discovery,
  execution, refresh, and saved views.
- Added one-click "My Default View" saving so a user's current parameter/slicer state can become the
  report default without creating duplicate saved views.
- Added interactive tag badges that navigate to catalog search in normal Portal usage and post a
  search intent to an embedding parent.
- Added owner/admin access request queue endpoints for pending request review, approval, and denial.

### VS Code Extension & IDE
- Added design-time Flow/DAG preview plumbing through the shared analysis and renderer stack.
- Schema lookup now re-checks connector egress policy even when metadata is served from cache.

### Connectors
- SFTP host-key verification is closed by default, with an explicit unpinned opt-out for lab or
  transitional environments.
- File-based schema lookup support was extended so `SHOW SCHEMA` can assist agents and authors with
  CSV/flat-file work.

## Performance

- Catalog fuzzy matching now avoids the old two-dimensional Levenshtein allocation pattern.
- Portal group membership is cached per scoped service by user, reducing repeated permission queries
  during catalog and report workflows.
- Variable interpolation uses compiled regexes in hot paths.
- Binary soft equality uses span sequence comparison.

---

## Security

- SFTP host-key verification now fails closed unless a host key is pinned or an explicit unpinned
  opt-out is configured.
- Cached schema responses re-check egress policy before returning metadata.
- Report access approvals grant report-level ACLs instead of broad folder ACLs by default.
- Access approvals and denials stage audit rows in the same unit of work as the access mutation.
- Stale-report refresh requests preserve permission boundaries: read-only consumers request owner
  action, while execute-capable users start a refresh.

---

## Bug Fixes

- Fixed EF migration/snapshot drift around report ACLs so SQLite and PostgreSQL migration validation
  no longer raises pending-model warnings.
- Removed an unnecessary standalone `ReportAcls.ReportId` migration index that did not match the
  EF model.
- Prevented repeated "My Default View" saves from creating duplicate saved-view rows.
- Prevented already-approved or already-denied access requests from being decided again.
- Corrected report-level ACL visibility gaps in catalog and saved-view endpoints.

## Upgrade Guide

1. Replace binaries and restart services.
2. Apply the Portal database migrations for your configured provider.
3. Review SFTP connections and add `HOST_KEY_FINGERPRINT` where missing.
4. Use the explicit `ALLOW_UNPINNED_HOST_KEY = 'TRUE'` opt-out only where an unverified connection is
   an intentional temporary choice.
