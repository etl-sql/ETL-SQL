# ETL-SQL v0.17.0

**Released:** 2026-07-26

v0.17.0 makes ETL-SQL easier to author, easier to govern, and easier for business users to find and
use trusted reports without learning the technical folder structure first.

---

## Release Summary

This release closes the v0.17.0 sprint by shipping in-pipeline data quality — declarative column
rules, run-metric assertions, quarantine capture, and steward-driven replay — alongside design-time
pipeline visualization, a much richer visual report designer, business-consumer Portal discovery,
report-scoped access approvals, and script-first protected-data stewardship. It also tightens the
release posture with SFTP host-key verification closed by default, permission-aware schema lookup,
report-level ACL enforcement, and performance fixes in catalog search, equality checks,
interpolation, and Portal permission lookup.

---

## Breaking Changes & Required Actions

**SFTP host-key verification is now closed by default**
- SFTP connections without `HOST_KEY_FINGERPRINT` are rejected unless
  `ALLOW_UNPINNED_HOST_KEY = 'TRUE'` is set intentionally.
- Preferred action: pin the expected host key fingerprint.

```sql
CREATE CONNECTION vendor_drop AS SFTP(
  HOST = 'sftp.vendor.example',
  USER = 'etl_sender',
  KEYFILE = 'C:\ETL\keys\vendor.key',
  HOST_KEY_FINGERPRINT = 'SHA256:...'
);
```

For temporary lab or migration scenarios only:

```sql
CREATE CONNECTION lab_sftp AS SFTP(
  HOST = 'lab.example',
  USER = 'etl_sender',
  PASSWORD = SECRET:lab_sftp_password,
  ALLOW_UNPINNED_HOST_KEY = 'TRUE'
);
```

**Build and publish scripts were renamed from `under_scores` to `hyphens`**
- Ten scripts changed name — `publish-release.ps1`, `build-msi.ps1`, `build-linux-packages.sh` and
  so on. Scripts and CI steps that invoke them **by path** must be updated.
- `scripts/README.md` lists every script and its current name.
- No action is required for anyone using `Master-Release.ps1` / `Test-PreRelease.ps1` as the entry
  points, since those call the renamed scripts internally.

**`ETL-SQL.Connectors` was split into per-domain assemblies**
- Scripts and connection syntax are **unaffected** — provider namespaces are unchanged.
- Only hosts that reference the connector assembly *directly* from .NET code need to add the group
  they use: `.Cloud`, `.Messaging`, `.Remote`, `.Databases`, `.Files`, or `.Common`. The benefit is
  that a host no longer pulls in every provider SDK transitively.

## Highlights

### In-Pipeline Data Quality

**Audience:** Script Authors · Data Stewards

Data quality checks previously had to be written as separate validation queries that ran *after* a
load, which meant bad rows were already in the target and the rule lived far away from the column it
described. Rules are now declared inline on the column they govern, and enforced while the rows
stream:

```sql
import_policies:
SELECT
    policy_no /* @expect: 'NOT NULL'; @fail: 'THROW';
                 @expect_1: 'UNIQUE'; @fail_1: 'QUARANTINE'; */,
    email     /* @expect: 'MATCHES ^[^@]+@[^@]+$'; @fail: 'QUARANTINE'; */,
    premium   /* @expect: '>= 0'; @fail: 'WARN'; */
INTO clean_policies
FROM staged_policies
ON FAILURE QUARANTINE TO dq_policy_rejects WITH (RETENTION = '30 DAYS')
ON FAILURE THROW;
```

Rules cover `NOT NULL`, `UNIQUE` (including `UNIQUE WITH (cols)` and `UNIQUE_FIRST/LAST BY`),
`MATCHES`, `IN`, `EXISTS IN`, `EXPR`, and numeric comparisons. Actions are `THROW`, `WARN`, and
`QUARANTINE`. Failing rows are captured **pre-projection** so a steward sees the value that actually
caused the failure, `@pii` values are masked in diagnostics and logs, and rules are validated at lint
time rather than at run time.

Run-level assertions check the run's own metrics instead of re-querying the target, so write-only
sinks are supported:

```sql
ASSERT JOB nightly_policies (
    ROW_COUNT WITHIN 0.2 OF HISTORICAL,
    NULL_PERCENT(clean_policies.email) < 0.02,
    QUARANTINE_PERCENT < 0.01
)
ON FAILURE ALERT ops_webhook
ON CRITICAL_FAILURE THROW;
```

Baselines come from the mean of recent completed runs and are skipped below a configurable minimum
run count, so a new job does not alert-storm. Orchestrator-hosted alerts are transition-based:
pass→fail alerts, repeated failures are suppressed for a configurable window, and fail→pass sends a
recovery notification. Alert payloads are counts-only — sample data is never transmitted.

### Steward-Driven Quarantine Remediation

**Audience:** Data Stewards · Operators

Quarantined rows are no longer a dead-end table. Orchestrator-hosted runs persist a replay manifest
recording the job, script, section label, source and quarantine targets, replayability, and the
captured input schema fingerprint. A steward can then correct rows and push them back through the
original pipeline section:

```sql
REPLAY QUARANTINE dq_policy_rejects;
```

Replay is fenced through the orchestrator cluster-lock store so two stewards cannot consume the same
released row set twice, and rows claim a `replaying` state before target-side work — a failed run
requires an explicit retry or completion decision instead of silently duplicating an uncertain load.
The `__dq_*` evidence columns are immutable except for status, and dispositions follow a defined
lifecycle (`quarantined` → `released`/`discarded`, `released` → `replayed`/`discarded`).

The Portal Governance sidebar adds a Quarantine Queue with an inline row editor for targets it can
resolve. Where Portal cannot reach the producing connection or a session-local table, the target is
explicitly marked **view-only** with the reason and copyable review SQL, rather than opening an
editor that would fail or misleadingly show an empty table.

### Design-Time Script Flow Preview

**Audience:** Script Authors · Report Builders

Authors can now inspect the expected shape of a pipeline before running it. The new Flow/DAG preview
is derived from the script itself, so `.etlsql` and `.rptsql` remain the source of truth while the UI
shows connections, staging tables, file reads/writes, report datasets, visuals, outbound transfers,
loops, branches, and unresolved dynamic parts.

The implementation reuses the existing lineage/DAG builder and shared browser renderer instead of
introducing a separate visual model. Node selection can route authors back to source context, and
parse uncertainty is shown explicitly instead of presenting an incomplete graph as definitive.

### Visual Report Builder Ergonomics

**Audience:** Report Builders

The visual designer is now closer to a daily-use dashboard authoring surface. It adds keyboard
delete, `Ctrl+S`/`Cmd+S`, escape-to-clear, arrow-key nudging, undo/redo, visual duplication,
multi-select movement, explicit container detachment, container collapse, tab/accordion child
assignment, mapping validation hints, dataset-column autocomplete, and drag-and-drop mapping from
the dataset tree.

These changes reduce the amount of manual `.rptsql` editing needed for layout work while keeping the
generated script reviewable in Git.

### Business Consumer Portal Discovery

**Audience:** Report Consumers · Portal Administrators

The Portal now gives non-admin users a consumer-oriented starting point: favorites, recently viewed
reports, featured/popular reports, and search results that explain why they matched. Catalog search
is fuzzy and metadata-aware, covering technical report titles, descriptions, tags, folders, owners,
domains, stewards, and certifications while preserving permission filtering.

Published report headers now expose owner/contact, freshness state, last-refresh information, and
interactive tags. A stale report can show a request-refresh action; users with execute permission
start a refresh, while read-only consumers create an audited owner request instead of bypassing
permissions.

### Report-Scoped Access Requests

**Audience:** Report Owners · Administrators

Restricted reports now have a self-service request path and an owner/admin approval queue. Approval
creates a report-level ACL using the existing `FolderPermission` levels, so granting one report does
not accidentally grant an entire folder. Effective report permission combines admin status, folder
ownership, folder ACLs, report creator ownership, and report-level ACLs.

Report authorship **upgrades** an existing grant to `Manage` rather than substituting for one: an
author who no longer has any access to the containing folder (or an explicit report ACL) loses access
to reports they created. This keeps deprovisioning effective — removing a user from their groups, or
from the directory, also revokes the reports they authored and any anonymous share/embed links they
issued for them, which then report as `PermissionLost` in the admin inventory.

Approval and denial decisions are audited atomically with the mutation, duplicate pending requests
are coalesced, and non-pending requests cannot be decided again.

### Protected-Data Stewardship Workflow

**Audience:** Data Stewards · Administrators

Stewards can inventory sensitive lineage without memorizing individual tag queries:

```sql
SHOW PROTECTED DATA LIMIT 100 INTO #protected_assets;
SHOW PROTECTED DATA SUGGESTIONS LIMIT 100 INTO #classification_review;
SHOW PORTAL AUDIT ACTION 'STEWARD_LINEAGE_IMPACT' LIMIT 100 INTO #steward_events;
```

The release includes a packaged `samples/08_Reporting/protected_data_audit.rptsql` dashboard and a
Portal Lineage Audit mode that brings protected inventory, missing metadata, stale protected assets,
impact, classifier suggestions, and audit/outbox health into one workflow.

## Improvements

### Language & Engine
- Added data prep helpers that materialize inspectable `#temp` tables: `GENERATE CALENDAR` (a full
  date dimension including ISO week and fiscal year/quarter), `FILL_DATES` (fills missing daily rows
  per group), and `COMPARE DATASETS` (key-based diff emitting `_change_type`, `_changed_columns`, and
  `<column>_old` / `<column>_new` pairs). See [Data Prep Helpers](../reference/statements/data-prep.md).
- Added 14 productivity functions — period boundaries (`START_OF_WEEK`/`MONTH`/`QUARTER` and their
  `END_OF_*` counterparts, `SAME_PERIOD_LAST_YEAR`), safe arithmetic and banding (`SAFE_DIVIDE`,
  `AGE_BUCKET`, `VALUE_BUCKET`), and text/PII presentation helpers (`CLEAN_STRING`, `MASK_EMAIL`,
  `MASK_PHONE`, `MASK_SSN`). The `MASK_*` functions are presentation masking for reports and
  diagnostics — they are not a security control and do not restrict access to the underlying value.
- Added string variable interpolation inside string literals — `${@var}` and `${var}` — usable in
  statement options, file paths, dynamic connection settings, and expressions. An undeclared name is
  left intact as literal text, so shell commands and regex patterns are not corrupted.
- Added `SET DATA_QUALITY_DRY_RUN` to preview a rule set's impact before it quarantines, warns, or
  fails a run — useful when calibrating new rules against production-shaped data.
- Added integer digit-precision and sign constraints on temp tables, and `INT(N,+)` / `INT(N,-)`
  sign enforcement for flat-file columns.
- Added protected-data and Portal-audit inspection commands for script-first governance reviews.
- Added `DATE_SUFFIX` and `SUFFIX_SEPARATOR` file-operation options for common dated archive names
  after exports, sends, and handoffs.
- Extended `SHOW SCHEMA`/`DESCRIBE` lookup for file-based connections so agents and authors can
  inspect CSV/flat-file shape before writing transformations.
- Added tag-driven governance gates for sensitive exports, restricted public datasets, required
  stewardship metadata, and `@quality=gold` promotion metadata.
- Kept soft DateTime equality at second-level semantics while improving byte-array equality with
  span-based comparison.

### Data Quality
- Added column-level `@expect` / `@fail` rules, `ASSERT JOB` run-metric predicates, transition-based
  alerting, quarantine replay manifests, `REPLAY QUARANTINE`, disposition enforcement, and the first
  Portal steward queue/editor for quarantine rows. When Portal cannot resolve the producing
  connection or a session-local target, the queue marks the target view-only, explains why, and
  provides copyable review SQL instead of offering a nonfunctional editor.
- Hardened `UNIQUE` rules for larger inputs: UNIQUE key records now spill into hash partitions,
  all UNIQUE rule occurrences are collected in one pre-pass, and duplicate lookup is keyed by rule
  occurrence so identical rule text on different columns cannot collide.
- Added connector-side retention pruning as an explicit data-source capability. SQLite-backed
  quarantine/warn targets now honor `WITH (RETENTION = '...')` with a bounded delete on `__dq_ts`,
  scoped by `__dq_capture_scope` so shared targets cannot cross-prune between jobs or scripts.
- Added probe-side quarantine replay for observed N:1 hash joins; fan-out joins are captured for
  steward review but remain non-replayable with a specific diagnostic.
- Replay now claims released rows as `replaying` before target-side work. Failed runs require an
  explicit retry or completion decision instead of automatically duplicating an uncertain load.
- `ASSERT JOB` alerts are routed to the owners of the columns that actually failed, rather than to a
  single catch-all channel.
- Added rule visibility and a disposition audit trail, so a steward can see which rules protect a
  column and who released or discarded each quarantined row.
- Added `SET DATA_QUALITY_DRY_RUN` for previewing a rule set's impact before it takes effect.

### Portal & Visualization
- Added report-level ACL persistence and effective-permission enforcement across report-scoped
  reads, execution, refresh, subscriptions, designer operations, management, and saved views.
- Added one-click "My Default View" saving so a user's current parameter/slicer state can become the
  report default without creating duplicate saved views.
- Added interactive tag badges that navigate to catalog search in normal Portal usage and post a
  search intent to an embedding parent.
- Added owner/admin access request queue endpoints for pending request review, approval, and denial.
- Promoted Lineage to a top-level Governance workspace with its own sidebar, and aligned in-Portal
  documentation with the Portal layout via a dedicated docs endpoint.
- Added governed multi-statement runs and workbench sidebar parity.
- Extended the visual designer with report-level theme persistence, custom colour-palette pickers, an
  interactive `@variable` parameter binder, Tidy Layout compacting, governance badges, live
  split-screen mode, snapping grid guides, hover drop-zone highlights, container box styling and group
  dragging, and `LAYOUT(COLSPAN, ROWSPAN, WIDTH, HEIGHT)` emission on `CREATE VISUAL`.
- Expanded ECharts option mapping so every visual type renders in snapshot mode.

### Workstation Editor & CLI
- Added `etl-sql edit`, which opens the browser-based script editor, backed by a unified editor
  workbench shared by the Workstation and Portal hosts.
- Added a Git status surface with a header branch badge, a formatter settings panel persisted to
  `.etlsql-formatter.json`, and local run history.
- Added a memory ceiling and a destructive-statement guard for local runs, plus cancellable runs with
  visible elapsed time and a graceful exit path.
- Added column lineage, report preview, and compact colour-coded hover help.
- Added `SHOW SCHEMA` as a statement, with `--mock` mode and `--json` output for scripting and agents.

### MOCKDB
- Added built-in `Numbers`, `Dates`, `Times`, `Geography`, `Currencies`, and `Flags` dimension tables,
  with `Numbers` expanded to 1M rows and `Dates` covering 1900–2100. Demos, samples, and tests can now
  exercise realistic dimensional shapes without provisioning an external database.

### VS Code Extension & IDE
- Added design-time Flow/DAG preview plumbing through the shared analysis and renderer stack.
- Added a Visual Flow (DAG) webview backed by the shared script DAG builder.
- Schema lookup now re-checks connector egress policy even when metadata is served from cache.

### Packaging
- Added Portal subject-module sub-choices to the Windows installer and Linux package configuration,
  so a deployment can select the Portal modules it actually runs.

### Connectors
- Added a write-only `WEBHOOK` connector (aliases `SLACK`, `TEAMS`) that POSTs each inserted row as a
  JSON payload, with Slack/Teams message shaping via `FORMAT`, custom bodies via `BODY_TEMPLATE`, and
  an opt-in retry policy. This is what backs `ASSERT JOB ... ON FAILURE ALERT`. The endpoint URL is
  treated as a credential — `SECRET:` references resolve on `URL`, and the URL is masked to scheme +
  host in `SHOW CONNECTION`, logs, and error messages. Every request and redirect hop is
  egress-policy validated, and only 307/308 redirects are followed so a delivery is never silently
  downgraded to a body-less GET.
- Added an opt-in data-source capability for connector-side data-quality retention pruning, so
  `WITH (RETENTION = '...')` capture targets prune through the connector where supported.
- SFTP host-key verification is closed by default, with an explicit unpinned opt-out for lab or
  transitional environments.
- File-based schema lookup support was extended so `SHOW SCHEMA` can assist agents and authors with
  CSV/flat-file work.

## Performance

- Catalog fuzzy matching now avoids the old two-dimensional Levenshtein allocation pattern.
- Portal group membership is cached per scoped service by user, reducing repeated permission queries
  during catalog and report workflows.
- Variable interpolation uses compiled regexes in hot paths.
- Binary soft equality uses span sequence comparison.

---

## Security

- SFTP host-key verification now fails closed unless a host key is pinned or an explicit unpinned
  opt-out is configured.
- Cached schema responses re-check egress policy before returning metadata.
- Report access approvals grant report-level ACLs instead of broad folder ACLs by default.
- Access approvals and denials stage audit rows in the same unit of work as the access mutation.
- Stale-report refresh requests preserve permission boundaries: read-only consumers request owner
  action, while execute-capable users start a refresh.

## Bug Fixes

- Fixed EF migration/snapshot drift around report ACLs so SQLite and PostgreSQL migration validation
  no longer raises pending-model warnings.
- Removed an unnecessary standalone `ReportAcls.ReportId` migration index that did not match the
  EF model.
- Prevented repeated "My Default View" saves from creating duplicate saved-view rows.
- Prevented already-approved or already-denied access requests from being decided again.
- Corrected report-level ACL visibility gaps in catalog and saved-view endpoints.
- Fixed a false `SHOW DATASETS` parse failure, and unreserved `QUARANTINE` as a keyword so existing
  scripts using it as an identifier keep parsing.

## Upgrade Guide

1. Replace binaries and restart services.
2. Apply the Portal database migrations for your configured provider.
3. Review SFTP connections and add `HOST_KEY_FINGERPRINT` where missing.
4. Use the explicit `ALLOW_UNPINNED_HOST_KEY = 'TRUE'` opt-out only where an unverified connection is
   an intentional temporary choice.
