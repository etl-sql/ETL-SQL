# ETL-SQL v0.15.0

**Released:** 2026-07-12

ETL-SQL now adapts to your hardware at runtime, governs shared connections and secrets
without an external vault, and proves parser correctness through million-query fuzz campaigns.

---

## Release Summary

v0.15.0 makes ETL-SQL smarter about the machine it runs on and safer for teams that share
credentials. The **Adaptive Execution Controller** continuously monitors CPU, memory, and
spill-disk pressure to scale batch sizes and worker threads up or down without manual tuning.
**Shared Connection Governance** lets administrators define connections once in a catalog and
have developers reference them as `SHARED:alias` — credentials are resolved at execution time
and never visible to script authors. A new **correctness fuzzing harness** executes up to
1,000,000 generated queries against an in-memory `MOCKDB()` to catch parser and evaluator
regressions before they ship.

---

## ⚠️ Breaking Changes & Required Actions

- **`SECRET:` and `ENC:` references must be quoted.** Unquoted `SECRET:name` or `ENC:...`
  values in `CREATE CONNECTION` / `ALTER CONNECTION` now produce a parser diagnostic. Wrap
  them in single quotes: `PASSWORD = 'SECRET:sales_db_password'`.
  See [SME Secret Management Design](../architecture/decisions/SMESecretManagementAdministrationHardening.md), §5.
- **`.tmp` removed from allowed file extensions.** Scripts that write to `.tmp` files must
  use a supported extension or add the extension to the local policy allowlist.

---

## ⏳ Deprecations

- None in this release.

## Highlights

### Adaptive Execution & Resource Controller

**Audience:** Administrators · Evaluators

**Problem:** Tuning `BatchRows`, `WorkerDegree`, and memory grants manually is fragile —
settings that work for a 10 M-row load over-allocate on small jobs and under-allocate when
multiple pipelines run concurrently.

**Solution:** A process-wide controller samples six runtime signals every 250 ms and adjusts
setpoints using an AIMD (Additive Increase / Multiplicative Decrease) control law with
hysteresis:

| Signal | Source | Purpose |
| :--- | :--- | :--- |
| `CpuUtilization` | Process processor time (EWMA, α=0.3) | Detect CPU saturation |
| `MemoryLoad` | `GC.GetGCMemoryInfo()` container-aware load | Detect memory pressure |
| `GrantPressure` | `MemoryGrantArbiter` headroom | Detect grant contention |
| `Gen2Rate` | GC Gen2 collection frequency | Detect memory thrashing |
| `SpillWriteLatency` | `ISpillWriter` extent flush speed (ms/MB) | Detect disk bottleneck |
| `QueueDepth` | Producer/consumer batch queue depth | Detect pipeline stalls |

Under high contention (CPU > 90%, memory > 80%), setpoints are **halved immediately**. When
all signals are low for 8 consecutive cycles (~2 s), setpoints increment round-robin toward
their configured maximums. Concurrent jobs share budgets proportionally with per-job floors
to prevent starvation. A 1-second cooldown after every adjustment ensures the physical
impact is observed before the next change.

> **Design context:** See [AdaptiveExecutionController.md](../architecture/decisions/AdaptiveExecutionController.md)
> for the full control-loop model, signal definitions, and governance boundaries.

### Shared Connection Governance & SME Secret Hardening

**Audience:** Administrators · Script Authors

**Problem:** Small and midsize teams are stuck between insecure environment-variable
credentials and the operational overhead of running a dedicated enterprise vault. Developers
copy-paste server names and passwords into every script, making rotation painful and
credential leaks likely.

**Solution:** Three composable layers that work without an external vault:

1. **`OsSecretStore`** — CLI-managed secrets encrypted at rest with machine-scoped DPAPI
   (`LocalMachine` on Windows, machine-id-derived AES-256-GCM elsewhere). Service accounts
   can read admin-written secrets; filesystem ACLs protect against other local accounts.

   ```powershell
   etl-sql admin set-secret --name sales_db_password   # masked prompt
   etl-sql admin verify-secret --name sales_db_password
   etl-sql admin rotate-secret --name sales_db_password
   ```

2. **Portal Encrypted Secret Store** — For multi-node HA deployments that cannot operate a
   vault. Secrets are encrypted in the Portal database using the cluster-wide Data Protection
   key ring. A `secret-store-keyring` health check decrypt-probes every stored secret on each
   node to detect key-ring drift before it causes failures.

3. **Connection Catalog (`SHARED:` prefix)** — Administrators define approved connections
   centrally; developers reference them without seeing credentials:

```sql
CREATE CONNECTION sales AS MSSQL('SHARED:sales_prod');
SELECT TOP 100 * FROM sales.dbo.Orders;
```

   The declared connector type stays in the script so the linter and dialect checks work
   without catalog access. Credentials resolve at execution time under the caller's identity.
   Group-scoped ACLs (`SharedConnectionAcl`) restrict use to authorized groups; denials are
   audited. An **Impact Inventory** scans all report and job scripts for `SHARED:` / `SECRET:`
   references before an administrator can disable or delete an entry.

> **Design context:** See [SMESecretManagementAdministrationHardening.md](../architecture/decisions/SMESecretManagementAdministrationHardening.md)
> for the full storage model, syntax decisions, catalog record shape, and RBAC design.

### SQL Correctness Fuzzing & NoREC Differential Testing

**Audience:** Evaluators · Script Authors

**Problem:** SQL engines are notoriously hard to test exhaustively — the combinatorial
space of expressions, joins, aggregations, and window functions makes it easy for edge-case
bugs to survive hand-written test suites.

**Solution:** A multi-layered automated fuzzing harness:

- **`MOCKDB()` crash harness:** A pure in-memory test database that generates random schemas
  and executes up to 1,000,000 queries in under 5 minutes, checking for parser faults, memory
  leaks, and unhandled exceptions. Configurable via `ETLSQL_FUZZ_ITERATIONS`.
- **NoREC differential checks:** Compares optimized `COUNT(*)` queries against unoptimized
  `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` equivalents to detect logical evaluation mismatches.
- **Token corruption & AST mutation:** Randomly mutates syntax tokens (5% probability per
  query) and verifies the parser recovers with a structured `SyntaxException` rather than an
  unhandled crash. A recursive AST minimizer (`QueryMinimizer`) prunes crashing queries to
  minimal reproduction cases.
- **Coverage:** Windowing (`ROW_NUMBER`, inline frames, named `WINDOW` declarations),
  `QUALIFY`, `FILTER(WHERE ...)`, `ROLLUP`/`CUBE`/`GROUPING SETS`, `PARALLEL BEGIN...END`,
  transactional bounds, and system variables.

---

### Column-to-Column Interactive Lineage Engine

**Audience:** Report Consumers · Evaluators

**Problem:** Existing lineage displays show table-level relationships but cannot answer
"which source columns feed this specific report metric?"

**Solution:** A high-fidelity Vanilla JS column-to-column lineage graph with ReactFlow-style
node rendering, visual mapping ports, midpoint edge badges, and column-path isolation.
Supports cursor-pinned zoom, floating details sidebar, Ctrl+Click filtering, PII toggles,
inline transformation formulas, and recursive BFS column traces.

---

### High-Availability Soak Certification

**Audience:** Administrators · Evaluators

**Problem:** Multi-node HA clusters need confidence that lease fencing, job quarantine, and
node-crash recovery actually work under sustained production-like load — not just in
unit tests.

**Solution:** Native CLI commands (`etl-sql admin ha-soak`) drive sustained workloads with
fault-injection (simulated node crashes, network partitions, lease expiry) and collect
evidence bundles with PostgreSQL cluster synchronization telemetry and operator-run metrics.

> **Design context:** See [ConcurrentPostgresFailureSoak.md](../architecture/decisions/ConcurrentPostgresFailureSoak.md)
> for the soak runner topology, fault-injection scenarios, and evidence validation gates.

## Improvements

### Language & Engine
- Extended fuzzer query walks to advanced relational syntax: windowing functions, filtering
  clauses, and advanced grouping set combinations.
- Integrated recursive AST expression minimizer for crash reproduction.

### Connectors
- Sensitive connection metadata is now classifiable via `Governance:Secrets:SensitiveConnectionFields`
  organization policy. Designated fields become `SECRET:`-resolvable and are masked in
  `SHOW CONNECTION`, diagnostics, logs, support bundles, and lineage exports.

### Native Admin Background Services
- Daily failure digest, backup outcome reporting, and capacity/free-disk monitoring are now
  native Portal/Orchestrator background services with HA singleton leases, retry/backoff,
  history retention, and SMTP notification — replacing the previous sample-script templates.
  Samples remain as examples with a README pointing at the native path.

## Performance

- **+74% throughput, −63% GC allocations** at scale (10 M / 50 M rows and 1B certification)
  under massive partition spilling. Met Gate F round-trip performance benchmarks.
- **1-second setpoint cooldown** enforced after every adaptive control change to ensure the
  runtime observes the physical performance impact before adjusting again.

---

## Security

- **Quoted `SECRET:`/`ENC:` enforcement:** Parser now rejects unquoted secret/encryption
  references and emits a targeted "must be quoted" diagnostic. `SecretReferenceUsage` lint
  rule flags references on non-resolvable fields.
- **Sensitive metadata masking:** Organization policy can classify non-password fields (HOST,
  BUCKET, PATH, etc.) as sensitive — masked through all display, diagnostic, and export
  surfaces without hiding them globally.
- **Portal secret store:** Encrypted at rest in the Portal database with cluster-wide Data
  Protection keys. Values are never returned after write. `verify-all` provides backup/restore
  validation without printing secrets.

---

## Bug Fixes

- Parser now cleanly handles `GROUP BY ALL` with star-modifiers (`* EXCLUDE (...)`) and
  qualified stars (`t.*`) instead of crashing during column expansion.
- Positional reference checks correctly block star projections from bypassing sorting/grouping
  syntax validation.

---

## Known Issues

- **Billion-row operator certification remains Candidate.** External sort and equi-join
  scenarios have implemented candidate paths but 1B operator-run artifacts have not yet
  passed on reference hardware. See [BillionRowOperatorCertification.md](../architecture/decisions/BillionRowOperatorCertification.md).
- **Heterogeneous `MERGE` at 1B is Not Certified** pending a bounded source/target staging
  design.

## Upgrade Guide

Standard upgrade — replace binaries and restart services. No configuration changes required.

If you have unquoted `SECRET:` or `ENC:` references in scripts, wrap them in single quotes
before upgrading to avoid parser diagnostics:

```sql
-- Before (no longer accepted)
PASSWORD = SECRET:my_password

-- After
PASSWORD = 'SECRET:my_password'
```
