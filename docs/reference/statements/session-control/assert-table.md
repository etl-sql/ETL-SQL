# ASSERT TABLE

Asserts that two tables or #temp datasets have matching schema, column structure, row counts, and data values.

`ASSERT TABLE` is designed for native unit testing and regression testing of data pipelines. When two datasets diverge, it prints an actionable side-by-side or +/- diff highlighting schema drift, row count differences, and specific mismatched cell values.

## Syntax

```sql
ASSERT TABLE <actual_table> MATCHES <expected_table>
[WITH (
  [IGNORE_ORDER = TRUE | FALSE,]
  [TOLERANCE = <numeric_bound>,]
  [IGNORE_COLUMNS = '<col1>,<col2>',]
  [MESSAGE = '<custom_error_message>']
)];
```

## Options

- **IGNORE_ORDER = TRUE | FALSE** — When `TRUE`, treats both datasets as unordered multisets and matches rows without requiring strict positional index alignment. Defaults to `FALSE`.
- **TOLERANCE = n** — Numeric tolerance threshold for floating point / decimal comparisons (e.g. `TOLERANCE = 0.001`). Differences `<= n` are treated as matching.
- **IGNORE_COLUMNS = 'col1,col2'** — Comma-separated list of column names to exclude from schema and data comparison (e.g. dynamic timestamps or autogenerated IDs).
- **MESSAGE = '...'** — Custom failure message to include in the error diagnostic payload when assertion fails.

## Examples

### Exact Table Equality

```sql
-- Compare staging output with expected gold standard
ASSERT TABLE #actual_customers MATCHES #expected_customers;
```

### Unordered Matching with Numeric Tolerance

```sql
ASSERT TABLE #actual_aggregates MATCHES #expected_aggregates WITH (
  IGNORE_ORDER = TRUE,
  TOLERANCE = 0.01,
  IGNORE_COLUMNS = 'calculated_at',
  MESSAGE = 'Aggregated revenue pipeline verification failed'
);
```

## CLI Test Runner

Execute native test suites matching `*.test.etlsql` or `*.test.sql`:

```bash
# Run all discovered tests in the project
etl-sql test

# Run a specific test file or directory
etl-sql test samples/unit_test_table_assertion.test.etlsql

# Output test outcomes in structured JSON format
etl-sql test --json
```
