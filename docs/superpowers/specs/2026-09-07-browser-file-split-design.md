# Splitting the two large browser files

Design for [the completed browser split](../../releases/v0.20.0-browser-split-baseline.md). Covers
`designer/designer.js` (9,008 lines) and `report-runtime.js` (9,668 lines).

## Why

v0.19.0's type gate found twelve live browser defects; three were scope confusion, and all three were
inside these two files. A file nobody can hold in context is where a name gets used before it is
declared and no reviewer notices. The goal is files that fit in one reading, not a smaller line count.

## Decisions taken

Four decisions were made during brainstorming and are recorded here because each one overrides a
default a later reader would otherwise assume.

1. **`report-runtime.js` becomes real ES modules, with a generated single-file bundle for offline
   snapshots.** This overrides TODO §2's "no bundler is required for this slice". The alternative
   considered was splitting into namespaced IIFEs, which needs no bundle but routes every cross-part
   call through a `window` namespace object — indirection of exactly the kind that hid the scope
   defects this work exists to prevent. TODO.md must be updated to say so rather than left in drift.
2. **The bundle is generated by `scripts/sync-assets.js`, checked in, and drift-gated.** No new build
   machinery, no Node in the .NET build graph, and the snapshot's actual content stays reviewable in
   a diff.
3. **Granularity is one module per concern** — roughly 300 to 1,000 lines each.
4. **Only pure extractions in this slice.** `createDesigner`, `createScriptEditorWorkbench` and
   `createStudioWorkbench` are closures over mutable state; their stateful interiors stay put. See
   [Deliberately out of scope](#deliberately-out-of-scope).

## Invariants

These hold for every commit in this work.

- **Behavior-preserving.** Moves only. No renames, no signature changes, no drive-by fixes. A
  reviewer must be able to confirm a hunk is a cut-and-paste.
- **Both gate baselines stay comment-only.** `browser-lint-baseline.txt` and
  `browser-typecheck-baseline.txt` carry zero live findings today. The split must neither add an
  entry nor need one removed.
- **Part modules use a constrained export style**, because the bundler's transform depends on it:
  named `export` on declarations only. No `export { ... }` lists, no `export default`, no
  re-exports, no dynamic `import()` of a sibling part.
- **New parts are siblings in the same directory** as the entry module. `sync-assets.js` discovers
  files by walking `Resources/Shared`, so sibling parts sync to all five hosts with no change to its
  copy logic.

### Cycles are expected here, and are safe

Modules 12 through 16 form a cycle: `rt-visual` calls into `rt-charts` and `rt-detail`, `rt-layout`
renders visuals, `rt-actions` navigates pages which re-renders layout, `rt-chrome` triggers actions.
Breaking it requires a dispatch registry — a behavior-bearing change explicitly excluded from this
slice.

The cycle is safe because of two properties, both of which must be preserved:

- Every cross-part binding is a hoisted `function` declaration or a `const` that is never read during
  module evaluation.
- Nothing runs at module-eval time. Every entry point into the cycle is reached from `boot()`, which
  runs on `DOMContentLoaded`.

This reasoning goes in a comment at the top of `rt-visual.js`, not only in this spec. A future
`const foo = () => {}` in place of `function foo()` inside the cycle would break it silently, and a
spec nobody opens will not stop that.

## The offline-snapshot bundle

`OfflineSnapshotViewer.cs` writes a `.etlsnap` as one self-contained file with the runtime inlined
into a single `<script>` tag. A single file has no siblings to `import`, so the parts are
concatenated into `report-runtime.bundle.js`.

**Generator.** `scripts/sync-assets.js` gains a bundle step that runs before the sync walk:

1. Read the part files in the declared order above. The order lives in one array in `sync-assets.js`;
   a part file present on disk but absent from the array is an error, so adding a part cannot
   silently omit it from snapshots.
2. Delete lines matching an intra-bundle import — `import { ... } from './rt-*.js';`. Imports of
   anything else are an error, because a real external dependency cannot survive concatenation.
3. Strip the leading `export ` from `export function`, `export async function`, `export const`,
   `export let`, `export class`. Any other `export` form is an error — this is what the
   constrained-style invariant buys.
4. Concatenate in order, wrap in `(function () { 'use strict'; ... })();`, and prepend a generated-file
   banner matching the one host copies already carry.
5. Write `report-runtime.bundle.js` beside the parts.

**Gating.** In `-Check` mode the step recomputes the bundle and reports drift instead of writing,
joining the existing `drift[]` list. The bundle is therefore covered by the gate that already runs,
with no new gate and no new CI wiring.

**Consumer.** `ETL-SQL.Reporting.csproj` changes its `EmbeddedResource` from `report-runtime.js` to
`report-runtime.bundle.js`, keeping `LogicalName` `runtime.report-runtime.js` so
`OfflineSnapshotViewer.cs` is untouched.

**Self-check.** The bundle must be verified to parse and to expose `window.__reportRuntime__`, not
merely to have been produced. A JSDOM assertion in the vitest suite covers this; a bundle that
concatenates cleanly but throws on load would otherwise reach a snapshot silently.

| `ETL-SQL.Reporting` snapshot | unchanged; consumes the bundle |

### The CSP change is load-bearing

`reportPreviewPanel.ts` sets `script-src 'nonce-${nonce}'`. A nonce does **not** propagate to modules
fetched by an `import` statement, so the moment the runtime imports a sibling, the webview preview
breaks with a CSP violation and no other symptom. `visualFlowPanel.ts` — the existing module webview
in the same extension — already sets `script-src ${webview.cspSource} 'nonce-${nonce}'` for this
reason. The fix is to copy that line.

### Module scripts are deferred

A `type="module"` script executes after parsing, whereas a classic script executes inline. The
runtime's boot guard already handles both:

```js
if (document.readyState === 'loading') { document.addEventListener('DOMContentLoaded', boot); } else { boot(); }
```

Under `type="module"` the second branch is taken. The behavior is the same; this is noted so it is
not rediscovered as a suspected regression.

The dynamic-injection hosts set `window.__MANIFEST__` before appending the script element, which
still holds — deferral makes the ordering safer, not less safe.

## `.gitattributes`

The file currently pins LF one bare filename per line. Bare names match at any depth, which is how
the five host copies are covered today. Adding roughly twenty part files that way is a trap: omit
one and the drift gate passes for everyone except a fresh clone with `core.autocrlf=true`, where it
fails with no clue why.

Replace the enumerated JS/CSS entries with path globs over the canonical directory and each host
copy root:

```gitattributes
src/ETL-SQL.ReportRuntime/Resources/Shared/**    text eol=lf
src/ETL-SQL.Portal/wwwroot/**/*.js               text eol=lf
src/ETL-SQL.Portal/wwwroot/**/*.css              text eol=lf
src/ETL-SQL.ReportPlayer/wwwroot/**              text eol=lf
src/ETL-SQL.WorkstationEditor/wwwroot/**         text eol=lf
src/etl-sql-vscode/media/**                      text eol=lf
```

Existing `*.min.js` and binary rules keep precedence per normal `.gitattributes` ordering. Verify
with `git ls-files --eol` on the canonical directory after the change, not by reading the file.

## Deliberately out of scope

Recorded so they are not re-litigated, and so the follow-up is not lost.

- **The stateful closure interiors.** `createDesigner` lands at roughly 3,200 lines,
  `createScriptEditorWorkbench` and `createStudioWorkbench` are untouched. Extracting them needs a
  context object threaded through every reference to shared state — a restructure that would make a
  reviewer unable to distinguish a move from a change. **This needs a follow-up TODO item.**
- **`studio.js` (315 KB) and `studio-authoring.js` (149 KB).** Larger than `designer.js` on disk but
  not named in TODO §2, and not implicated in the v0.19.0 defects. Out of scope for this item;
  worth raising as a candidate.
- **Breaking the render cycle** via a dispatch registry.
- **Sub-module cache busting.** `EditorShell.cs` and `StudioShell.cs` append `?v={SessionToken}` to
  the entry module URL; sibling imports do not inherit it. This gap already exists for
  `visual-preview.js` and the thirteen `studio-*.js` modules, so the split widens a known gap rather
  than creating one. Not fixed here.
- **`AssetFingerprinter.cs`** rewrites asset references found in `.html` files only, so it never
  reached sibling modules and still does not. Same pre-existing gap; not fixed here.

## Sequencing

1. `.gitattributes` globs first, verified with `git ls-files --eol`. Doing this last risks a
   whole-tree line-ending churn on top of the move.
2. `designer/` split, including the two pure extractions. Independently shippable.
3. `report-runtime/` split, bundle generator, host wiring, CSP fix, consumer test fixes.
4. Update TODO §2 to record decision 1, and add the follow-up item for the closure interiors.
