# ETL-SQL Development TODO List

## Bugs
### Security / Zero-Trust
- [x] Split file prefix can escape the validated destination directory → Fixed: `SplitFileStatementHandler` now rejects empty/rooted/path-traversal prefixes, validates each generated part path with `ValidatePath`/`ValidateWriteAccess`/`ValidateFileType`, and verifies every part remains under the resolved destination directory. Added `TestSplitFileRejectsUnsafePrefix`.
- [x] LDAP portal auth still contains diagnostic console/file logging that leaks directory details and bypasses configured logging → Fixed: removed `[LDAP-DIAG]` console writes and all hard-coded `ldap_debug.txt` writes; LDAP diagnostics now use structured `ILogger` with sanitized message text.
- [x] SharePoint connector prints request URLs and may expose site/library/file paths in logs → Fixed: removed `System.Console.WriteLine("[TEST-PRINT] ...")` calls from SharePoint file listing/download paths and removed the mock handler print in connector tests.
- [x] Portal refresh tokens remain valid after a user is disabled → Fixed: `AuthController.Refresh` now rejects and revokes refresh tokens for inactive users, and admin deactivation revokes outstanding refresh tokens. Extended the deactivated-user portal regression test to cover refresh.

### Connectors
- [x] SharePoint connector documentation says `PASSWORD`/`CLIENT_SECRET` can use `ENC:`, but the implementation does not decrypt them → Fixed: SharePoint `AD_WINDOWS` password and Entra `CLIENT_SECRET` now decrypt `ENC:` values through the execution context, and SharePoint provider response bodies are no longer reflected in credential-sensitive errors.
- [x] New connector option aliases violate the no-alias connector standard → Fixed: removed S3 `ACCESSKEY`/`SECRETKEY`, Active Directory `LDAPS`, Kafka `SERVERS`, and MongoDB `URI`/`SERVER`/`UID`/`DB` option fallbacks; updated help/docs/snippets and added metadata assertions.

### File Operations
- [x] `MERGE FILES` can destroy an existing destination when the source pattern matches nothing → Fixed: source files are now resolved before destination replacement; zero matches throw and leave the destination unchanged. Added `TestMergeFilesNoMatchesPreservesDestination`.
- [x] `SYNC DIRECTORY DELETE_EXTRA` bypasses the file-operation guardrail spirit and under-counts destructive work → Fixed: `DELETE_EXTRA` now validates file types, increments file-operation counts for each file/directory delete, and checks recursive depth before recursive sync traversal.

### Engine / SQL Semantics
- [ ] Recursive CTE numeric columns widen to decimal-style values when materialized → The `recursive_cte_hierarchy_rollup` scenario currently observes values like `EmployeeId = 1.0` and `Depth = 0.0` even though the anchor query uses integer literals/source columns. Decide whether this widening is acceptable recursion arithmetic behavior or preserve the anchor/source integer shape through recursive CTE materialization before making strong type-fidelity claims.

### Report Portal
- [x] Structure DAG jumbled on large maps → Fixed: `render()` in `designer.js` now computes a fit-to-view zoom from the actual node bounding box (`min(containerW/dataW, containerH/dataH, 1.0)`, floor 0.15) so all nodes are visible on first open regardless of graph size. `roam: true` still lets users pan/zoom further.
- [x] Dependencies transformation column shows only category name → Fixed: `formatTransformationKind(kind, expr, fns)` now shows the actual function names for Aggregation/FunctionCall (e.g. "SUM", "COUNT", "UPPER()"), extracts the target type for Cast (e.g. "→ INT"), and keeps the full expression as a hover tooltip.
- [ ] Structure DAG emits no page→visual edges when visuals are declared before pages → In `GetStructure` (`ReportsController.cs`), `currentPage` is assigned by statement iteration order, so a report that declares every `CREATE VISUAL` before any `CREATE PAGE` (e.g. `samples/10_Kitchen_Sinks/report_kitchen_sink.rptsql`) leaves all visuals with `page = null` and produces zero page→visual edges — pages render as orphan nodes. Page membership should come from each page's layout (which visuals it references), not declaration order.
- [x] Report designer generates invalid dataset syntax → Fixed: `DesignerController.StateToScript` now emits `CREATE DATASET &name` and `SOURCE = &name` for report datasets. Added `DesignerControllerTests.Generate_UsesReportDatasetIdentifiers`.

### Lineage
- [x] `CREATE DATASET` column lineage was keyed to the generic `RESULTSET` target → Fixed: `LineageAnalyzer` (via `_selectTargetOverride`) and runtime `LineageManager.RecordCreateDatasetLineage` now record the inner SELECT's column lineage against `dataset:{name}`, carrying source columns + inherited descriptions/tags, so dataset column lineage persists and resolves by name across scripts. Tests: `LineageAnalyzerTests.Analyze_CreateDataset_KeysColumnLineageToDatasetName`, `EvenMoreHandlerTests.CreateDataset_RecordsReportObjectLineage`.
- [x] `LineageHistory` persistence dropped column-level fidelity → Fixed: store now persists + reads back `SourceColumns`, `TransformationKind`, `TransformationExpression`, `FunctionsApplied`, `DerivedFromDescriptions` (schema + ALTER migration + `SaveLineageAsync` + all read queries + `LineageHistoryEntry`). Test: `LineageCatalogTests.SaveAndQuery_PersistsColumnTransformAndDescription`.
- [x] Structure detail panel couldn't cross script boundaries to a separately-built dataset → Fixed: `GetStructure` `BridgeDatasetLineageAsync` resolves dataset references by stitching the registered `SourceQuery` parse (transform + source columns) with the persisted lineage catalog (description/tags), and propagates pass-through columns to `SELECT *` consumers. Verified end-to-end against the real portal endpoint + stores by `PortalIntegrationTests.Structure_BridgesDatasetReferenceAcrossScripts` (register dataset + persist build lineage → `GET /structure` resolves `total = SUM(Amount) ← edw.Sales.Amount` with description + pii across the boundary). Also fixed: a bare `SELECT *` consumer was recording a junk `"*"` column that blocked the bridge — `GetStructure` now skips `"*"` columns so the dataset's real columns propagate.
- [x] Descriptions required manual ETL-SQL tagging, not a live source-DB column comment → Fixed (opt-in): when `Lineage:ImportCatalogMetadata` is on (appsettings.json) or `SET LINEAGE_IMPORT_CATALOG = ON`, the engine lazily imports a DB source table's catalog metadata the first time it's read (`Evaluator.EnsureCatalogMetadataImportedAsync`, called from the `SELECT INTO` / `CREATE DATASET` handlers before lineage is recorded). A column's native comment is recorded as the lineage description (`d`) — not a `db_description` tag — so it inherits onto derived columns and surfaces in the structure panel. SQL Server/PostgreSQL/MySQL catalog providers already read comments. **Off by default** to avoid catalog-query latency; documented prominently in the Administrator's Guide and User Manual. Verified: `LineageAnalyzerTests.Analyze_InheritsDbColumnDescriptionOntoDerivedColumn` (comment → `d` → inherits onto a derived column with pii). The live provider read (`sys.extended_properties` etc.) and the evaluator lazy-hook firing remain integration-verified (real DB / Docker). Oracle/Snowflake/BigQuery catalog providers can be added later to extend coverage.
- [x] Surface the new persisted lineage fields in the catalog Lineage view → Fixed: `CatalogLineageHistoryDto` + `CatalogController.ToLineageDtosAsync` now expose `SourceColumns`, `TransformationKind`, `TransformationExpression`, `FunctionsApplied`, `DerivedFromDescriptions`; the portal Lineage view (`renderLineageRow`) shows a transform badge, source columns, and the inherited description, and the CSV export includes Transform + Description. Verified by `PortalIntegrationTests.CatalogLineageEndpoints_ReturnHistoryWithReportContext` (rich fields round-trip persist → store → DTO → JSON).
