# Enterprise Release Evidence Checklist

Status: Prepared checklist, not release evidence.

This checklist defines the evidence required before the v0.16.0 enterprise release-suite TODO can be
closed. Fast tests are useful contract checks, but the enterprise release gate requires current
operator evidence from the full functional, performance, migration, recovery, enterprise
certification, and standalone regression suites.

## Evidence Record

Create a release evidence folder for each candidate build:

```text
artifacts/release-evidence/<version>/
```

The folder should include command transcripts, test result files, recovery reports, HA soak summaries,
configuration manifests with secrets redacted, and links to CI runs where applicable. Do not store raw
secret values, connection strings, private keys, `ENC:` payloads, or `SECRET:` references in evidence.

## Required Suites

| Gate | Command or Evidence | Required Artifact | Pass Criteria |
| :--- | :--- | :--- | :--- |
| Functional fast lane | `.\scripts\test-lane.ps1 -Lane fast -NoRestore` | Test transcript and result summary | No failed tests; skipped tests are explained. |
| Full pre-release lane | `.\scripts\Test-PreRelease.ps1 -IncludeSlt -IncludeDockerIntegration -IncludeStandardScale -BuildInstallers -Platforms win-x64` | Pre-release transcript, packaged artifact list, installer hashes | No failed phases; packaging output matches expected version. |
| Migration and upgrade | `.\scripts\Test-PreRelease.ps1 -IncludeSlt -Explain` plus N to N+1 upgrade-path evidence | Migration logs and upgrade-path summary | Forward migrations succeed without data loss or manual catalog edits. |
| Enterprise hardening | `.\scripts\Test-EnterpriseHardeningCertification.ps1` on Windows and Linux | Certification transcript and policy/audit evidence | Enrollment, signed policy, standalone behavior, boundary enforcement, and security delivery pass. |
| Recovery drill | `etl-sql admin restore --validate --report recovery-report.json` | Recovery report JSON and drill transcript | Report records achieved RPO/RTO, missing dependencies, data-loss window, and operator actions. |
| HA failure certification | `etl-sql admin ha-soak fault-run` and `etl-sql admin ha-soak validate` | Fault-run transcript, validation report, node logs | No duplicate ownership, lost mutation, hidden environment failure, or unsafe ready node. |
| Scale and performance | `.\scripts\Test-ScaleCertification.ps1 -Tier Smoke`; Standard tier when advertising scale claims | Scale transcript, counters, spill/memory summary | Bounded-memory behavior and published scale claims are supported by measured evidence. |
| Standalone regression | `dotnet test tests\ETL-SQL.Tests\ETL-SQL.Tests.csproj --filter FullyQualifiedName~StandaloneRegressionTests` | Test result summary | Unenrolled hosts remain unrestricted by enterprise policy. |
| Security boundary docs | `dotnet test tests\ETL-SQL.Tests\ETL-SQL.Tests.csproj --filter FullyQualifiedName~SecurityBoundaryDocTests` | Test result summary | Documentation does not overclaim OS-level containment or remote fleet authority. |

## Acceptance Rules

- Evidence must be from the exact candidate commit or a documented rebuild of the same source state.
- Failures cannot be waived silently. Each failure needs an owner, risk decision, and retest evidence.
- Long-running Docker, HA, Standard-scale, and enterprise certification runs must identify the host
  topology, operating system, database/storage versions, and any external service dependencies.
- Recovery evidence must include the machine-readable report generated by `--report`.
- Security-review evidence must link to the signed
  [Enterprise Security Review Packet](Enterprise_Security_Review_Packet.md).
