## Smoke scale-certification — deferred (no trustworthy reading this session)

The smoke scale-cert baseline check could not be given a clean read during the v0.15.0 release
window: the workstation was under **concurrent interactive load** (other work running alongside the
release gate). Under that load the small (50k–100k row) micro-benchmarks were unreliable, and the
apparent regressions were **not stable**:

- The failing scenario **moved between runs on identical code** — `ExternalSort_50000_DESC` and
  `ExternalAggregate_100000_10grps` on one run, `CubeGroupingSets_50000_10x5` on the next (which had
  *passed* the prior run), `StreamingSelect_100000_cap50000` on a 5-sample run.
- `PEAK_WORKING_SET_MB` was inflated +10–15% across several unrelated scenarios simultaneously.
- Increasing samples (1 → 5) did **not** stabilize the result (sustained-load throttling).

This is the signature of environmental variance, not a confirmed code regression. An earlier attempt
to accept + bless `ExternalSort`/`ExternalAggregate` was **reverted** — those readings came from the
same loaded session and cannot be trusted.

**Decision (maintainer, 2026-07-12):** the smoke/standard scale-cert phases were skipped for the
v0.15.0 pre-release gate (`Test-PreRelease.ps1 -SkipScale`). This is a **local-only** gate phase —
CI, CodeQL, and the Release workflow do not run it — so the release itself is unaffected. All
functional lanes (build, unit/LSP/portal tests, SLT incl. the columnar `ALTER` fix, VS Code package,
HA soak contract, Docker integration) passed. The checked-in `baseline-smoke.json` is left at its
last known-good 2026-07-05 values (bless reverted).

**Update (2026-07-13) — CONFIRMED regression.** Re-ran smoke certification on a **quiescent** machine
with a 5-sample median. The core regression persists (it was partly, not wholly, load):

| Scenario | Metric | Baseline (07-05) | Quiet 5-sample | Δ | Band |
| :--- | :--- | ---: | ---: | ---: | ---: |
| `ExternalSort_50000_DESC` | elapsed | 462 ms | 603 ms | **+30.5%** | fail 25% |
| `ExternalAggregate_100000_10grps` | GC pause | 14.6 ms | 21.7 ms | **+48.6%** | fail 35% |
| `ExternalSort_50000_DESC` | rows/s | 108,225 | 82,919 | −23.4% | warn 12% (was fail under load) |

So `ExternalSort` (and the aggregate GC pause) are a **genuine** regression vs the ~v0.14.0-era
baseline, not measurement noise. The baseline is **not** re-blessed (that would bury it). Next step:
bisect the external-sort / spill path across the v0.15.0 range to pin the cause, optimize, then
re-bless from the recovered numbers. `SpillStore` (+236 lines in v0.15.0) and the external-operator
plan-decision instrumentation are the starting suspects.
