## Accepted regression — external sort/aggregate spill (ACCEPTED, tracked for v0.16.0)

The smoke scale-certification baseline check flagged a **real, reproducible** regression in the
disk-spilling external operators versus the 2026-07-05 baseline. Same machine, same ServerGC + 2048 MB
grant; reproduced across three runs, so it is not measurement noise, hardware, or config drift.

| Scenario | Metric | Baseline (07-05) | v0.15.0 | Δ | Fail band |
| :--- | :--- | ---: | ---: | ---: | ---: |
| `ExternalSort_50000_DESC` | elapsed | 462 ms | 631 ms | **+36.6%** | 25% |
| `ExternalSort_50000_DESC` | rows/s | 108,225 | 79,239 | **−26.8%** | 25% |
| `ExternalAggregate_100000_10grps` | GC pause | 14.6 ms | 29.5 ms | **+102%** | 35% |

**Root cause:** not yet pinned. The obvious suspect — new plan-decision instrumentation
(`25843a58`, `PlanDecisionRecorder.Record`) — was ruled out: `Record` runs once per operator
invocation and is trivially cheap. The regression is diffuse across the engine/spill changes between
the baseline and `cfa51038`, and needs a bisect or profile to isolate.

**Decision (maintainer, 2026-07-12):** accepted for v0.15.0 — the magnitudes are small in absolute
terms (a 50k-row micro-benchmark) and do not warrant holding the release. The smoke baseline
(`certification-results/baseline-smoke.json`) was re-blessed to the measured v0.15.0 values for the
three affected metrics so the gate reflects reality; all other scenarios and the per-scenario bands
are unchanged.

**Action for v0.16.0:** bisect `2026-07-05 → cfa51038` on `ExternalSort_50000_DESC` /
`ExternalAggregate_100000_10grps` to pin the regressing change, then restore the prior throughput /
GC-pause profile and re-bless the baseline to the recovered numbers.
