## ETL-SQL v0.15.0

This release introduces the **Adaptive Execution Controller**, **Shared Connection Governance**, **SME Secret Storage Hardening**, **High-Availability Soak Certification**, and **NoREC Correctness Fuzzing**.

---

### Highlights

#### 1. Adaptive Execution & Resource Controller (Phase 2)
To optimize resource usage dynamically based on runtime signals rather than static configurations, v0.15.0 introduces a bounded, observing controller. It shifts runtime setpoints inside operator-configured and governance-locked boundaries.
* **Observe-and-Adapt Engine:** A DI-managed process-wide `AdaptiveExecutionController` samples system load metrics every 250ms via a periodic timer.
* **Dimension Signals Sampled:**
  - `CpuUtilization`: EWMA (exponentially weighted moving average, $\alpha=0.3$) based on process processor time.
  - `MemoryLoad`: GC container-aware memory load percentage via `GC.GetGCMemoryInfo()`.
  - `GrantPressure`: Headroom from the core `MemoryGrantArbiter`.
  - `Gen2Rate`: GC collection rate monitoring to detect memory thrashing.
  - `SpillWriteLatency`: Write speed (ms/MB) reported by `ISpillWriter` extent flushes.
  - `QueueDepth`: Pending batches in internal producer/consumer boundaries.
* **Control Law (AIMD with Hysteresis):** 
  - **Multiplicative Decrease:** Under high contention (e.g. CPU > 90%, memory load > 80%), setpoints like batch sizes (`BatchRows`), operator grants (`OperatorGrantRequestMB`), and worker threads (`WorkerDegree`) are immediately halved.
  - **Additive Increase:** When all metrics are low for 8 consecutive cycles (~2 seconds), the controller increments setpoints round-robin toward their configured limits.
  - **Fairness Setpoints:** When multiple concurrent jobs run, the controller divides memory budgets and processor quotas proportionally (`1 / activeJobs`) with per-job floors to prevent resource starvation.

#### 2. Shared Connection Governance & Secrets Hardening (Phase 7)
Fills the security gap between putting plaintext credentials in environment files and operating a separate heavy enterprise vault.
* **Machine-Scoped Secret Storage:** Local secrets managed via `OsSecretStore` are encrypted at rest with `CryptoUtils.ProtectMachine` (using Windows DPAPI `LocalMachine` or a machine-id-derived AES-256-GCM elsewhere) so service accounts can read admin-written secrets, secured by local filesystem ACLs.
* **Portal Encrypted Secret Store:** Multi-node HA setups can store encrypted secret keys and values directly in the Portal database, validated by a `secret-store-keyring` liveness check on each node.
* **Connection Catalog (`SHARED:` Prefix):** Approved connections are defined centrally by admins and referenced in scripts as `CREATE CONNECTION c AS MSSQL('SHARED:sales_db')`. Credentials (`SECRET:name` references) are resolved at execution time under the caller's identity and never exposed to the developer.
* **Group-Scoped Access (`SharedConnectionAcl`):** Connection catalog entries support group-scoped ACL grants. Users without permissions are blocked from utilizing the connection at the parser boundary.
* **Impact Inventory:** The `ReferenceImpactService` dynamically scans report and scheduled job scripts for `SHARED:` and `SECRET:` references to build an active impact analysis map before an administrator disables or deletes a connection.
* **Sensitive Metadata Masking:** Ad-hoc hostnames, port details, and bucket names can be classified as sensitive via `Governance:Secrets:SensitiveConnectionFields` policies, masking them in all diagnostics, logs, support bundles, and `SHOW CONNECTION` statements.

#### 3. High Availability (HA) & Soak Certification (Phase 6)
To support multi-node production safety, a native HA testing infrastructure has been integrated.
* **Large-Job Soak & Fault-Injection Runners:** Native CLI commands (`etl-sql admin ha-soak`) manage scheduled workloads, lease fencing, and simulated node crash recovery.
* **Diagnostics Bundling:** Generates HA metrics snapshots, PostgreSQL cluster synchronization telemetry, and operator evidence bundles.

#### 4. NoREC Correctness & Parser Fuzzing
* Shipped the pure in-memory `MOCKDB()` testing database designed to execute up to 1,000,000 queries in under 5 minutes to test parser edge cases.
* **NoREC Differential Checks:** Evaluates optimized count queries against unoptimized case-when sum queries on `MOCKDB()` to assert logical execution parity.
* **Mutation & Token Corruption Fuzzing:** Randomly mutates AST syntax to verify the lexer/parser throws graceful `SyntaxException` diagnostics rather than unhandled index crashes.

### Performance

- **Allocation Budgets & Spill Churn Reduction** — Met Gate F performance benchmarks: +74% throughput, -63% GC allocations at scale (10M / 50M rows and 1B scale certification) under massive partition spilling.
- **Setpoints Cooldown** — A 1-second delay is enforced after any control setpoint change to ensure the runtime observes the physical performance impact before adjusting levers again.
