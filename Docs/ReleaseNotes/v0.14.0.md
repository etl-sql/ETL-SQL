## ETL-SQL v0.14.0

This release delivers the foundation for **Billion-Row Columnar Execution**, **Row-Level Security (RLS)**, and **Enterprise Policy Enforcement and Monitoring**.

---

### Highlights

#### 1. Billion-Row Columnar Execution Foundations
To support high-throughput, large-scale query processing, the engine has been refactored from traditional row-at-a-time evaluation to a vectorized columnar approach.
* **Segmented `#temp` Storage Engine:** Implements a native, append-only segmented `#temp` database engine utilizing `ColumnBatch` buffers. This bypasses the memory allocation and boxing overhead of standard C# `DataRow` and `DataTable` types.
* **Process-Wide RAM Governor:** A centralized Memory Grant Arbiter coordinates memory allocation for memory-intensive operations (external sort, hash join, distinct, aggregation, and window queries), dynamically partitioning and limiting RAM grants per operator.
* **Extents-Based Spilling:** Partition spilling has been optimized to stream sequential extents targeted at 128 MB blocks, which minimizes OS file handle thrashing and speeds up NVMe transfer paths.
* **Double-Buffered Pipelining:** Overlaps background extent disk writes with foreground memory chunk evaluation to keep CPU cores active during heavy spills.
* **Scale Certification Tiers:** Introduces formal scale test limits: Smoke (1 GB), Standard (4 GB / 10M rows), Stress (8 GB / 5M rows), and Huge (16 GB / 50M rows).

#### 2. Row-Level Security (RLS) & Impersonation (Phases 1 & 2)
Introduces robust, unforgeable row-filtering predicates based on the caller's active identity.
* **Injected System Variables:** Surat-injected variables that are managed strictly outside user-controlled parameter namespaces:
  - `@@CURRENT_USER` / `@@CURRENT_USER_ID`: The effective principal running the query.
  - `@@REAL_USER`: The actual authenticated actor (remains unchanged during administrative run-as impersonation).
  - `@@IS_ADMIN`: Flag determining administrative status.
* **Predicate Primitives:** Standardized set-membership checks `HAS_GROUP('name')` and `HAS_ROLE('name')` to prevent buggy substring matches (`LIKE`), along with table-valued functions `USER_GROUPS()` and `USER_ROLES()` for SQL subquery filtering.
* **Immutability Enforcement:** The compiler actively rejects statements trying to declare or write to system variables (`DECLARE @@CURRENT_USER`).
* **Identity-Sensitive Scan:** The engine automatically scans script ASTs for RLS variables and functions. When detected:
  - **Shared snapshots are disabled** to prevent user A's data from being cached and served to user B.
  - **Subscriptions are executed per-recipient** to evaluate the predicates against each subscriber's unique rights.
* **Publisher Preview-As:** Report authors can preview RLS reports by simulating specific target groups (e.g. `Region:East`), which gates the data output to test filter behaviors safely during design.

#### 3. Enterprise Policy Enforcement & Monitoring (Phase 3)
Allows organization-wide policies to be distributed securely to all runner machines.
* **Policy Authority API (`api/admin/policy-authority`):** Administrator-only endpoints to publish, sign, roll back, and audit tenant organization policies.
* **Signed Distribution Envelopes:** Enrolled machines fetch signed policy configurations via OIDC-authenticated headers, verifying key signatures before loading.
* **Governed Connector Egress:** Enforces egress destination host, scheme, and port allowlists at connect time, disabling ambient proxies and pinning DNS socket mappings to block DNS-rebinding or proxy-bypass attacks.
* **Governed Resource Ceilings:** Global boundaries for resource limits (such as `MAX_PARALLEL_DEGREE` or `MAX_FILE_OPERATIONS`) are bound from an immutable policy snapshot captured when the script starts, preventing in-script overrides.

### Performance

- **Columnar Islands** — Projection, selection, and arithmetic aggregations operate directly on contiguous memory slices, drastically reducing CPU cache misses.
- **Default Columnar Temp Storage** — The system configures columnar temp storage by default across all pipeline execution steps.

---

### Security

- **Filesystem Policy Boundary** — Restricted local paths in file operations are checked recursively; delete/copy tasks perform a second authorization check immediately before calling the OS file system API.
