## ETL-SQL v0.12.0

This release introduces **Practical High Availability (HA)**, **Multi-Node Portal and Orchestrator Clustering**, **PostgreSQL State Persistence**, and **Monotonic Fencing Locks**.

---

### Highlights

#### 1. Cluster-Aware State Persistence (PostgreSQL Provider)
To support multi-node scaling, both the Report Portal (EF Core) and Orchestrator state stores are selectable between single-node SQLite and enterprise-grade PostgreSQL.
* **Dialect-Neutral Relational Store:** Shipped `RelationalJobHistoryStore` utilizing standard SQL dialect queries. Employs case-insensitive collations (Postgres `nocase` ICU collation) to guarantee identical variable/history search results across database Backends.
* **SQLite to PostgreSQL Migration Engine:** Adds the `etl-sql admin migrate-database --from sqlite --to postgres` utility. This copies existing execution histories and memberships, validates schema column mappings, resyncs identity sequences, and asserts row-count parity (failing closed if any migration mismatch occurs).

#### 2. Practical High Availability (HA) Coordination
Implements a database-backed coordinator layer to fence out stale nodes and synchronize active jobs.
* **Cluster Registry Heartbeats:** Portal and Orchestrator nodes record periodic liveness heartbeats to a shared database cluster registry on a synchronized DB clock. Nodes that miss heartbeat cycles are automatically marked offline.
* **Leader Election and Singleton Leases:** Synchronizes metadata migration runs, daily mail deliveries, and active job schedulers to ensure exactly one leader node runs background tasks.
* **Monotonic Fencing Tokens:** Writes to shared database and file scopes are gated by monotonically increasing lock version tokens. Node lease losses immediately cancel in-flight jobs on the affected node to prevent database corruption.
* **Quarantine and Recovery:** Automatically sweeps active jobs from a crashed node into a quarantine state at startup, allowing healthy nodes to claim and restart interrupted tasks.

#### 3. Shared Artifact Storage (`IArtifactStorage`)
* **UNC/SMB Storage Providers:** Report templates, uploaded files, and snapshot archives reside on a shared network path accessible by all cluster nodes.
* **Storage-Boundary Checks:** `SecurityService` policies actively validate that UNC file access stays within allowed boundaries.

---

### Performance

- **Postgres Concurrency Optimization** — Replaces local database locking loops with database-native connection pooling and transaction isolations, ensuring Portal performance under heavy concurrent API requests.

---

### Security

- **Fencing Security** — monontonically incremented locks prevent split-brain conditions where two nodes attempt to write to the same file or database location simultaneously.
